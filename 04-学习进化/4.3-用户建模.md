## 本篇新词

- 用户模型（user model） 指系统关于某个人的一组特征：偏好、熟练程度、习惯、当前目标。
- 置信度（confidence） 指一条推断被支持的程度。它是用户模型与记忆最本质的差别。
- 显式声明与隐式推断 指特征的两个来源：用户直接说的，与从行为里得出的。
- 过拟合（overfitting） 指把一次性的表达当成稳定偏好。
- 漂移（drift） 指用户变了而模型没有跟上。
- 注入点（injection point） 指用户模型在请求里被使用的位置，本课程放在执行层。
- 可见性与边界 指用户能看、能改、能删、能关闭自己的模型。
- 冷启动（cold start） 指模型为空时的行为，其默认必须是安全的中性行为。

## 一、【设计原因】

### 1.1 缺陷一：系统越用越自作主张

系统开始做一些用户没有要求的事，理由是"根据你以往的习惯"。而那个习惯是从一两次偶发行为推出来的：用户在赶时间时截断了一次长回答，系统记下了"偏好简短"，此后每次都只给要点。

成因是单向累积：支持证据会累积而反驳不会。

### 1.2 缺陷二：用户变了，系统还停在过去

用户换了技术栈、改变了工作方式，而系统仍按旧模型行事。它的表现与过拟合相反：系统不再自作主张，而是固守一个已经过时的判断，用户每次都要纠正。

修法有两条：时间衰减（置信度随时间下降）与不一致检测（负向观察在短期内多次出现时立即降低置信度）。

### 1.3 缺陷三：冷启动时的错误猜测

模型为空时，系统面临一个选择：用通用默认，还是从第一次交互里立刻推断。后者的风险是第一印象固化——而它恰好发生在系统对用户了解最少的时候。

处置是：没有证据时的默认行为必须是安全的（通用、中性、不猜测）。

### 1.4 缺陷四：用户看不到也删不掉

系统按某些推断行事，而用户既不知道系统记住了什么，也没有入口修改或删除它。

这条缺失的严重性高于前三条：前三条影响体验，这一条影响信任。而信任一旦损失，后续的个性化收益都会被折扣掉——用户会主动隐藏行为，从而让模型更不准。

### 1.5 由此确定的设计目标

1. 每条特征带置信度，注入有门槛。
2. 更新有两条路径，且反驳必须能降低置信度。
3. 反驳到零时删除特征，而不是留一个空壳。
4. 注入发生在执行层，不改变方法的选择。
5. 提供看、改、删、关闭四个入口，删除是物理删除。

**本节要点**

- 单向累积是过拟合的成因。
- 漂移与过拟合方向相反。
- 冷启动的错误会通过反馈回路自我强化。
- 边界缺失影响的是信任，而不只是体验。
- 五条目标：带置信度、双向更新、归零即删、执行层注入、四入口。

## 二、【直觉】

### 2.1 印象与修正

对人的印象有两种来源。

- 他说过的话：明确、权重高、一次就够。
- 你观察到的行为：模糊、权重低、需要重复。

而印象最危险的地方在于它会自我印证：你按印象对待他，他的反应就会带上这个前提，于是你收集到的证据都被这层前提污染过。

::: keypoint 反直觉点
**反驳必须比支持更重。** 用户沉默时系统收不到任何信号，而要求调整时才产生一条反驳。因此如果两者等权，沉默就会被当成支持，置信度随使用时长单调上升——而用户满意度并不上升。这条与"失败的信号比成功更强"是同一原则。
:::

### 2.2 天平

把每一条特征想成一台天平。

- 支持的观察往一边加砝码，一次隐式行为加一份。
- 明确的声明加三份（他直接说了）。
- 反对的观察往另一边加两份（一次反对抵两次支持）。
- 天平归零时把这件事忘掉。

最后一条是这套设计的要点：**留着一条权重为零的特征，等于让被推翻的判断在下次被观察到时从一个非零起点复活。**

### 2.3 一个数字直觉

设注入门槛是 3，权重表是"显式 3、隐式 1、反驳 −2"。

| 证据 | 累计 | 达门槛 |
|---|---|---|
| 一次隐式行为 | 1 | 否 |
| 两次隐式行为 | 2 | 否 |
| 三次隐式行为 | 3 | 是 |
| 一次显式声明 | 3 | 是 |
| 三次隐式 + 一次反驳 | $3 - 2 = 1$ | 否 |

**单次观察不构成偏好**，而一次明确声明就够——这张表把过拟合挡在门外的方式就是这条门槛。

**本节要点**

- 行为证据会带上既有印象的污染。
- 反驳比支持更重，且归零即忘。
- 单次行为不构成偏好。

## 三、【严格】

### 3.1 定义

::: theorem 定义 4.3.1（用户特征）
一条特征是

$$
f = (\mathit{key},\ \mathit{value},\ \mathit{weight},\ \mathit{evidence},\ \mathit{lastUpdatedAt},\ \mathit{expiresAt}),
$$

其中 $\mathit{weight}$ 是置信度，$\mathit{evidence}$ 是最近的若干条观察，$\mathit{expiresAt}$ 按特征类别的保留期设定。**保留最近的证据而不只保留计数**，用于向用户解释与调整规则。
:::

::: theorem 定义 4.3.2（权重表与置信度）
观察的种类与权重是

$$
W(\text{显式}) = 3,\quad W(\text{隐式}) = 1,\quad W(\text{反驳}) = -2 .
$$

置信度是加权计数。**反驳的绝对值大于隐式支持**：一次反对抵消两次支持。
:::

::: theorem 定义 4.3.3（更新的两条路径）
同向观察累加：

$$
\mathit{weight}' = \mathit{weight} + W(\text{种类}).
$$

反向观察先削弱：

$$
\mathit{weight}' = \mathit{weight} - 2,
$$

且 $\mathit{weight}' \le 0$ 时**删除该特征**（而不是留下权重为零的条目）。

显式声明的语义是**替换**（用户改主意时后到的声明直接覆盖），而隐式推断是累加。
:::

::: theorem 定义 4.3.4（注入门槛与注入点）
只有满足 $\mathit{weight} \ge \tau$ 的特征参与注入。注入发生在**执行层**，即它调整输出规格、解释深度与交互节奏，而不改变技能与工具的选择。
:::

::: theorem 定义 4.3.5（漂移）
设特征 $f$ 在时间窗 $\Delta$ 内的反驳次数为 $m$。称 $f$ **漂移**，当且仅当 $m \ge m_0$（本课程取 $m_0 = 2$，$\Delta = 7$ 天）。
:::

::: theorem 定义 4.3.6（边界四入口）
用户模型对用户的接口是四个入口：**看**（列出特征与理由）、**改**（修正取值）、**删**（物理删除内容）、**关闭**（回到默认行为，特征保留但不使用）。
:::

### 3.2 命题

::: theorem 命题 4.3.1（无反驳路径时置信度单调不减）
若更新只处理同向观察，则对任意观察序列，$\mathit{weight}$ 非严格递减。

**证明.** 同向观察的更新是 $\mathit{weight} \to \mathit{weight} + W$，其中 $W > 0$（显式为 3、隐式为 1）。序列的每一项都不减少该值，故其单调不减。

↓ **为什么能这么写？** 每一项的增量都是正的，而正增量之和为正。

$\blacksquare$

**数值**：三次隐式支持达 3（恰好到门槛）。此时一次反驳把它降到 $3 - 2 = 1$，落入门槛之下。再反驳一次即归零并删除。

::: keypoint 归零即删的必要性
**保留权重为零的条目，会让它下次被观察到时从非零起点复活。** 那条起点来自一次已经被推翻的判断，等于让错误复活。
:::

::: theorem 命题 4.3.2（支持的采集频率天然高于反驳）
在正常使用中，一次任务产生 0 或 1 条同向证据，而一次反驳需要用户主动表达。

**证明.** 同向证据来自任务本身的完成（系统按当前推断行动，任务继续）。反驳需要用户对系统行为提出异议，而这发生在系统行为不合预期时。前者是常态，后者是例外，故前者的频率更高。

↓ **为什么能这么写？** 两种事件的触发条件不同：一个由任务驱动，一个由不满驱动。

$\blacksquare$

**数值**：设每 10 次任务出现一次反驳，则等权（$+1/-1$）下净增 $+9$，而本课程的不等权（$+1/-2$）下净增 $+8$，但单次反驳的即时效果是让特征掉出注入门槛（$3-2=1$）。

::: theorem 命题 4.3.3（门槛把单次观察挡在门外）
设门槛 $\tau = 3$。一次隐式观察后 $\mathit{weight} = 1 < \tau$，故不参与注入。

**证明.** 由定义 4.3.2，隐式观察的权重为 1。由定义 4.3.4，注入要求 $\mathit{weight} \ge 3$。故不注入。

↓ **为什么能这么写？** 门槛是权重上的一个不等式。

$\blacksquare$

::: theorem 命题 4.3.4（注入的层决定它的影响面）
若注入只修改输出规格，则它不改变"采用哪套方法"，因此它不改变任务走哪条路径。

**证明.** 输出规格是请求中的一个字段，不影响技能选择或工具调用。方法选择由任务与技能描述决定（4.2 的触发）。两者输入不同，故互不影响。

↓ **为什么能这么写？** 影响面由被修改的对象决定。

$\blacksquare$

::: keypoint 偏好不该改变方法
**一个偏好简洁的用户与一个偏好详细的用户，需要的是同一套重构方法，只是产出的说明详略不同。** 若偏好影响到技能选择，就会出现"因为用户偏好简洁而不加载某个技能"这类荒谬结果。
:::

::: theorem 命题 4.3.5（抑制不足以删除个人信息）
若删除被实现成抑制，则内容仍在存储中，因此从用户视角看未被删除。

**证明.** 抑制只修改状态标记，条目内容不参与任何删除操作。任何能读存储的主体仍能读到该内容。用户对"是否删除"的判断依据是内容是否仍存在，故抑制不满足该判据。

↓ **为什么能这么写？** "删除"的语义是内容不再存在，而抑制不改变这一点。

$\blacksquare$

**数值**：删除动作本身被记录（时间与特征名），因此"这条特征曾经存在"仍有痕迹，而它的内容已不存在。**这个折中把不可复盘的范围缩到了内容层。**
:::

::: theorem 4.3.6（冷启动默认的影响不可逆）
若冷启动采用"多数用户的偏好"，则少数用户的首次体验偏离其真实偏好，而系统此时没有证据纠正。由于反馈回路，错误默认会收集到支持它的证据。

**证明.** 初始无证据（定义 4.3.1 的 evidence 为空）。采用任一回退默认 $d$ 后，系统按 $d$ 行动。用户面对一个已经按 $d$ 行事的系统，其行为带上这个前提，因此新证据在 $d$ 的方向上更具支持性。故错误的 $d$ 会自我强化。

↓ **为什么能这么写？** 证据由交互产生，而交互被默认值塑造。

$\blacksquare$

**数值**：因此本课程的冷启动默认是与用户模型无关的通用中性行为，而不是"多数用户的选择"。

### 3.3 本节要点

**本节要点**

- 特征由取值、置信度、证据与保留期构成（定义 4.3.1）。
- 权重表里反驳的绝对值大于隐式支持（定义 4.3.2）。
- 同向累加、反向削弱、归零即删（定义 4.3.3）。
- 注入有门槛，且发生在执行层（定义 4.3.4）。
- 漂移由负向观察密度判定（定义 4.3.5）。
- 边界有四个入口，删除是物理删除（定义 4.3.6）。
- 无反驳路径时置信度单调不减（命题 4.3.1）。
- 支持的采集频率天然更高（命题 4.3.2）。
- 门槛把单次观察挡在门外（命题 4.3.3）。
- 注入的层决定影响面（命题 4.3.4）。
- 抑制不足以删除个人信息（命题 4.3.5）。
- 冷启动默认的影响不可逆（命题 4.3.6）。

## 四、【回到直觉】

- **定义 4.3.1 说的**：每条推断要记下它被什么支持过，以及它什么时候该过期。
- **定义 4.3.2 说的**：他说的算三份，看到的算一份，而反对一次抵两次支持。
- **定义 4.3.3 说的**：同向就加，反对就减，减到零就当没这回事。
- **定义 4.3.4 说的**：够格的推断才生效，而且只调整"怎么说"，不调整"用哪套方法"。
- **定义 4.3.5 说的**：一周内被反对两次，就该怀疑这条推断过时了。
- **定义 4.3.6 说的**：能看、能改、能删、能关。
- **命题 4.3.1 说的**：只加不减，置信度就会一直涨。
- **命题 4.3.2 说的**：他沉默不代表同意，只是没说话。
- **命题 4.3.3 说的**：看到一次不构成偏好。
- **命题 4.3.4 说的**：偏好决定说得详不详细，不决定用哪种做法。
- **命题 4.3.5 说的**：只做标记不算删除，内容还在就等于没删。
- **命题 4.3.6 说的**：第一次猜错，之后会越来越像猜对了。

**本节要点**

- 证据要留痕。
- 反对更重。
- 归零即忘。
- 只改执行不改选择。
- 漂移要主动发现。
- 删除要真删。

## 五、【工具箱】

### 5.1 四类特征与保留期

| 类别 | 例子 | 来源 | 保留期 |
|---|---|---|---|
| 表达偏好 | 详略、语言、格式 | 显式或隐式 | 长期 |
| 熟练程度 | 是否需要解释背景 | 隐式为主 | 季度级 |
| 工作习惯 | 提交粒度、测试习惯 | 隐式 | 季度级 |
| 当前目标 | 正在做的项目 | 显式为主 | 周级 |

**保留期与敏感度反向**：当前目标的错误代价最大（拿一个过期的目标去理解当下，会给出完全无关的建议），因此它过期最快。

### 5.2 更新规则

1. 同向观察累加权重。
2. 反向观察削弱，削弱到零即删除。
3. 没有特征时，反驳**不创建**特征（一次"不要这样"的意思是否定，不是建立一个反向偏好）。
4. 显式声明替换旧值（用户改主意）。

### 5.3 注入的三个位置

| 位置 | 内容 | 对哪类特征敏感 |
|---|---|---|
| 输出规格 | 长度、格式、是否给例子 | 表达偏好 |
| 解释深度 | 是否展开背景与推导 | 熟练程度 |
| 交互节奏 | 是否先确认、是否给多方案 | 工作习惯 |

**三者都不改变"选哪个技能"或"调用哪个工具"。**

### 5.4 边界检查

1. **看**：列出特征与理由，不暴露内部字段（"权重 2.0"对用户没有意义，"因为你三次要求简短"才有）。
2. **改**：允许修正取值。
3. **删**：物理删除内容，只记录删除动作。
4. **关闭**：回到默认行为，特征保留但不使用。

### 5.5 漂移的发现

统计同一特征在时间窗内的反驳次数。它先报告，不自动处置——自动降低置信度可能误伤（用户可能只是那天心情不好）。

**本节要点**

- 保留期与敏感度反向。
- 反驳归零即删，且不凭空建反向特征。
- 注入三位置不改方法。
- 四个入口缺一不可。
- 漂移先报告再处置。

### 7.2 特征段与更新段

特征段定形状，更新段处理三条路径。

```js
// 定义 4.3.2：权重表——反驳的绝对值大于隐式支持
export const WEIGHT = { explicit: 3, implicit: 1, contradict: -2 }
export const THRESHOLD = 3
export const CONFIRM_THRESHOLD = 5

/**
 * 定义 4.3.3：应用一条观察。
 * @param model 特征表（Map）
 * @param obs 形如 `{ key, value, kind, at }` 的观察
 * @returns 新的特征表
 */
export function applyObservation(model, obs) {
  const next = new Map(model)
  const prev = next.get(obs.key)
  if (prev && prev.value === obs.value) {
    next.set(obs.key, { ...prev, weight: prev.weight + WEIGHT[obs.kind], evidence: [...prev.evidence, obs] })
    return next
  }
  if (prev) {
    const weakened = prev.weight + WEIGHT.contradict
    if (weakened <= 0) {
      next.delete(obs.key)                      // 归零即删
      return next
    }
    next.set(obs.key, { ...prev, weight: weakened, evidence: [...prev.evidence, obs] })
    return next
  }
  if (WEIGHT[obs.kind] < 0) return next         // 无特征时反驳不创建特征
  next.set(obs.key, {
    key: obs.key,
    value: obs.value,
    weight: WEIGHT[obs.kind],
    evidence: [obs],
    lastUpdatedAt: obs.at,
    expiresAt: obs.at + (obs.ttl ?? 90),
  })
  return next
}
```

### 7.3 衰减段

衰减段做两件事：清掉过期的，报告漂移的。

```js
// 定义 4.3.5：过期清除与负向密度报告
export function decayAndDetect(model, now, window = 7) {
  const kept = new Map()
  for (const [key, f] of model) if (f.expiresAt > now) kept.set(key, f)
  const drifting = []
  for (const [key, f] of model) {
    const recent = f.evidence.filter((e) => e.kind === 'contradict' && now - e.at <= window).length
    if (recent >= 2) drifting.push(key)
  }
  return { model: kept, drifting }
}
```

### 7.4 注入段与边界段

注入段只调整输出规格，边界段提供四个入口。

```js
// 定义 4.3.4：门槛以上的特征才生效，中等置信度附带说明
export function inject(model, spec) {
  let out = { ...spec }
  const notices = []
  for (const [, f] of model) {
    if (f.weight < THRESHOLD) continue
    out = applyFeature(out, f)
    if (f.weight < CONFIRM_THRESHOLD) notices.push(`按你以往的偏好：${describe(f)}`)
  }
  return { spec: out, notices }
}

/**
 * 定义 4.3.4：把一条特征应用到输出规格上（只改规格，不改方法）。
 * @param spec 输出规格
 * @param f 特征
 * @returns 调整后的规格
 */
export function applyFeature(spec, f) {
  const out = { ...spec }
  if (f.key === 'answer-length') out.verbosity = f.value
  if (f.key === 'explain-level') out.explain = f.value
  if (f.key === 'interaction-pace') out.confirmFirst = f.value === 'careful'
  return out
}

/**
 * 定义 4.3.6：面向用户的清单——含理由，不含内部字段。
 * @param model 特征表
 * @returns 用户可见的条目数组
 */
export function listFeatures(model) {
  return [...model.values()].map((f) => ({
    label: describe(f),
    reason: summarizeEvidence(f.evidence),
    confidence: f.weight >= CONFIRM_THRESHOLD ? '已确认' : '推测',
  }))
}
```

### 9.2 失败模式

**（1）检查放在装载期（L9 位置放错）。** 漂移检测只在复盘时跑一次，而用户的变化是连续的。表现是"上次复盘之后用户已经变了，而系统还在用旧模型"。

**（2）前提会变（L9）。** 命题 4.3.2 的不等权以"反驳是主动表达"为前提。若系统频繁询问"这样对吗"，用户的反驳会变成被动应答，频率大幅上升，权重关系随之失衡。

**（3）只实现同向更新。** 置信度随使用时长单调上升，系统越来越自作主张。

**（4）反驳留下权重为零的空壳。** 被推翻的判断在下一次观察时复活。

**（5）无特征时反驳创建反向特征。** 一句"不要这样"被理解成建立了一个反向偏好。

**（6）注入点在选择层。** 偏好污染的变成方法的选择。

**（7）门槛设得太低。** 单次行为即生效，等价于没有门槛。

**（8）删除实现成抑制。** 用户视角等于没有删除。

**（9）查看清单暴露内部字段。** 用户看不懂，等于没有入口。

**（10）冷启动用"多数用户偏好"。** 少数用户的错误印象被固化，且会被反馈回路强化。

**本节要点**

- 决策表覆盖 12 种情形。
- 失败模式十条，前两条是位置放错与前提会变。
- 最严重的是"删除实现成抑制"——它不影响功能，只破坏信任。

## 十二、系统影响回溯

**影响一：用户模型与技能在同一处上下文空间竞争，而它们的取舍标准不同。** 技能主体是按需的大块内容，用户模型是常驻的小块特征，因此后者适合常驻。

**影响二：隐式推断的反馈回路会让错误难以消除。** 处置是定期用显式声明校准，并把隐式证据的权重保持在低水平。

**影响三：用户模型的删除必须是真删除。** 代价是无法复盘，只能通过"删除动作本身被记录"部分弥补。

**一处需要修正的预判。** 旧稿把四类特征的保留期按"敏感度越低越可长期保留"总结，读完之后要把它说得更准：**保留期应当与"这条特征随什么变化"对齐，而不是与敏感度对齐。** 当前目标变化最快（它跟着项目走），表达偏好变化最慢（它跟着人走）。敏感度高只说明它需要更严的保护，不说明它该更快过期——两者的依据不同，因此不能用一个维度概括。

**通向下一步的桥。**

前三篇积累的是"关于世界的知识"：事实、做法、关于人。而它们都依赖一个前提：**系统能判断一次结果是好是坏**。一次失败如果没有被归因，它只会被记为"某次没成功"，而无法变成任何改进。

所以下一篇是 4.4 诊断。它要从失败中提取可归因的原因，而它的输入正是前三篇积累的内容——记忆里的约定、技能里的方法、用户模型里的偏好。
