## 本篇新词

- 诊断（diagnosis） 指从一次失败里得出一个**可行动的原因**。它与归因的差别在于后半段。
- 失败的定义 指"什么算失败"的判据。没有它时只有报错与异常会被当成失败。
- 可行动性（actionability） 指结论是否指向一个可修改的对象。
- 反事实（counterfactual） 指"如果改变某个条件，这次会不会成功"。它是归因的最强证据。
- 过早收敛（premature convergence） 指在第一个说得通的原因上停下。
- 归因的证据 分三类：时间相关、反事实、复现，强度递增。
- 已知条件（known conditions） 指失败发生时系统已知的状态。
- 无指责（blameless） 指结论不指向个人。它的理由是可行动性，不是宽容。

## 一、【设计原因】

### 1.1 缺陷一：任务失败了，而没有任何信号

系统的"失败"只包括报错与异常，而更常见的一类被漏掉：任务跑完了、没有报错、而结果不是用户要的。

后果在积累上：没有信号意味着没有可诊断的对象，因此这类失败从来不进入改进循环——而它们恰好是数量最多的。

### 1.2 缺陷二：归因停在"模型能力不足"

结论的形态是一份看起来很完整的分析（现象、影响、时间线），而结论落在"当前模型能力有限"或"用户表达不够清楚"上。

两个后果：下一次遇到同样情况仍然一样（因为没有东西被改），以及它会掩盖真正的原因——"模型能力"是一个无法反驳的结论，因此追问会在这里停止。

### 1.3 缺陷三：过早收敛，只修了一条链

诊断者沿着"为什么"追问下去，得到一条因果链，然后修了链条末端的那一处。而失败在别的情况下仍然出现——因为同一次失败还有另一条成因链。

修法是把候选并列：先收集多个说得通的原因，各自标注证据强度，再决定改哪一处。

### 1.4 缺陷四：修了，但不知道有没有效

偶发的失败在修改之后无法确认是否被解决——它不再出现，而这不构成证据（它本来就可能只是这次没出现）。

修法的核心是**先复现再修**：一个可复现的失败可以在修复前后各跑一次，而那次对比就是证据。

### 1.5 由此确定的设计目标

1. 失败按三类判定，判定顺序从最明确到最宽泛。
2. 候选至少两个，先收集再排序，不在收集时筛选。
3. 证据分三类并显式标注强度。
4. 结论必须含一个可改的对象，否则不成结论。
5. 修复验证要求"改前能复现、改后不能复现"。

**本节要点**

- 数量最多的失败是没有报错的那些。
- "模型能力不足"无法反驳，因此追问会停止。
- 深挖一条链也会过早收敛。
- 改后不再出现不构成证据。
- 五条目标：三类判定、多候选、证据分档、可行动、两观测点。

## 二、【直觉】

### 2.1 三个候选

一位有经验的修车师傅听到"车抖"时不会立刻动手，他会先列几种可能。

- 轮胎不平衡：开快了更明显。
- 火花塞老化：怠速时更明显。
- 传动轴松动：转弯时更明显。

**三者的区别靠"在什么条件下出现"来分辨。** 只列一条链的师傅会先换一个零件，再听声音有没有变。

::: keypoint 反直觉点
**诊断的质量由候选收集得够不够全决定，不由追问得够不够深决定。** "五问法"式深挖会得到一条链，而它只是众多可能中的一条——一条链看起来严密，而严密不等于全面。
:::

### 2.2 证据的强度

三类证据像三种证词。

| 证据 | 相当于 | 能证明 |
|---|---|---|
| 时间相关 | 他在场 | 与结果有关（还不够） |
| 反事实 | 他不在结果就不同 | 这个条件是必要的 |
| 复现 | 每次他在都出事 | 在这些条件下够了 |

第二种是最有价值也最费力的：它需要真的改一个条件再跑一次。

### 2.3 一个数字直觉

设一次"任务超时"的失败，三个候选的证据分别是：

- 单次调用的超时上限过小：反事实 + 复现，得分 $2 + 3 = 5$。
- 上下文过长导致首 token 慢：时间相关，得分 1。
- 重试放大拥塞：时间相关，得分 1。

**排序给出 5、1、1，而前者的动作是"调大超时"、后两者是"收紧压缩阈值"与"调低并发"。** 三个动作指向三处不同的修改，而只列一个候选的人只会做其中一处。

**本节要点**

- 列候选比深挖一条链更有价值。
- 反事实证明必要，复现证明充分（在当前条件下）。
- 多候选给出多个可改对象。

## 三、【严格】

### 3.1 定义

::: theorem 定义 4.4.1（失败的三类）
一次回合属于失败，当且仅当它满足三者之一：

$$
\text{失败} = \begin{cases}
\text{报错}, & \text{有异常或非零退出码},\\
\text{静默的错误结果}, & \text{检查不通过},\\
\text{目标未达成}, & \text{任务的成功判据不成立}.
\end{cases}
$$

**判定顺序是从最明确到最宽泛**：先报错、再检查、最后目标。顺序反了会把有明确错误的结果记成"目标未达"，从而丢掉最具体的诊断入口。
:::

::: theorem 定义 4.4.2（候选原因）
一个候选原因是一个四元组

$$
c = (\mathit{cause},\ \mathit{evidence},\ \mathit{actionable},\ \mathit{cost}),
$$

其中 $\mathit{actionable}$ 是它指向的可改对象（为空表示不可行动），$\mathit{cost}$ 是改动的成本。**收集阶段不筛选**，筛选只发生在排序阶段。
:::

::: theorem 定义 4.4.3（证据强度）
三类证据的强度是

$$
\mathrm{strength}(\text{时间相关}) = 1 < \mathrm{strength}(\text{反事实}) = 2 < \mathrm{strength}(\text{复现}) = 3 .
$$

一个候选的证据得分是它全部证据的强度之和。
:::

::: theorem 定义 4.4.4（可行动性）
一条结论**可行动**，当且仅当它包含一个可修改的对象：一段提示词、一个阈值、一条工具描述、一条技能的适用条件、一个配置项。

不属于可改对象的：模型的能力、用户的表达方式、外部服务的稳定性。
:::

::: theorem 定义 4.4.5（已知条件）
失败 $\phi$ 的**已知条件**是发生时系统已知的状态，至少四项：

$$
\mathrm{known}(\phi) = (\text{当时的配置},\ \text{是否冷启动},\ \text{加载的技能与记忆},\ \text{资源状况}).
$$

已知条件必须被记录，否则失败无法被重放，而重放是验证的前提。
:::

::: theorem 定义 4.4.6（诊断结论的六个字段）
一份诊断结论是

$$
D = (\text{现象},\ \text{已知条件},\ \text{候选},\ \text{结论},\ \text{动作},\ \text{观察项}),
$$

其中**动作**与**观察项**必须分开：前者是要改的，后者是不改但下次要看的。分开的理由是避免"为了显得有作为而改一个无关的东西"。
:::

### 3.2 命题

::: theorem 命题 4.4.1（可观测性决定诊断的上限）
若某状态未被记录，则它不能被用作归因证据。

**证明.** 归因的证据来自记录（日志、度量、检查结果）。未被记录的状态在事后不可读取，故无法成为某条候选的证据，也无法出现在已知条件里。

↓ **为什么能这么写？** 证据的存在以记录的存在为前提。

$\blacksquare$

::: keypoint 因此诊断没有引入新的采集机制
**它只消费已有的日志与度量。** 一件没有被观测的事，不论诊断方法多好都无法被归因——这也是"诊断的上限在第 3 卷就被决定"的具体含义。
:::

::: theorem 命题 4.4.2（单候选无法区分"相关"与"因果"）
若只收集一条候选，则它与其他条件的相对证据强度不可比较，因此"看起来相关"与"因果"不可区分。

**证明.** 区分依赖比较：两条候选在同一批证据上的得分差异说明其中一条的支持更强。只有一条候选时不存在比较对象，故无法排除"另有更强的候选未被列出"。

↓ **为什么能这么写？** 判别需要一个参照物，而单元素集合不含参照物。

$\blacksquare$

**数值**：因此要求候选数 $\ge 2$（除非某一条同时具备反事实与复现）。**写下第二条候选这个动作本身会让人去检查第一条的证据**，而检查常常发现它比想象中弱。
:::

::: theorem 4.4.3（反事实证明必要性，不证明唯一性）
若"去掉条件 $x$ 则本次成功"，则 $x$ 是本次失败的必要条件之一，但不排除存在其他必要条件。

**证明.** 反事实是一次单变量的对照：只改变 $x$ 而其他条件不变。结论只覆盖 $x$ 在该组条件下的作用。若另有一条件 $y$，同样去掉它也会成功，则两者都是必要条件。反事实没有排除这种情形。

↓ **为什么能这么写？** 单变量对照只能证伪含有该变量的组合，不能穷尽其他组合。

$\blacksquare$

**数值**：一次工具调用失败中，超时太短与参数错误可以同时是必要条件。因此结论应当是"这一组条件共同导致失败，其中改动成本最低的是哪一个"。
:::

::: theorem 4.4.4（复现的充分性只在这些条件下成立）
若在条件组合 $C$ 下失败可复现，则该复现说明 $C$ 在这些条件下充分，而不说明 $C$ 在其他条件下也充分。

**证明.** 复现是对同一组条件的重复观测。不同条件下是否失败不受该观测约束（条件组合变化后，失败机制可能不同）。故"所有同类失败都是这个原因"是超出证据的推广。

↓ **为什么能这么写？** 观测的证据力被其条件的范围限制。

$\blacksquare$

::: theorem 4.4.5（修复验证需要两个观测点）
"改后失败不再出现"不构成修复证据。只有"改前复现、改后不出现"才构成。

**证明.** 设失败发生率为 $p$。只观测改后一次未失败的概率是 $1 - p$，它是正数（当 $p < 1$ 时），故不出现的观测与"未修复"相容。加上改前的复现观测后，"改前失败"排除了"该条件下本来就不失败"这一解释，从而使对比具有对照意义。

↓ **为什么能这么写？** 单点观测与两种假设都相容，两点观测才把它们分开。

$\blacksquare$

**数值**：因此验证的第一步是"用同一组已知条件重放，确认它确实会失败"。这一行最容易被跳过，而它决定了这次验证是否有意义。
:::

::: theorem 4.4.6（不可行动的结论会掩盖原因）
若结论落在不可行动的对象上，则该结论不可反驳，因此追问会终止。

**证明.** 不可行动的对象包括模型能力与用户表达，它们在这个系统内没有对应的可修改项，故无法通过"改一处再观测"来检验。缺乏检验手段意味着任何针对它的反驳都不产生可观测差异，因而追问没有可依据的下一步。

↓ **为什么能这么写？** 可反驳性要求存在一个能改变结果的干预。

$\blacksquare$

**数值**：不可行动的结论可以按规律转换成可行动的：模型能力不足 → 拆小任务或加一步校验。用户表达不清 → 信息不足时主动提问。外部服务不稳 → 加超时与降级。
:::

### 3.3 本节要点

**本节要点**

- 失败有三类，判定从最明确到最宽泛（定义 4.4.1）。
- 候选是原因、证据、可改对象与成本的四元组（定义 4.4.2）。
- 证据强度递增：时间相关、反事实、复现（定义 4.4.3）。
- 可行动性要求结论含一个可改对象（定义 4.4.4）。
- 已知条件至少要记四项（定义 4.4.5）。
- 结论分六个字段，动作与观察项分开（定义 4.4.6）。
- 可观测性决定诊断上限（命题 4.4.1）。
- 单候选无法区分相关与因果（命题 4.4.2）。
- 反事实证明必要不证明唯一（命题 4.4.3）。
- 复现的充分性受条件范围限制（命题 4.4.4）。
- 修复验证需要两个观测点（命题 4.4.5）。
- 不可行动的结论会掩盖原因（命题 4.4.6）。

## 四、【回到直觉】

- **定义 4.4.1 说的**：失败不只是报错，还包括"跑完了但不对"与"没达到目标"。
- **定义 4.4.2 说的**：列候选时先写下动作，写不出动作的候选会自己暴露。
- **定义 4.4.3 说的**：在场、不在场就不同、每次在场都出事，三种证词的分量递增。
- **定义 4.4.4 说的**：结论里要有一个能被改的东西。
- **定义 4.4.5 说的**：记下当时的环境，否则这次失败无法重演。
- **定义 4.4.6 说的**：要改的和要看的分开列。
- **命题 4.4.1 说的**：没记下来的东西，事后归因不到它头上。
- **命题 4.4.2 说的**：只有一个候选时，"碰巧有关"和"真的有关"分不出来。
- **命题 4.4.3 说的**：去掉它就好了，只说明它是必要条件之一。
- **命题 4.4.4 说的**：这一次能复现，不代表所有同类都出在这里。
- **命题 4.4.5 说的**：改后不再出现不算证据，改前能重现才算。
- **命题 4.4.6 说的**：落在"模型不行"上的结论没法反驳，追问就停了。

**本节要点**

- 三类失败。
- 候选要带动作。
- 证据分档。
- 结论要有可改对象。
- 记已知条件。
- 两点验证。

## 五、【工具箱】

### 5.1 失败判定的顺序

1. 有异常或非零退出码吗？有 → 报错。
2. 检查通过吗？不通过 → 静默的错误结果。
3. 任务的成功判据成立吗？不成立 → 目标未达成。
4. 三者都不成立才算成功。

**顺序不能换**：先判目标会把有明确错误的结果记成"目标未达"。

### 5.2 候选的两个收集方向

| 方向 | 做法 | 适合 |
|---|---|---|
| 自上而下 | 按系统分层逐层排除（模型层、工具层、循环层） | 结构性失败 |
| 自下而上 | 把多次失败的共同特征聚类 | 模式性失败 |

**两个方向都要做**，因为它们给出不同的候选：前者落在"机制没工作"，后者落在"某些条件的组合"。

### 5.3 反事实的三种构造

1. 改一个条件再跑一次。
2. 从会话日志重放，只改一个变量（成本低于重跑）。
3. 找位置相近的工具做对称检查（证据较弱，是无法重跑时的唯一选择）。

### 5.4 不可行动结论的转换

| 不可行动的结论 | 转成可行动的 |
|---|---|
| 模型能力不足 | 拆小任务、加一步校验、提供示例 |
| 用户表达不清 | 信息不足时主动提问 |
| 外部服务不稳定 | 加超时与降级 |

**共同形态是把"对方的问题"翻译成"我能改的东西"**，而这一步通常就是好诊断与坏诊断的差别。

### 5.5 验证流程

1. 用同一组已知条件重放，**确认改前确实会失败**。
2. 改动一处。
3. 用同一组条件重跑，确认不再失败。
4. 不能复现的失败进待观察清单，不立刻改。

**第 1 步最容易被跳过**，而它决定了这次验证是否有意义。

**本节要点**

- 判定顺序从最明确到最宽泛。
- 两个方向都收集候选。
- 反事实要主动构造。
- 不可行动的结论可以按规律转换。
- 验证的第一步是改前复现。

### 7.2 失败判定段

判定段按顺序检查三类失败。

```js
// 定义 4.4.1：三类失败，判定顺序从最明确到最宽泛
export function classifyFailure(turn, checks = []) {
  if (turn.error) return { kind: 'error', detail: turn.error }
  const failed = checks.filter((c) => !c.passed(turn))
  if (failed.length) return { kind: 'silent', detail: failed.map((c) => c.name) }
  if (turn.goal && !turn.goal.met(turn)) return { kind: 'goal-miss', detail: turn.goal.summary }
  return null
}
```

### 7.3 证据段与候选项段

证据段给出能自动得到的证据，候选项段合并两个方向的候选后统一排序。

```js
// 定义 4.4.3：证据强度与候选得分
export const STRENGTH = { correlation: 1, counterfactual: 2, reproducible: 3 }
export const COST_ORDER = { low: 0, medium: 1, high: 2 }

/**
 * 定义 4.4.3：一个候选的证据得分。
 * @param c 候选
 * @returns 得分
 */
export function score(c) {
  return c.evidence.reduce((n, e) => n + STRENGTH[e], 0)
}
```

排序规则先去掉不可行动的候选，再按证据与成本排。

```js
// 定义 4.4.2 / 命题 4.4.2：先过滤不可行动的，再按证据与成本排序
export function rankCandidates(candidates) {
  return [...candidates]
    .filter((c) => c.actionable !== null)
    .sort((a, b) => score(b) - score(a) || COST_ORDER[a.cost] - COST_ORDER[b.cost])
}
```

结论把候选取值、动作与观察项分开写成六个字段。

```js
// 定义 4.4.5 / 4.4.6：结论的六个字段
export function conclude(candidates, failure, known, taskId) {
  const ranked = rankCandidates(candidates)
  if (ranked.length === 0) throw new Error('没有可行动的候选：需要扩大观测范围或改可配置性')
  const chosen = ranked[0]
  return {
    phenomenon: `${failure.kind}：${JSON.stringify(failure.detail)}`,
    knownConditions: known,
    candidates: ranked,
    conclusion: { cause: chosen.cause, why: `证据得分 ${score(chosen)}，改动成本 ${chosen.cost}` },
    action: { target: chosen.actionable, verify: `改后重跑：${taskId}` },
    watchList: ranked.slice(1).map((c) => c.cause),
  }
}
```

### 7.4 验证段

验证段要求两个观测点。

```js
// 命题 4.4.5：改前复现、改后不出现，缺一不可
export async function verifyFix(diagnosis, replay, rerun) {
  const before = await replay(diagnosis.knownConditions)
  if (!before.failed) return { ok: false, reason: '改前无法复现，本次验证无效' }
  const after = await rerun(diagnosis.knownConditions)
  return { ok: !after.failed, reason: after.failed ? '改后仍失败' : '改前复现、改后通过' }
}
```

### 9.2 失败模式

**（1）检查放在装载期（L9 位置放错）。** 诊断只在复盘时做一次，而失败是逐次发生的。表现是"下次复盘前，同类失败已经又发生了若干次"。

**（2）前提会变（L9）。** 命题 4.4.4 的复现以"已知条件可重放"为前提。若配置在期间变化，重放的条件与当时不同，复现也就不成立。

**（3）只统计报错类失败。** 数量最多的失败从未进入改进循环。

**（4）归因落在不可行动的对象上。** 下次仍然一样，且追问终止。

**（5）只收集一个候选就动手。** 修了一条链，另一条仍然存在。

**（6）在收集阶段就筛选候选。** 同一处偏见被应用两次，过早收敛由此产生。

**（7）结论用散文写。** 无法机械检查可行动性，也无法按字段聚类。

**（8）不记已知条件。** 失败无法重放，验证环节整体失效。

**（9）验证跳过改前复现。** 一次"本来就不会失败"的运行被当成验证通过。

**（10）偶发失败立刻改一处。** 改动积累，且掩盖真正的模式。

**本节要点**

- 决策表覆盖 12 种情形。
- 失败模式十条，前两条是位置放错与前提会变。
- 最隐蔽的是"验证跳过改前复现"——它给出一个错误的"已修复"印象。

## 十、仍未解决

- **诊断依赖已有观测。** 未被记录的状态无法归因，而本篇不引入新的采集机制。
- **跨会话的长期模式。** 同类失败反复出现需要复盘周期来聚合。
- **跨用户的聚合。** 它涉及数据边界，不在本课程范围内。
- **候选的完整性无法验证。** 无法证明"候选已收集全"。
- **反事实的成本。** 重跑一次可能很贵，重放受日志完整性限制。
- **修复的长期有效性。** 一次验证只说明当时有效。

**本节要点**

- 观测是诊断的上限。
- 模式与跨用户聚合都在本篇之外。
- 候选完整性与长期有效性都不可证。

## 十二、系统影响回溯

**影响一：诊断的准确性受限于可观测性。** 没被观测的东西不能被诊断，因此诊断的上限在第 3 卷就被决定了。

**影响二：诊断会消耗信任，而结论必须比现象更有价值。** 判据是"用户读完结论之后知道自己该做什么"。

**影响三："可行动"这个要求会反向约束系统设计。** 当多数失败的结论都落在同一个不可行动的对象上时，说明系统结构上缺少可调的地方。

**一处需要修正的预判。** 旧稿把本卷的诊断限定为"单次失败的处理"，读完之后要补一句它的规模含义：诊断处理的失败次数越多，它的输出就越应当结构化——因为复盘的聚类依赖字段，而自由文本只能靠人工阅读。这意味着**诊断的格式是复盘能否自动化的前提**，而不是一个可选的整洁要求。

**通向下一步的桥。**

诊断给出的是一组候选与一个被选中的动作，而它**不改变任何东西**。把它变成对系统的一次真实修改，需要另一层：这个修改要经过提议、评估、门控与回滚。

所以下一篇是 4.5 演化。它与本篇的连接点是"动作"字段——诊断交出"要改什么"，演化决定"改不改、怎么改、改坏了怎么办"。
