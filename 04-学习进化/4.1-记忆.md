## 一、为什么记忆需要一条流水线

### 1.1 记住了一次性的东西

用户说"这次先跳过测试"。系统把它当成长期偏好记下来，**从此这个用户的所有任务都不跑测试**。

### 1.2 推测被当成事实

系统观察到"用户似乎偏好短回答"，把它记成"该用户喜欢短回答"。**下次注入时它和用户明确说过的话一样有分量。**

### 1.3 注入了无关内容

检索返回了十条与当前任务无关的记忆，**把上下文占掉一大块，还干扰了模型判断**。

这三件事分别对应：**写入过滤、来源标注、检索阈值。**

## 二、记忆的四个环节

| 环节 | 回答 | 出错的后果 |
|---|---|---|
| **写入过滤** | 什么值得长期记住 | 记下噪声，污染后续全部会话 |
| **存储** | 怎么存、来源是什么 | 无法判断可信度 |
| **检索** | 这次该取出哪几条 | 取出无关内容 |
| **注入** | 放多少进上下文 | 挤占预算、干扰判断 |

核心认识：**记忆系统的质量主要由"写入过滤"决定，而不是检索。** 因为写错的东西会被反复检索出来——污染是持久的。

## 三、怎么做

### 3.1 写入过滤：四条判据

算例给出四个候选中两条通过，拒绝理由有两条。可总结为四条判据：

```js
// 写入过滤：四条判据全过才写入长期记忆
export function shouldRemember(candidate) {
  if (candidate.sessionOnly) return { keep: false, reason: '只在本次会话有用' }
  if (candidate.speculative && !candidate.source) return { keep: false, reason: '推测类记忆缺来源标注' }
  if (!candidate.stable) return { keep: false, reason: '不是稳定事实' }
  if (!candidate.actionable) return { keep: false, reason: '无法据以行动' }
  return { keep: true }
}
```

| 判据 | 内容 | 反例 |
|---|---|---|
| **跨会话有用** | 下次还会用到 | "这次先跳过测试" |
| **稳定** | 不随时间快速变化 | "今天用了 v2 版本" |
| **可行动** | 能据此改变行为 | "用户提过三次 Python" |
| **可信** | 有来源（用户明说 / 可观察证据） | "用户似乎偏好短回答" |

算例实测：

| 项 | 值 |
|---|---|
| 候选数 | **4** |
| 通过的候选数 | **2** |
| 被拒绝的原因 | **只在本次会话有用、推测类记忆缺来源标注** |
| **临时信息也被拒绝** | **`false`**（说明它未被拒——缺陷） |
| 带来源的推测可以通过 | **`true`** |

"临时信息也被拒绝 = false"这一行值得注意：它意味着**当前实现没有拦住临时信息**。这是一个真实缺陷，也正是算例要暴露的：判据里必须有"跨会话有用"这一条。

"带来源的推测可以通过"：**推测不是不能记，而是必须标注来源**。这样注入时模型知道它的可信度。

为什么"跨会话有用"是第一条：**它过滤掉的最大一类噪声。** 会话内的临时约定（"这次别跑测试"、"用这个临时目录"）如果被长期记住，就会变成永久行为。

### 3.2 存储与来源标注

每条记忆至少要有这些字段：

| 字段 | 作用 |
|---|---|
| 内容 | 记住了什么 |
| **来源** | 用户明说 / 观察推断 / 系统规则 |
| **证据** | 支撑它的原始材料（哪次对话、哪条命令） |
| **时间** | 何时写入（用于衰减） |
| **置信度** | 有多确定 |
| 作用域 | 全局 / 项目 / 用户 |

"证据"字段是最有价值的：它让一条记忆**可被追溯与推翻**。没有证据的记忆无法在出错时清理。

"作用域"决定它在什么范围内生效：一个项目的编码约定不该影响另一个项目。**这与 2.5 的作用域是同一个概念。**

### 3.3 检索打分

检索的关键是**打分函数**。算例给出的得分可以考虑两部分：相关度与时间衰减。

```js
// 打分：相关度乘以时间衰减，衰减保证新记忆占优
export function score(memory, query, now, halfLifeMs) {
  const relevance = similarity(memory.content, query)
  const age = now - memory.createdAt
  const decay = Math.pow(0.5, age / halfLifeMs)
  return relevance * decay
}
```

算例实测的三条得分：

| 记忆 | 得分 |
|---|---|
| m1 | 1.069 |
| **m2** | **1.265**（排序第一） |
| m3 | 0.075 |

检索结果：

| 项 | 值 |
|---|---|
| 命中条数 | **2** |
| 排序第一名 | **m2** |
| 不相关查询的命中条数 | **0** |
| 阈值把低分条目挡在外面 | **1** |
| **时间衰减把较新的排到前面** | **`true`** |

读法：m3 的得分 0.075 远低于其他两条，**被阈值挡掉**。不相关查询命中 0 条，说明检索不会强行返回内容。

"不相关查询命中 0 条"是一个重要性质：**检索系统必须能够说"没有相关的"**。做不到这一点的系统会把最不相关的内容也返回，污染上下文（1.3 就是这种情况）。

### 3.4 阈值与注入预算

两条独立的限制：

| 限制 | 作用 | 依据 |
|---|---|---|
| **阈值** | 低于此分不返回 | 防止返回无关内容 |
| **预算** | 最多注入多少 token | 保护上下文（见 3.3） |

两者的分工：阈值管"够不够相关"，预算管"放不放得下"。

推荐参数起点：

| 参数 | 推荐 | 依据 |
|---|---|---|
| 命中上限 | 3–5 条 | 记忆是补充，不是主体 |
| 注入预算 | 上下文的 5%–15% | 不挤占任务内容 |
| 相似度阈值 | 由"不相关查询返回 0 条"标定 | 用负样本调 |
| 单条长度上限 | 几百 token | 太长会挤占预算 |
| 半衰期 | 数周到数月 | 取决于记忆类型 |

"用负样本调阈值"很实用：**准备一批"不相关的查询"，调阈值直到它们返回 0 条。** 这比凭感觉定阈值可靠。

### 3.5 时效与淘汰

记忆会过时。淘汰有三个手段：

| 手段 | 作用 |
|---|---|
| **时间衰减** | 降低旧记忆的得分（上面已讲） |
| **显式过期** | 写入时设定有效期 |
| **矛盾检测** | 新记忆与旧记忆冲突时，标记或替换旧的 |

"矛盾检测"最容易被漏：用户换了技术栈，新的偏好与旧偏好同时存在。**检索时两条都会被返回，模型不知道该信哪个。**

做法建议：

1. **写入时检查是否与已有记忆矛盾**，矛盾则标记旧记忆为失效。
2. 保留历史但仍然能找到（因为可能只是暂时的变化）。
3. 注入时若发现矛盾，优先注入较新的并注明。

这与 3.5 的持久化"不用累加型更新"是同一个思路：**状态更新应当是赋值型（覆盖）而不是累加型（叠加），否则矛盾会不断累积。**

## 四、特殊情况与处理技巧

| 情况 | 为什么 | 处理 |
|---|---|---|
| 记下了临时约定 | 缺少"跨会话有用"判据 | 写入前逐条过滤 |
| 推测被当成事实 | 没有来源标注 | 必须带来源与置信度 |
| 注入了无关内容 | 没有阈值 | 用负样本标定阈值 |
| 旧偏好与新偏好冲突 | 没有矛盾检测 | 写入时检测并失效旧的 |
| 记忆越攒越多 | 没有淘汰 | 衰减 + 过期 + 定期整理 |
| 一个项目记住了另一个项目的约定 | 没有作用域 | 记忆带作用域字段 |
| 检索总返回内容 | 阈值过低 | 用负样本校准 |
| 记忆与当前任务矛盾 | 检索时未校验 | 注入时比较时间戳并标注 |

最后一条的实用做法：**注入时把记忆的时间戳一起给模型**（例如"你在 3 个月前说过…"）。让模型自己判断时效，比系统替它判断更稳。

## 五、工业界的做法（可照做）

### 5.1 检索的三种技术

| 技术 | 原理 | 特点 |
|---|---|---|
| **词法检索**（BM25） | 词频统计 | 精确匹配强，不怕专有名词 |
| **向量检索** | 语义相似度 | 能匹配同义表达，需要嵌入模型 |
| **混合检索** | 两者加权融合 | **通常效果最好** |

混合检索值得优先考虑：**词法检索对专有名词与标识符（例如函数名、错误码）更强，向量检索对同义表达更强。** 两者互补。

参数起点：融合权重各半，再按你自己的查询分布调。

### 5.2 记忆服务的形态

| 形态 | 例子 | 特点 |
|---|---|---|
| **内置记忆工具** | 让模型自己调用"记住/回忆" | 简单，但依赖模型判断 |
| **自动抽取** | 后台从对话抽取事实 | 覆盖全，但噪声多 |
| **显式存储** | 用户/系统显式写入 | 质量高，覆盖低 |
| **混合** | 自动抽取 + 人工/规则过滤 | 实践中最多 |

"自动抽取必须配过滤"：抽取器会产出大量候选（算例里 4 个候选），**没有过滤就会积攒噪声**。

### 5.3 组织记忆与个人记忆的区别

| 类型 | 内容 | 稳定性 | 作用域 |
|---|---|---|---|
| **组织记忆** | 约定、架构决策、术语表 | 高 | 团队/项目 |
| **个人记忆** | 偏好、习惯、常用工具 | 中 | 用户 |
| **会话记忆** | 本次任务的约定 | 低 | 单次会话 |

三者的存储与检索策略应当不同：组织记忆几乎不过期，会话记忆根本不该进长期存储。

**算例里"只在本次会话有用"的拒绝理由正是指第三类。**

### 5.4 一份可落地的实施清单

1. **写入四判据**：跨会话、稳定、可行动、可信。
2. 来源与证据：每条记忆带来源、证据、时间、置信度。
3. 作用域：全局 / 项目 / 用户。
4. 检索：混合检索（词法 + 向量）。
5. 打分：相关度 × 时间衰减。
6. 阈值：用"不相关查询返回 0 条"校准。
7. 预算：注入不超过上下文的 5%–15%。
8. 矛盾检测：写入时检测并失效旧的。
9. 注入时给时间戳：让模型自己判断时效。
10. 定期整理：合并重复、清理过时。

## 六、学术界的结论

### 6.1 记忆的分类

认知科学对记忆的分类被广泛借用到系统设计：

| 类型 | 内容 | 系统对应 |
|---|---|---|
| **情景记忆** | 具体发生过的事 | 会话历史、事件日志 |
| **语义记忆** | 一般性事实 | 事实库、知识库 |
| **程序记忆** | 怎么做某件事 | 技能（见 4.2） |

这个分类的实用价值：**三类的存储与检索方式不同**——情景记忆按时间检索，语义记忆按内容检索，程序记忆按任务匹配。

"把三类混在一个库里"是一个常见设计错误：它们的时效性、检索方式、注入目的都不同。

### 6.2 分层记忆与虚拟上下文

把"记忆"做成"可以分页的虚拟内存"是一个有影响的思路：**模型看到的上下文只是工作集，其余按需换入**。

它的三个机制：

1. **工作上下文**（当前可见）。
2. 外部存储（可检索）。
3. 分页操作（显式地把内容换入换出）。

与 3.3 的上下文压缩的区别：压缩是**有损**的（摘要），分页是无损的（原样换入换出）。两者可以结合：常用内容分页保留，不常用的压缩。

### 6.3 遗忘曲线

心理学里的遗忘曲线指出：**记忆的保持率随时间指数下降**，且间隔重复能显著减缓下降。

对记忆系统的三条启示：

| 启示 | 做法 |
|---|---|
| 衰减应当是指数的 | 半衰期模型（3.3 用的正是这个） |
| **被反复用到的记忆应当保留更久** | 每次命中重置衰减 |
| 一次性记忆尽早淘汰 | 不重置 |

"每次命中重置衰减"是一个简单而有效的改进：它让"常用的记忆"自动获得更长的生命。

### 6.4 检索增强的评测

记忆与检索系统需要专门的评测方法：

| 维度 | 怎么测 |
|---|---|
| **命中率** | 有答案的问题里，检索到了正确的记忆 |
| **准确率** | 返回的记忆里，有多少是相关的 |
| **无关注入率** | 不相关时是否强行返回（应当为 0） |
| **端到端效果** | 有记忆与无记忆的任务成功率对比 |

"端到端对比"是最有说服力的一条：**它回答的是"记忆到底有没有用"**，而不只是"检索准不准"。

注意第 3 行与算例的对应：算例里"不相关查询的命中条数是 0"，正是这个指标。

## 七、理论：三个模型

### 7.1 写入过滤的通过率

$$
\text{通过率} = \frac{\text{通过的候选}}{\text{全部候选}}
$$

算例实测：4 个候选 → 2 个通过（**通过率 50%**）。

这个比例本身是一个可监控的指标：如果通过率接近 100%，说明过滤太松（噪声会积攒）。如果接近 0%，说明太严（记不住东西）。

### 7.2 检索打分

$$
\text{score} = \text{relevance} \times 0.5^{\Delta t / H}
$$

算例实测：三条得分分别是 1.069、1.265、0.075，且**较新的排在前面**。

读法：衰减项让**同样相关的新旧记忆产生分差**。半衰期 $H$ 是最需要按业务调的参数——偏好类可以长（月），环境类应该短（天）。

### 7.3 阈值的作用

$$
\text{返回条目} = \{ m : \text{score}(m) > \theta \}
$$

算例实测：阈值挡掉 1 条，不相关查询返回 0 条。

**阈值的作用不只是"过滤低分"，而是保证"宁可不返回"**。一个不能返回空集的检索系统必然污染上下文。


要求：

- 逐条按 3.1 的四判据判断，说明每条拒或不拒的理由。

### 第二题：设计检索打分

它做到的事：
