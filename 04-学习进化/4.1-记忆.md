## 本篇新词

- 记忆条目（memory entry） 指跨会话保留的一条事实或偏好。它与会话历史的区别是跨会话。
- 写入策略（write policy） 指决定"什么值得记"的三个过滤器。
- 相关性检索 指按当前任务需要找回条目，它由关键词、时间与频率三种信号构成。
- 注入预算（injection budget） 指一次请求最多注入多少条与多少 token。
- 抑制（suppression） 指降低条目的可检索性而不删除它。
- 记忆污染 指错误信息被写入并长期影响后续判断。
- 有界策略（bounded policy） 指容量满时的处置：拒绝、合并或抑制。

## 一、【设计原因】

### 1.1 缺陷一：记忆写了，但从没被用上

系统有记忆功能而效果为零，原因有三种：写入的条目从来没有被注入（没有检索环节）、检索的查询词与条目用词对不上、或者检索到了但没有注入（预算为零或被别的内容挤掉）。

三种原因的最终表现都是"它没记住"，因此从外部看不出差别。区分它们需要三个数字：写入条数、检索命中条数、实际注入条数。

### 1.2 缺陷二：错误的结论被当成事实长期保留

一条错误结论被写入记忆之后，它会在后续每一个相关任务里被注入，从而持续影响判断。危害随使用次数增长：用得越多，被当成事实的机会越多。

来源有三类：模型的一次误判被当成事实记下、用户的一次临时表达被当成长期偏好、以及过期的事实没有被更新。

### 1.3 缺陷三：上下文被记忆撑爆

检索返回前十条而每条都注入，如果有些条目很长，它们可能占掉窗口的一大部分，从而挤掉本该留给历史的空间。

它的后果与"大输出撑爆上下文"是同一类。一个细节是裁剪的粒度：**截断单条比不注入它更糟**，因为半句话可能误导。

### 1.4 缺陷四：写入太随意，检索失准

记忆里存了大量低价值信息（重复的、临时的、别人也能推断的），于是相关的那几条在前十条里排不进——因为候选集本身太大了。

它的修法不是改检索算法（算法只能在候选集里排序），而是收紧写入。

### 1.5 由此确定的设计目标

1. 写入必须过三个过滤器，不通过就不进存储。
2. 推测类信息允许写入，但必须带来源标注。
3. 相关性由多种信号组合，且组合权重用真实数据检验。
4. 注入有双重预算，且按稳定性分层放置。
5. 容量满时默认拒绝，优先尝试合并，淘汰用抑制而不是删除。

**本节要点**

- "没记住"有三种原因，靠三个数字区分。
- 错误条目的危害随使用次数增长。
- 截断单条比不注入更糟。
- 检索的上限由写入决定。
- 五条目标：写入有门槛、推测带标注、权重经检验、预算双重、拒绝优先。

## 二、【直觉】

### 2.1 笔记本与聊天记录

聊天记录记的是"这次说了什么"，而笔记本记的是"以后还用得着的"。

- 聊天记录属于一次对话，说完就归档。
- 笔记本跨对话保留，因此写之前要判断"以后会用吗"。
- 笔记本写满了，不能随手撕掉一页——撕掉哪一页需要一个理由。

::: keypoint 反直觉点
**记忆系统的效果由"检索到的对不对"决定，而不是由"存了多少"决定。** 多数实现的问题不是容量不足，而是写入太随意导致检索失准，而失准的表现是"它记住了但没用对"——听起来像模型的错，实际是写入策略的错。
:::

### 2.2 三个信号

想找回一条笔记时，人会同时用三条线索。

- 关键词：我记得里面提到过"部署"这个词。
- 时间：应该是最近写的。
- 频率：这条我以前翻过好几次。

三条各自会失效：用词不同就搜不到，新写的不一定更相关，而常用的是不是更该优先也不确定。因此它们需要组合，而组合方式要拿真实数据检验。

### 2.3 一个数字直觉

设一条错误记忆在每次相关任务中被注入的概率是 0.3，跑了 10 次相关任务。

$$
\text{至少影响一次的期望次数} = 10 \times 0.3 = 3 .
$$

这就是污染的形态：它不是"错一次"，而是"在后续每一次相关任务里都可能错一次"。而注入预算是它唯一的减速带——如果一次只注入 2 条而候选有 200 条，那么错误条目被选中的概率本身就低。

**本节要点**

- 笔记本跨对话，因此写入前要判断。
- 相关性由三条线索组合，各自会失效。
- 污染的危害随相关任务次数线性增长。

## 三、【严格】

### 3.1 定义

::: theorem 定义 4.1.1（记忆条目）
一条记忆条目是

$$
e = (\mathit{id},\ \mathit{text},\ \mathit{kind},\ \mathit{source},\ \mathit{createdAt},\ \mathit{useCount},\ \mathit{lastUsedAt},\ \mathit{status}),
$$

其中 $\mathit{kind} \in \{\text{事实},\ \text{偏好},\ \text{推测}\}$，$\mathit{status} \in \{\text{有效},\ \text{被抑制},\ \text{被取代}\}$。**$\mathit{kind}$ 与 $\mathit{source}$ 是防污染的关键字段**，而 $\mathit{useCount}$ 与 $\mathit{lastUsedAt}$ 是淘汰的依据。
:::

::: theorem 定义 4.1.2（写入策略）
一条候选 $c$ 被接受，当且仅当三个过滤器全部通过：

$$
\mathrm{accept}(c) = \mathrm{crossSession}(c) \ \land\ \mathrm{attributed}(c) \ \land\ \neg\mathrm{temporary}(c),
$$

其中 $\mathrm{attributed}(c)$ 要求：若 $\mathit{kind}(c) = \text{推测}$，则 $\mathit{source}(c)$ 非空。
:::

::: theorem 定义 4.1.3（相关性打分）
条目 $e$ 对查询 $q$ 的得分是三种信号的加权和：

$$
s(e, q) = w_1 \cdot \mathrm{overlap}(q, e) + w_2 \cdot \mathrm{recency}(e, t) + w_3 \cdot \mathrm{frequency}(e),
$$

其中 $w_i \ge 0$。检索结果是 $\{e : s(e,q) \ge \tau\}$ 按得分降序取前 $k$ 条。**阈值 $\tau$ 的作用是不硬凑满 $k$ 条。**
:::

::: theorem 定义 4.1.4（注入预算与分层）
注入受双重限制：

$$
\mathrm{inject} = \min(k_{\max}, \lfloor T / \bar{L} \rfloor),
$$

其中 $T$ 是 token 预算，$\bar{L}$ 是平均条目长度。**放置按稳定性分层**：长期被使用到的条目放上下文前部（它们很少变，因此不影响前缀缓存），与当前任务相关的放后部。
:::

::: theorem 定义 4.1.5（有界策略）
容量满时可选三种处置：**拒绝**（写入失败）、**合并**（把相似条目压成一条并保留演化痕迹）、**抑制**（降低可检索性而不删除）。本课程的默认是拒绝，推荐处置是合并，长期补充是抑制。
:::

::: theorem 定义 4.1.6（记忆污染）
设错误条目 $e$ 在每次相关任务中被注入的概率为 $p$。污染的量度是它累计影响过的相关任务次数。

$$
\mathbb{E}[\text{影响次数}] = n \cdot p,
$$

其中 $n$ 是相关任务次数。
:::

### 3.2 命题

::: theorem 命题 4.1.1（检索的上限由写入决定）
检索是在候选集上排序的运算。若相关条目不在候选集中，则任何检索算法都无法返回它。

**证明.** 检索的输出是 $\mathrm{rank}(C)$ 的一个前缀，其中 $C$ 是候选集。相关条目 $e^* \notin C$ 时，$e^* \notin \mathrm{rank}(C)$，故不在任何前缀中。

↓ **为什么能这么写？** 排序不改变集合的成员，只改变顺序。

$\blacksquare$

::: keypoint 所以收紧写入比改算法有效
**记多了会污染候选集，记少了等于没有记忆。** 而"该不该记"这条判断放在系统侧（三个过滤器），模型只负责提议。
:::

::: theorem 命题 4.1.2（污染的危害随相关任务次数线性增长）
由定义 4.1.6，$n$ 次相关任务中错误条目被注入的期望次数是 $n \cdot p$，且 $p$ 不随 $n$ 下降。

**证明.** 每次相关任务的检索与打分是独立过程，注入概率为常数 $p$（条目内容与权重未变）。期望的可加性给出线性关系。

↓ **为什么能这么写？** 期望对独立同分布的事件可加。

$\blacksquare$

**数值**：$p = 0.3$、$n = 10$ 时期望影响 3 次。**降低它的唯一手段是降低 $p$（收紧写入或提高阈值），而不是指望"用久了自然会发现"。**
:::

::: theorem 命题 4.1.3（截断单条比跳过更糟）
存在条目 $e$ 使 $\mathrm{truncate}(e)$ 的信息含义与 $e$ 不同，而"不注入 $e$"的损失是已知的缺失。故在预算不足时，跳过整条优于截断。

**证明.** 取 $e$ 的语义依赖句尾（例如含"不要"的约束）。截断后剩余部分构成一个语义不同的陈述，而它会被模型当成完整信息使用。不注入时模型缺少该信息，缺失是可察觉的（模型可能追问或另找），而错误的信息不可察觉。

↓ **为什么能这么写？** 两种处置的失真类型不同：一个是"没有"，一个是"错的"。

$\blacksquare$

**数值**：预算不足以容纳剩余 $n$ 条时，注入条数从 $n$ 降到 $n-1$，而不是把某条裁成半句。

::: theorem 命题 4.1.4（分层注入降低前缀失效频率）
设稳定部分占 $s$ 个 token、任务相关部分占 $t$ 个 token。全部置于前部时，任一任务相关记忆的变化都会使 $s + t$ 个 token 的前缀失效。分层放置时，只有 $s$ 参与前缀，其变化频率取决于稳定条目的更新频率。

**证明.** 前缀缓存的命中条件是前缀逐字节相同。任务相关记忆每次任务都可能变化，故它们若在前部，则每次都破坏前缀。把它们放在后部后，前部只包含稳定部分，故前缀只在稳定部分变化时失效。

↓ **为什么能这么写？** 命中条件只看前缀内容是否相同。

$\blacksquare$

**数值**：$s = 1500$、$t = 500$ 时，分层使每次任务的失效长度从 2000 token 降到 0（在稳定部分不变的假设下）。

::: theorem 命题 4.1.4（补）与 4.1.5（容量满时拒绝是唯一无依据风险的处置）
若系统没有任何关于条目使用情况的记录，则任何"丢弃哪一条"的策略都缺少依据。

**证明.** 丢弃策略是一个选择函数，它需要条目上的全序（谁更该走）。可用的全序来源只有两类：写入时间（假设旧的更可弃）与使用情况（假设少用的更可弃）。前者以"新旧"代替"相关"，而一条重要的项目约定可能三个月才用一次。后者需要观测，而无观测时该全序不存在。故在无观测时，唯一不引入错误依据的动作是拒绝。

↓ **为什么能这么写？** 选择需要依据，而无依据的选择等价于任意选择。

$\blacksquare$

::: keypoint 由此推出观测不是可选功能
**淘汰需要依据，依据来自观测。** 观测回答四件事：写入多少条、检索命中多少条、实际注入多少条、每条被用过多少次。它们都可以从日志派生，因此不需要新的埋点设施。
:::

::: theorem 命题 4.1.6（抑制优于删除）
抑制保留条目并只改变它的可检索性，因此它可逆且保留了演化痕迹。删除使派生结果不可重建（与 2.7 的不变量冲突）。

**证明.** 抑制只修改 $\mathit{status}$，条目内容仍在，故任何依赖历史条目的派生物仍然可重算，且可撤销。删除移除条目，使"当时记过什么、后来改成了什么"这两个派生结果失去输入，违反可重建。

↓ **为什么能这么写？** 可重建要求输入仍在日志里，而删除移除了输入。

$\blacksquare$

### 3.3 本节要点

**本节要点**

- 记忆条目带来源类别与使用计数（定义 4.1.1）。
- 写入由三个过滤器把关（定义 4.1.2）。
- 相关性是三种信号的加权和，且有阈值（定义 4.1.3）。
- 注入受双重预算限制，并按稳定性分层（定义 4.1.4）。
- 有界策略三种：拒绝、合并、抑制（定义 4.1.5）。
- 污染的期望影响次数是 $n \cdot p$（定义 4.1.6）。
- 检索的上限由写入决定（命题 4.1.1）。
- 污染危害随使用线性增长（命题 4.1.2）。
- 截断单条比跳过更糟（命题 4.1.3）。
- 分层注入降低前缀失效（命题 4.1.4）。
- 无观测时拒绝是唯一安全处置（命题 4.1.5）。
- 抑制优于删除（命题 4.1.6）。

## 四、【回到直觉】

- **定义 4.1.1 说的**：每条记忆要写清它是事实、偏好还是推测，以及是谁说的。
- **定义 4.1.2 说的**：跨会话有用、来源可查、不是临时的，三条都过才写。
- **定义 4.1.3 说的**：相关性是三种线索的加权和，且低于门槛的不凑数。
- **定义 4.1.4 说的**：条数与 token 双限，稳定的放前面，任务相关的放后面。
- **定义 4.1.5 说的**：满了就拒绝，先试着合并，实在要退场的是抑制而不是删除。
- **定义 4.1.6 说的**：一条错记忆的危害，与它之后被用到的次数成正比。
- **命题 4.1.1 说的**：排序只能改变次序，不能把不在候选集里的条目变出来。
- **命题 4.1.2 说的**：错误条目每被相关任务碰到一次都可能生效一次。
- **命题 4.1.3 说的**：半句话是"错的"，缺一条是"没有的"，后者更安全。
- **命题 4.1.4 说的**：稳定的放前面，任务相关的放后面，前缀就不会被频繁打断。
- **命题 4.1.5 说的**：不知道该丢哪条时，拒绝写入是唯一不冒险的动作。
- **命题 4.1.6 说的**：抑制只是让它难找，删除是让它消失，前者可逆。

**本节要点**

- 来源类别是防污染的第一道。
- 三过滤器决定候选集质量。
- 阈值防止硬凑。
- 分层保护前缀。
- 拒绝是安全默认。
- 抑制保留痕迹。

## 五、【工具箱】

### 5.1 写入判断三问

1. 它在下一个会话里还有用吗？
2. 它是可验证的事实，还是需要标注的推测？
3. 它在一周后还成立吗？

**三问都过才写。** 第三问挡的是"这次任务特有的东西"。

### 5.2 检索的评估

准备一批查询与人工标注的相关条目，测不同权重下前 $k$ 条的准确率。

**这是唯一能验证"检索够不够准"的方式**，也是权重不能靠猜的原因。

| 信号 | 回答 | 失效方式 |
|---|---|---|
| 关键词 | 提没提到 | 用词不同就匹配不上 |
| 向量相似度 | 说的是不是同一件事 | 对专有名词不稳定，需要额外调用 |
| 时间与频率 | 还新不新、以前用过吗 | 会把长期有效但少用的排到后面 |

### 5.3 注入规划

1. 条数与 token 双限。
2. 稳定的在前、任务相关的在后。
3. 预算不足时**跳过整条**，不截断。
4. 每条带编号与性质说明。

**格式的例子**：先说"以下是已知的偏好与事实"，再逐条列出。

### 5.4 淘汰的依据

| 依据 | 是否有用 |
|---|---|
| 存在时长 | 不是相关性，重要条目可能很久才用一次 |
| 使用次数与最近使用 | 是相关性，但需要观测 |
| 无依据 | 只能拒绝写入 |

**定期看的是"最近 N 次相关检索里有没有命中它"，而不是"它多久没被写过"。**

### 5.5 污染的三条防线

1. 来源标注：写入时记下是谁说的，注入时如实告诉模型哪些是推测。
2. 有效期：会失效的条目带过期时间，过期后不参与检索但保留在存储里。
3. 可撤销：发现错误时能低成本地抑制它。

**三条缺一条，污染就会持续。** 其中第三条的成本必须低——如果撤销要人工改数据文件，它实际上不会被执行。

**本节要点**

- 写入三问。
- 检索准确率要人工标注才能测。
- 注入双限且分层，预算不足跳过整条。
- 淘汰看使用而不是时长。
- 污染防线三条，缺一不可。

### 7.2 条目段与写入

```js
// 定义 4.1.2：三个过滤器——跨会话有用、来源可查、不是临时的
export function checkWriteFilters(candidate) {
  const reasons = []
  if (!candidate.crossSession) reasons.push('只在本次会话有用')
  if (candidate.kind === 'inference' && !candidate.source) reasons.push('推测类记忆缺来源标注')
  if (candidate.temporary) reasons.push('临时信息')
  return { accept: reasons.length === 0, reasons }
}
```

### 7.3 检索段

检索段先过滤掉不应参与的条目，再按三种信号打分。

```js
// 定义 4.1.3：三种信号加权，阈值在前、取前 k 在后
export const WEIGHTS = { overlap: 1.0, recency: 0.3, frequency: 0.2 }

export function scoreEntry(query, e, now, decayDays = 30) {
  const q = query.toLowerCase()
  const overlap = e.text.toLowerCase().includes(q) ? 1 : 0
  const ageDays = (now - (e.lastUsedAt ?? e.createdAt)) / 86400
  const recency = 1 / (1 + ageDays / decayDays)
  const frequency = Math.min(1, e.useCount / 5)
  return WEIGHTS.overlap * overlap + WEIGHTS.recency * recency + WEIGHTS.frequency * frequency
}

export function retrieve(query, entries, opts) {
  return entries
    .filter((e) => e.status === 'active')
    .map((e) => ({ e, s: scoreEntry(query, e, opts.now, opts.decayDays) }))
    .filter((x) => x.s >= opts.threshold)
    .sort((a, b) => b.s - a.s)
    .slice(0, opts.k)
    .map((x) => x.e)
}
```

### 7.4 注入段

注入段按稳定性分层，并在预算不足时跳过整条。

```js
// 定义 4.1.4：双重预算，稳定在前，预算不足跳过整条
export function planInjection(entries, budget, stableThreshold = 3) {
  const stable = entries.filter((e) => e.useCount >= stableThreshold)
  const rest = entries.filter((e) => e.useCount < stableThreshold)
  const picked = []
  let tokens = 0
  for (const e of [...stable, ...rest]) {
    if (picked.length >= budget.maxEntries) break
    if (tokens + e.tokens > budget.maxTokens) continue      // 整条跳过，不截断
    picked.push(e)
    tokens += e.tokens
  }
  return { picked, tokens, skipped: entries.length - picked.length }
}

/**
 * 定义 4.1.4：把注入内容格式化，带上性质说明与编号。
 * @param picked 选中的条目
 * @returns 给模型的一段文本
 */
export function formatInjection(picked) {
  if (picked.length === 0) return ''
  const lines = picked.map((e, i) => `${i + 1}. [${e.kind}] ${e.text}`)
  return `以下是已知的偏好与事实：\n${lines.join('\n')}`
}
```

### 8.3 评审一份记忆实现的六个问题

### 9.1 决策表

### 9.2 失败模式

**（1）检查放在装载期（L9 位置放错）。** 检索权重在开发时调好一次，而领域或语言变化后不再适用。表现是"以前能记住的现在找不到了"。

**（2）前提会变（L9）。** 命题 4.1.5 的"拒绝是安全处置"以"合并不可行"为前提。若合并总能成功，拒绝就永远不会被触发，容量实际上没有上限。

**（3）写入没有门槛。** 候选集膨胀，相关条目排不进前 k。

**（4）推测不带标注。** 推测被当成事实，且随使用次数放大。

**（5）检索权重靠猜。** 在多语言或专有名词场景下命中率很低。

**（6）注入只看条数。** 长条目占掉大半个窗口。

**（7）截断单条而不是跳过。** 半句话可能含相反的意思。

**（8）把淘汰实现成删除。** 复盘与演化痕迹同时丢失。

**（9）淘汰依据是存在时长。** 重要的低频条目被丢掉。

**（10）记忆全部注入在前部。** 每次任务都破坏前缀缓存。

**本节要点**

- 决策表覆盖 12 种情形。
- 失败模式十条，前两条是位置放错与前提会变。
- 最隐蔽的是"淘汰依据是存在时长"——它看起来合理，而它淘汰掉的恰好是最有价值的长效知识。

## 十、仍未解决

- **检索权重是手工超参。** 换领域或语言需要重调。
- **没有冲突检测。** 矛盾的两条会同时注入，表现为行为不稳定。
- **记忆是纯文本的。** 无法做结构化查询。
- **没有跨设备共享。** 同一用户的多个设备之间不共享记忆。
- **淘汰依赖简单计数。** 一次误用会让条目长期留存。
- **抑制的条目仍占存储。** 长期运行需要归档。

**本节要点**

- 权重与冲突检测是两个真实缺口。
- 文本形态限制了查询能力。
- 归档策略缺失。

**参考要点**

1. 历史属于一条会话，记忆要跨会话继续存在。
2. 跨会话有用、可验证或带标注、不是临时的。
3. 关键词回答"提没提到"，时间回答"还新不新"，频率回答"以前用过吗"。失效方式分别是用词不同、把长效低频条目压低、以及把真正相关的稀释。

5. 不带标注的推测会在后续被当成事实，而它的危害随使用次数增长。
6. 只限条数时长条目会占掉空间，只限 token 时短条目会塞进太多无关内容。
7. 半句话可能表达相反的意思，而"没有"是可察觉的缺失。
8. 按稳定性分层：长期被使用到的放前部（很少变，不影响前缀），任务相关的放后部。
9. 拒绝、合并、抑制。默认是拒绝。
10. 丢弃需要一个"谁更该走"的依据，而这个依据只能来自使用观测。
11. 抑制保留条目与演化痕迹，删除使派生结果不可重建。
12. 来源标注、有效期、可撤销。

## 十二、系统影响回溯

**影响一：写入太随意会让检索失准。** 检索的上限由写入决定，因此收紧写入比改算法有效。

**影响二：记忆与缓存命中率相互影响。** 注入位置决定前缀是否稳定，而解法是按稳定性分层。

**影响三：没有观测的记忆系统无法淘汰。** 淘汰需要依据，依据来自观测，因此观测不是可选的附加功能。

**一处需要修正的预判。** 旧稿把注入预算说成"取窗口的一个固定比例"，读完之后要改掉：**它必须是一个独立配置项**。理由是它与 3.3 的压缩争抢同一块空间，而"记忆多了意味着历史要压得更狠"这个交换必须被显式分配，不能各取一个比例然后互相挤压。

**通向下一步的桥。**

本篇积累的是"事实"：用户偏好什么、项目有什么约定。而系统还需要另一类积累——**"遇到这类事该怎么做"**。那是可复用的做法，它与事实的区别在于它携带步骤与前提，因此它的检索条件不同（按任务类型匹配而不是按关键词），它的失效方式也不同（前提不成立时整条作废）。

所以下一篇是 4.2 技能。它把记忆的写入、检索与有界策略复用一遍，而把"条目"换成"带前提的做法"。
