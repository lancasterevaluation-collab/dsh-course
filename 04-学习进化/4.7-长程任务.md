## 本篇新词

- 长程任务（long-horizon task） 指同时满足三条的任务：跨多次会话、状态量超过一次能载入的量、目标需要被保持。
- 任务状态（task state） 指推进一个任务所需的最小信息集合。它是被筛选出来的，而不像日志那样是全量的。
- 外部化（externalization） 指把任务状态写在系统之外，而不是留在上下文或人的记忆里。
- 续作（resumption） 指中断之后继续推进。它的成本由重建成本决定。
- 检查点（checkpoint） 在任务级指一个可验证的里程碑。
- 进度判断（progress assessment） 指回答"做到哪了、还剩多少"。它的困难在分母。
- 目标漂移 在长程语境下指目标在推进中被逐步改写，每一步都合理而累积起来已经偏离。
- 范围蔓延（scope creep） 指任务范围不断扩张。
- 唯一下一步（single next action） 指状态里唯一一条"接下来做什么"，它让续作入口足够小。

## 一、【设计原因】

### 1.1 缺陷一：每次接着做都要重新读一遍全部历史

任务中断之后重新开始时，执行者要读大量历史才能知道"现在在哪"。

代价有两部分：成本，以及准确性——历史被压缩之后，早期的约束与决策可能已经被压掉，而执行者不知道它们存在。第二种更危险：它表现为"做着做着发现方向不对"。

### 1.2 缺陷二：状态只存在会话里，会话一结束就没了

任务的目标、约束、进度都只在当前会话的上下文里，而它们不会被写下来。于是下一个会话要么从零理解任务，要么让用户重新说明。

一个容易忽略的细节：外部化的对象不只是进度，还包括**决策记录**。少了它，续作时会把已经排除的方案重新评估一遍。

### 1.3 缺陷三："快完成了"永远是快完成了

推进过程中反复得到"快完成了"的评估，而实际剩余工作量并没有减少——因为分母在推进中才变清楚。

### 1.4 缺陷四：目标被悄悄改了

目标被逐步改写（每次调整都合理），或者范围不断扩张。单次调整看不出来，累积之后原始意图已经不在。

### 1.5 缺陷五：同一个坑踩了两次

已经排除的方案被重新评估，已经踩过的坑被重新踩。成因是决策记录没有外部化。

### 1.6 由此确定的设计目标

1. 状态外部化到一份文本文件，可读、可 diff。
2. 状态含八个字段，其中决策记录与未决问题不可省。
3. 唯一下一步，且它带验证方式。
4. 进度用里程碑与剩余待办双度量，偏差即信号。
5. 原始目标冻结，任何调整作为追加的修订记录。

**本节要点**

- 重读历史既贵又不准。
- 决策记录是续作最容易被省略的一项。
- 百分比估算的分母不确定。
- 冻结不是为了禁止变更，而是让变更可见。
- 五条目标：外部化、八字段、唯一下一步、双度量、冻结加修订。

## 二、【直觉】

### 2.1 一张便签

离开工位前贴一张便签，写"下一步做什么"。

- 回来时第一眼看到它，不必回忆。
- 便签上还要写"做完怎么验证"，否则回来仍要重新判断。
- 便签只写一条，写三条就变成了"自己挑一个"，而那正是要避免的。

::: keypoint 反直觉点
**过时的状态比没有状态更糟。** 没有状态时你会重新理解，而过时的状态会给你一个方向——且它是错的。所以续作流程里必须包含"这份状态可信吗"这一步，而不是默认它可信。
:::

### 2.2 可数的剩余

问"还剩几成"得不到可靠答案，因为分母在变。问"还剩几件可验证的事"得到一个可数的数。

- 里程碑给出阶段感，适合对外沟通。
- 剩余待办数给出工作量，适合内部判断。
- **两者的偏差本身是信号**：里程碑在推进而待办数不降，说明发现了新工作。

### 2.3 一个数字直觉

设任务的历史有 200K token，而外部化状态有 2K token。

| 续作方式 | 要读的 | 成本量级 | 引入的错误 |
|---|---|---|---|
| 重放历史 | 全部历史 | 200K | 压缩有损，早期约束可能已被压掉 |
| 读状态文件 | 状态加最近若干轮 | 2K | 状态可能过时 |

**100 倍的量级差决定了长程任务的可行性上限。** 不外部化的系统在任务长度超过一个上下文之后就开始失效，而它的表现不是报错，而是回到已经做完的事情上。

**本节要点**

- 唯一下一步是续作的最小入口。
- 过时状态比没有状态更糟。
- 双度量的偏差是信号。
- 外部化把续作成本降两个数量级。

## 三、【严格】

### 3.1 定义

::: theorem 定义 4.7.1（长程任务）
任务 $T$ 是长程的，当且仅当三条同时成立：

$$
\text{跨多次会话} \ \land\ \text{状态量} > \text{一次可载入的量} \ \land\ \text{目标需要被保持}.
$$

三条缺一不可。一次会话内的大重构虽然长，但它在同一个上下文里，因此不是长程问题。
:::

::: theorem 定义 4.7.2（任务状态）
任务状态是八元组

$$
S = (\mathit{goal},\ \mathit{constraints},\ \mathit{milestones},\ \mathit{progress},\ \mathit{decisions},\ \mathit{open},\ \mathit{artifacts},\ \mathit{next}),
$$

其中 $\mathit{constraints}$ 是**判据形式**的（可检查），$\mathit{next}$ 是**唯一**的下一动作且带验证方式。
:::

::: theorem 定义 4.7.3（外部化）
**外部化**指把状态 $S$ 写在系统之外（一份文本文件）而不是留在上下文或人的记忆里。它要求三件事：

$$
\text{可读} \ \land\ \text{可 diff} \ \land\ \text{可被另一个执行者直接使用}.
$$
:::

::: theorem 定义 4.7.4（续作与重建成本）
续作是一次映射

$$
\mathrm{resume}: S \to (\text{入口},\ \text{上下文},\ \text{剩余},\ \text{下一个检查点},\ \text{过时警告}).
$$

它的成本是 $O(|S|)$，而重放全部历史的成本是 $O(|H|)$。
:::

::: theorem 定义 4.7.5（进度的双度量）
进度由两个量共同表示：

$$
\mathrm{progress} = \big(\text{里程碑：已完成的个数} / \text{总数},\ \text{剩余待办：可数的项数}\big).
$$

**两者的偏差是一个信号**：里程碑在推进而待办数不下降时，说明在推进过程中发现了新工作。
:::

::: theorem 定义 4.7.6（目标冻结与变更记录）
原始目标 $\mathit{goal}$ **不被修改**。任何方向调整作为一条追加记录进入 $\mathit{revisions}$：

$$
\mathit{revisions}' = \mathit{revisions} \ \|\ [\,(\text{调整内容},\ \text{理由},\ \text{时间})\,].
$$

范围变更同理：新增工作项在待办里带一个标记，使"原计划内的"与"新增的"可分开计数。
:::

### 3.2 命题

::: theorem 命题 4.7.1（续作成本差决定长程任务的可行性）
若状态量为 $S$，历史量为 $H$，则两种续作方式的成本比是 $H / S$，随任务长度增长。

**证明.** 重放需读入全部历史，成本 $O(H)$。读状态文件需读入 $|S|$ 加少量近期上下文，成本 $O(S)$。两者比值 $H/S$ 随任务推进而增大（历史单调增长，而状态规模由任务的复杂度而非长度决定）。

↓ **为什么能这么写？** 成本是读入量，而两种方式的读入量由不同量决定。

$\blacksquare$

**数值**：$H = 200{,}000$ token、$S = 2{,}000$ token 时比值为 100。**这是量级差，不是常数因子**，因此它决定的是可行性而不是效率。
:::

::: theorem 命题 4.7.2（百分比估算系统性乐观）
若分母 $\mathrm{total}(t)$ 随时间单调不减（推进过程会不断发现新工作），则对任意 $t_2 > t_1$，

$$
\frac{\mathrm{done}(t_1)}{\mathrm{total}(t_2)} \le \frac{\mathrm{done}(t_1)}{\mathrm{total}(t_1)} .
$$

即用时刻 $t_1$ 的分母算出的完成度高于用 $t_2$ 算出的。

**证明.** $\mathrm{total}(t_2) \ge \mathrm{total}(t_1) > 0$ 时，分母越大商越小。故同一分子在较大分母下的值更小——即用早期分母估算的完成度偏高。

↓ **为什么能这么写？** 分母单调不减是"发现新工作"的直接表述。

$\blacksquare$

::: keypoint 可操作的替代
**不问"完成了几成"，问"还剩几件可验证的事"。** 后者不依赖分母的估计，而是一个可数的事实。
:::

::: theorem 4.7.3（五类长程失败模式中四类源于状态缺失）
原地打转、遗忘约束、重复劳动、范围蔓延的成因都不是执行者的能力。

**证明.** 逐类对照：原地打转的成因是决策记录缺失（已排除的方案没有留下痕迹），遗忘约束的成因是约束只存在于早期上下文，重复劳动的成因是进度与决策未外部化，范围蔓延的成因是新增工作没有显式记录。四者都指向"某项信息不在当前可读的状态里"，故与能力无关。

↓ **为什么能这么写？** 逐一给出成因，而每个成因都是信息缺失。

$\blacksquare$

::: keypoint 第五类方向相反
**过早收敛**是"为了收尾而收尾"，它的成因是把目标反过来适配于已有进度。防线是检查点必须可验证：一个里程碑的完成若只有模糊的说法支撑，它就不算完成。
:::

::: theorem 4.7.4（多条下一步会把选择成本转移给状态最不清楚的人）
若状态里列出若干待办而不指明唯一的下一步，则续作者需要先读完状态与上下文才能判断先做哪一条。

**证明.** 判断"先做哪一条"需要理解全部待办的相互依赖，而这份理解正是当前执行者（状态最清楚的人）拥有的。把它交给续作者意味着续作必须先完成一次与推进等量的理解工作。故入口的最小化要求状态里给出唯一的一条。

↓ **为什么能这么写？** 选择的成本由掌握信息最少的一方承担时最高。

$\blacksquare$

::: theorem 4.7.5（过时状态比没有状态更有害）
设状态过时（推进已发生而状态未更新）。此时执行者依据它得到的方向与实际进度不符。

**证明.** 无状态时，执行者的下一步是"重新理解任务"，这个动作的产出是正确理解。有（过时的）状态时，执行者的下一步是"按状态指示继续"，而这个指示基于旧进度，故可能指向已完成或已排除的工作。前者耗时，后者产生错误动作。

↓ **为什么能这么写？** 错误信息被当作可信输入时，它的危害大于缺少信息。

$\blacksquare$

**数值**：因此续作流程的第四步是"这份状态可信吗"，其判据是可机械检查的三条：产物比状态新、状态长期未更新、有待办而没有进行中的项。
:::

::: theorem 4.7.6（冻结使变更可见）
若原始目标可被直接修改，则经过若干次合理的小调整之后，任何单一时刻都看不出方向已经改变。

**证明.** 设目标经 $k$ 次调整，每次调整幅度小于某阈值而方向一致。逐次观察时每次都在阈值内（看不出问题），而 $k$ 次之后与原目标的距离已经超过阈值。没有原目标作参照时，这个距离无法被测量。

↓ **为什么能这么写？** 变化量需要与被测量对象比较，而删除参照物使比较不可能。

$\blacksquare$

### 3.3 本节要点

**本节要点**

- 长程任务由三个条件定义（定义 4.7.1）。
- 状态含八个字段，约束是判据形式，下一步唯一（定义 4.7.2）。
- 外部化要求可读、可 diff、可被他人使用（定义 4.7.3）。
- 续作的成本是 $O(S)$ 而对历史的成本是 $O(H)$（定义 4.7.4）。
- 进度用里程碑与剩余待办双度量（定义 4.7.5）。
- 目标冻结，变更追加为修订记录（定义 4.7.6）。
- 续作成本差决定可行性（命题 4.7.1）。
- 百分比估算系统性乐观（命题 4.7.2）。
- 四类失败源于状态缺失（命题 4.7.3）。
- 多条下一步转移选择成本（命题 4.7.4）。
- 过时状态比没有状态更有害（命题 4.7.5）。
- 冻结使变更可见（命题 4.7.6）。

## 四、【回到直觉】

- **定义 4.7.1 说的**：跨天、装不下、目标要保持，三条都中才叫长程。
- **定义 4.7.2 说的**：目标、约束、里程碑、进度、决策、未决、产物、下一步，八样。
- **定义 4.7.3 说的**：写在文件里，能读、能比、别人也能用。
- **定义 4.7.4 说的**：读一张纸能开工，重读全部历史也能开工，但成本差两个数量级。
- **定义 4.7.5 说的**：既看阶段，也数剩余；两者不同步就是发现新工作的信号。
- **定义 4.7.6 说的**：原文不改，改动另记一笔并写理由。
- **命题 4.7.1 说的**：200K 与 2K 是 100 倍的差。
- **命题 4.7.2 说的**：分母在变，所以"完成七成"总是偏乐观。
- **命题 4.7.3 说的**：打转、忘约束、重复、蔓延，四条都不怪能力。
- **命题 4.7.4 说的**：列三条待办，等于让最不清楚情况的人来做选择。
- **命题 4.7.5 说的**：错的方向比没有方向更糟。
- **命题 4.7.6 说的**：没有原文对照，改到哪里都看不出来。

**本节要点**

- 三条件定义长程。
- 八字段。
- 外部化三点。
- 成本差百倍。
- 偏差是信号。
- 原文不改。

## 五、【工具箱】

### 5.1 状态的八个字段与维护时机

| 字段 | 维护时机 |
|---|---|
| 目标（冻结） | 开始时写一次，修订时追加 |
| 约束（判据形式） | 开始时，发现新约束时 |
| 里程碑（带检查方式） | 完成一个时 |
| 进度（可数的项） | 每次推进之后 |
| 决策记录（含理由与排除项） | 每次做选择时 |
| 未决问题 | 出现与解决时 |
| 产物位置 | 产生时 |
| 下一步（唯一，带验证） | 每次推进之后 |

### 5.2 续作的四步

1. 读**唯一下一步**（入口）。
2. 读必要的上下文：目标、约束、决策记录。
3. 读剩余与下一个检查点。
4. 检查**状态是否可信**（三条机械判据）。

**第四条不能省**：产物比状态新、状态长期未更新、有待办而没有进行中的项。

### 5.3 进度判断

| 做法 | 缺陷 |
|---|---|
| 百分比 | 分母不确定，系统性乐观 |
| 里程碑 | 粒度可能不均 |
| 剩余待办数 | 未知工作不会出现在列表里 |

**两者一起用**：里程碑对外，待办数对内，偏差即信号。

### 5.4 变更的两条纪律

1. 目标修订必须写理由——否则复盘时无法判断它是精确化还是改方向。
2. 新增工作项要带标记——否则范围蔓延不可数，而"可数"是处理它的前提。

### 5.5 人也用同一套

同一条方法用在人身上，形态更简单：

- 把状态写在文件里，而不是记在脑子里。
- 每次中断前写下唯一的下一动作（带验证方式）。
- 把任务切成可验证的阶段。
- 每完成一个检查点，重读一次原始目标。
- 记录决策理由，尤其是被排除的方案。

**本节要点**

- 八字段各有时机。
- 续作四步，第四步不可省。
- 双度量加偏差信号。
- 修订带理由、新增带标记。
- 人与系统用同一套。

### 7.2 状态段

状态段在写入时校验三条设计约束。

```js
// 定义 4.7.2：写入时校验唯一下一步、可检查的约束、唯一的进行中项
export function writeState(state, now) {
  if (!state.next || state.next.length < 8) throw new Error('缺少唯一下一步（或它太短，无法作为入口）')
  const bad = state.constraints.filter((c) => !isCheckable(c))
  if (bad.length) throw new Error(`约束必须可检查：${bad.join('、')}`)
  if (state.doing.length > 1) throw new Error('进行中的项应当只有一项')
  return { ...state, updatedAt: now }
}

/**
 * 定义 4.7.2：约束是否是判据形式。
 * @param c 约束文本
 * @returns 是否可检查
 */
export function isCheckable(c) {
  return /(通过|不超过|齐全|等于|至少|≤|≥|\d+%|\d+ 节|\d+ 篇)/.test(c)
}
```

### 7.3 续作段

续作段给出最小入口，并在第四步检查状态是否可信。

```js
// 定义 4.7.4：续作包——入口、上下文、剩余、检查点、过时警告
export function resume(state, ctx) {
  const nextMilestone = state.milestones.find((m) => !m.done)
  return {
    startHere: state.next,
    context: { goal: state.goal, constraints: state.constraints, decisions: state.decisions },
    remaining: { todos: state.todo.length, added: state.todo.filter((t) => t.added).length },
    verifyAt: nextMilestone ? { name: nextMilestone.name, check: nextMilestone.check } : null,
    warnings: detectStale(state, ctx),
  }
}

/**
 * 命题 4.7.5：状态是否过时的三条机械判据。
 * @param state 任务状态
 * @param ctx 形如 `{ now, mtimeOf, staleAfter }`
 * @returns 警告数组
 */
export function detectStale(state, ctx) {
  const out = []
  const newest = Math.max(0, ...state.artifacts.map((a) => ctx.mtimeOf(a)))
  if (newest > state.updatedAt) out.push('产物比状态新：状态可能漏记了进展')
  if (ctx.now - state.updatedAt > ctx.staleAfter) out.push('状态长期未更新')
  if (state.doing.length === 0 && state.todo.length > 0) out.push('有待办而没有进行中的项：进度记录可能不完整')
  return out
}
```

### 7.4 进度段与变更段

进度段做双度量与偏差检测，变更段只做追加。

```js
// 定义 4.7.5：双度量与偏差信号
export function assess(state, baselineTodoCount) {
  const ms = { done: state.milestones.filter((m) => m.done).length, total: state.milestones.length }
  const todos = { open: state.todo.length, added: state.todo.filter((t) => t.added).length }
  const divergence = ms.done > 0 && todos.open >= baselineTodoCount
  return { milestones: ms, todos, divergence, note: divergence ? '里程碑推进但待办未减少：范围可能在扩张' : null }
}
```

### 9.2 失败模式

**（1）检查放在装载期（L9 位置放错）。** 状态的可信性只在任务开始时判断一次，而它在推进中随时可能过时。表现是"按几天前的状态继续，做到一半发现做过"。

**（2）前提会变（L9）。** 命题 4.7.2 的乐观偏差以"分母单调不减"为前提。若某个阶段分母确实固定（范围已冻结），百分比估算在那个阶段是可用的。

**（3）状态不外部化。** 会话结束即丢失，下一个会话从零理解。

**（4）只记进度不记决策。** 已排除的方案被重新评估。

**（5）下一步列出多条。** 选择成本转移给状态最不清楚的人。

**（6）约束写成原则。** 不可检查，也就无法在续作时校验。

**（7）直接修改目标字段。** 方向变化不可见。

**（8）新增工作不标记。** 范围蔓延不可数。

**（9）续作时不检查状态可信性。** 过时状态给出错误方向。

**（10）过早收敛。** 为了收尾而收尾，把目标反过来适配已有进度。

**本节要点**

- 决策表覆盖 12 种情形。
- 失败模式十条，前两条是位置放错与前提会变。
- 最隐蔽的是"过时状态被当成事实"——它不报错，只给出错误方向。

## 十二、系统影响回溯

**影响一：任务状态与记忆会争抢容量，而它们的分工必须明确。** 任务状态应当是独立存储，并在完成后归档。

**影响二：长程任务的失败模式主要不是能力不足，而是状态丢失。** 这解释了为什么长程能力在工程上主要是一个状态管理问题。

**影响三：目标冻结把变更从隐性变成显性，代价是灵活性下降。** 这与 4.5 的元控制同构，理由也相同。

**一处需要修正的预判。** 旧稿把本篇定位成"第 4 卷的收口"，读完之后要补一句它更准确的位置：**它是全课程里唯一同时面向系统与人的一篇**。前六篇的机制都是给系统用的，而本篇的状态结构同时是"一个人怎么推进一件跨天的事"的答案——这也是为什么它的判据里有一条（换一个执行者能否只靠状态继续）只能由人检查。

**通向下一步的桥。**

第 4 卷到此收口：系统能积累事实与做法、能推断人、能把失败变成可行动的结论、能在门控下改自己、能按节奏复盘，也能把一条长任务的状态维护下来。
