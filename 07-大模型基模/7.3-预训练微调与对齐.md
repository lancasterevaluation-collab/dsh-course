## 读完这一篇你会知道什么

1. **三件事各自改什么**：预训练给能力，微调改行为，对齐改偏好。
2. **SFT 的关键细节**：损失只算在回答上，prompt 部分要掩码掉。
3. **DPO 在优化什么**：隐式奖励 = $\beta (\log \pi - \log \pi_{\text{ref}})$，以及"策略等于参考时损失恰好是 $\log 2$"这条可验证的恒等式。
4. **LoRA 有多便宜**：d=4096、r=16 时只训 0.78% 的参数。
5. **什么时候不该微调**：可逆性、成本、以及"等模型变强"这个选项。
6. **一个真实的失败**：scaling law 的拟合方法选错，会得出偏差 72% 的结论。

## 一、为什么需要知道它

### 1.1 该不该微调：一个成本差三个数量级的问题

产品说"模型回答的语气不专业"。第一反应是微调。但按 7.2 的公式，训练单个 token 比推理贵 $3D$ 倍——微调是**训练**，而写一段提示是**推理**。在多数情况下，先试提示与检索，微调的收益往往比不上它的代价（不可逆、要维护数据、要重训）。

### 1.2 微调之后，别的能力退化了

在一个任务上微调后，该任务变好了，但另一类任务明显变差——这是**灾难性遗忘**。它不是 bug，而是微调的固有性质：参数被推向了新任务的分布。

### 1.3 用哪份数据做对齐，就直接决定模型偏什么

对齐数据里的偏好会被模型学走（这是设计意图），但**数据里没写出来的偏好也会被学走**（例如总是先复述问题再回答）。所以"对齐"这件事的产物不只是"更有用的模型"，还有"一批没被记录的隐性偏好"。

这三件事都属于同一个问题：**改变模型行为有几种手段，各自代价是什么。**

## 二、三件事分别在做什么

| 手段 | 它改变什么 | 数据形态 | 可逆性 | 相对成本 |
|---|---|---|---|---|
| **预训练** | 能力（会做什么） | 海量无标注文本 | 不可逆，也不该由你来做 | 极高 |
| **SFT（监督微调）** | 行为（怎么做） | 输入 + 期望输出 | 不可逆，但可回滚到旧权重 | 中 |
| **偏好对齐（RLHF / DPO）** | 偏好（哪种更好） | 成对的优劣样本 | 不可逆 | 中 |
| **提示 / 检索** | 当次行为 | 你写的文字 / 检索到的片段 | **完全可逆** | 极低 |

这张表的用法是自下而上：先试最下面那一行。只有当提示与检索都无法解决时，才考虑往上走——因为**往上走的每一步都失去可逆性**。

## 三、怎么做

### 3.1 SFT：损失只算在回答上

微调数据是"输入 + 期望输出"。关键细节是：**损失只应计算在期望输出上**，输入部分要掩码掉。否则模型会被训练去"预测用户的问题"，这不是你要的。

```python
def sft_loss(logits, targets, mask):
    """只在 mask 为真的位置计算交叉熵。"""
    per_token = F.cross_entropy(
        logits.reshape(-1, logits.size(-1)), targets.reshape(-1), reduction="none"
    )
    m = mask.reshape(-1)
    return (per_token * m).sum() / m.sum()
```

怎么验证掩码是对的（这是可以机械检查的）：改动输入部分的 logits，损失必须**完全不变**。算例实测：改 prompt 段的 logits，损失变化 **0.000e+00**。改回答段，损失确实改变。

为什么用"除以被掩码的个数"而不是"除以总长度"：后者会让损失随输入长度变化，同一个回答在不同的输入长度下损失不同，训练信号的强度就不一致了。

### 3.2 偏好对齐：DPO 与隐式奖励

对齐不用逐 token 标注，只需成对的"哪个更好"。DPO 把这件事写成可微的损失：

```python
def dpo_loss(policy_w, policy_l, ref_w, ref_l, beta=0.1):
    """胜出 / 落败的对数概率差，相对参考模型做修正。"""
    margin = beta * ((policy_w - ref_w) - (policy_l - ref_l))
    return -F.logsigmoid(margin).mean()
```

对应的**隐式奖励**是 $r(x,y) = \beta (\log \pi(y|x) - \log \pi_{\text{ref}}(y|x))$——它可以直接用来比较两个回答，不需要额外的奖励模型。

一条可验证的恒等式：当策略与参考完全相同时，margin 为 0，损失等于 $-\log \text{sigmoid}(0) = \log 2$。算例实测 **0.693147**，与 $\log 2$ 一致。**这类恒等式是最有价值的断言**——它不依赖具体数据，只依赖公式结构，所以在任何实现上都该成立。

其他被验证的性质：

- 偏好方向正确时损失小于 $\log 2$，反过来则大于（算例：$\beta=0.5$ 时为 0.474077）。
- $\beta$ 越大，同一个对数概率差带来的惩罚越强（损失越小）。

### 3.3 LoRA：只训极小一部分参数

不训练原权重，而是在每层旁边挂一对低秩矩阵 $A_{r \times d}$ 与 $B_{d \times r}$：

$$
\text{LoRA 参数} = 2rd, \qquad \text{占比} = \frac{2r}{d}
$$

算例实测：$d = 4096$、$r = 16$ 时是 131,072 个参数，而全量是 16,777,216——**占比 0.7812%**。32 层模型是 4.2M 可训练参数 vs 537M 全量。

**只占 0.78% 却常常够用**，这是 LoRA 的价值。它的工程含义更重要：**微调从"重训一个模型"变成"保存一个几十 MB 的补丁"**——可分发、可切换、可回滚。

### 3.4 决策表：什么时候用哪一种

| 你的问题 | 首选 | 理由 |
|---|---|---|
| 输出格式总是不对 | 提示 + 少样本示例 | 完全可逆，改动分钟级 |
| 模型不知道你们的内部文档 | 检索（RAG） | 内容会变，检索天然可更新 |
| 语气 / 风格不统一 | 提示，再考虑 SFT | 提示通常够，SFT 要维护数据 |
| 一个明确的固定任务总做不好 | SFT（优先 LoRA） | 有稳定输入输出对时它最有效 |
| 两个回答"都对但一个更好" | 偏好对齐 | 逐 token 标注不可行，成对判断可行 |
| 需要模型学会全新能力 | 等基模升级 | 微调改行为，不改能力上限 |

最后一行最容易被忽略：微调擅长"把已有能力引导到特定形式"，不擅长"从无到有造出新能力"。

## 四、特殊情况与处理技巧

| 情况 | 为什么 | 处理 |
|---|---|---|
| 微调后别的任务退化 | 灾难性遗忘是固有性质 | 用 LoRA、混入通用数据、只训部分层 |
| SFT 后模型开始"复述问题" | 训练数据里输入输出高度相关 | 检查损失是否掩码到了输入段 |
| 对齐后回答变长、变啰嗦 | 偏好数据偏长回答 | 在数据里显式加入"简洁"的偏好样本 |
| 模型附和用户（对齐税） | 偏好数据里"顺从"被判为更好 | 加入"坚持正确"的对照样本 |
| 数据量少却训很多轮 | 过拟合 | 早停 + 留出验证集，评估要留独立样本 |
| 评估显示变好了，线上没变 | 评估集与训练集重叠 | 评估集必须独立，且要防污染（见 7.6） |
| 微调后能力上限没提高 | 微调改行为不改能力 | 需要新能力时考虑等基模升级或换模型 |

一条通用技巧：**微调前先问"这件事能不能用提示解决"。** 提示失败的原因通常是"信息不够"或"格式说不清"，这两者分别对应检索和更好的示例，都不需要动权重。

## 五、理论：scaling law 与"等模型变强"

损失随规模下降的经验规律大致是：

$$
L(N) = a \cdot N^{-b} + c
$$

其中 $c$ 是**不可约损失**（规模再大也降不到它下面）。算例用 $a=3.0$、$b=0.35$、$c=1.2$ 生成数据验证了拟合方法，并给出一个真实的教训。

收益递减是这条规律的直接推论：算例实测从 $10^3$ 到 $10^4$ 损失降 0.1479，而从 $10^7$ 到 $10^8$ 只降 0.0059——**后者的规模是前者的一万倍，收益只有它的 4%**。

**算例里出现的一个真实失败**，值得单独记下来：

| 拟合方法 | 得到的指数 $b$ | 偏差 |
|---|---|---|
| 先扣掉一个估的常数，再对 log 做线性回归 | **0.0973** | **72.2%** |
| 同时对 $a$、$b$、$c$ 做非线性最小二乘 | 0.3475 | 3.1%（真值 0.35） |

两种方法用的是**同一份数据**，结论却差了一个"该不该继续投入"的量级。原因是第一个方法里常数项估偏了（把 $c$ 当成最小损失乘 0.9），剩下的曲线被这个错误的常数**压平**，斜率因此严重偏小。

这条教训的适用范围远超 scaling law：**当你要从数据里估计一个幂律（或任何带常数项的规律）时，"先扣一个估的常数再线性回归"是不可靠的。** 要么做三参数拟合，要么把实验点取到常数项可以忽略的区域——不要用估出来的常数去减。

由此得到"等模型变强"这个策略的判断依据：

1. **你的瓶颈是能力还是行为**？行为问题靠提示/微调解决，能力问题只能等基模。
2. **收益曲线的斜率还陡吗**？在算例里，规模到 $10^7$ 之后斜率已经很平——此时再投入训练算力换不来多少损失下降。
3. **你的能力能不能在升级时无缝迁移**？如果整套系统建立在"提示 + 工具 + 检索"上，换模型基本是换一个字符串。如果建立在微调权重上，每次升级都要重做数据与训练。

第三点最值钱：它意味着**把可迁移的部分留在提示与工具层，是应对模型快速迭代的核心策略**。

## 六、工程化

| 项 | 内容 |
|---|---|
| 数据版本化 | 微调数据集要版本化并能追溯，否则无法复现某次发布 |
| 权重可回滚 | 保留上一版权重与它的评估结果，让回滚成为一条命令 |
| 评估集独立 | 与训练数据严格分离，并定期检查污染（见 7.6） |
| 能力回归测试 | 除目标任务外，跑一组通用任务，监控灾难性遗忘 |
| 成本核算 | 训练成本按 $6ND$ 估，并把它与"用检索解决"的成本对比 |
| 补丁分发 | LoRA 补丁的加载、切换与版本兼容要有明确约定 |
| 可逆性记录 | 每种手段的可逆性写进决策记录（提示可逆、微调不可逆） |
