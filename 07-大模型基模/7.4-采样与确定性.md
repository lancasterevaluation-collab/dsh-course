## 读完这一篇你会知道什么

1. **输出为什么不确定**：模型给出的是概率分布，最终 token 是从分布里抽出来的。
2. **温度改什么**：把分布变尖（更确定）或变平（更多样），算例给出熵与 top-1 概率的完整对照表。
3. **top-p 改什么**：削掉概率尾巴，让候选集只覆盖指定的概率质量。
4. **怎么让结果可复现**：同种子同结果，异种子异结果——以及为什么"可复现"不等于"确定"。
5. **一条统计常识**：卡方检验超过 5% 临界值是正常事件，**单次检验不能当铁证**。
6. **工程上要补什么**：把采样参数变成可观测、可回放的记录。

## 一、为什么需要知道它

### 1.1 同一个评测跑了两次，分数不一样

你在评估集上跑了两遍，准确率一次 71%、一次 74%。差异是不是改动带来的？在没有多次运行之前，这个问题无法回答——**你不知道噪声有多大，就不知道差异算不算数**。

### 1.2 线上偶发错误无法复现

用户报了一个错，你按同样的输入重试十次都没复现。因为每次的采样路径不同。要复现，必须把当次的采样参数与种子一起记下来。

### 1.3 调不出想要的效果

把温度从 1.0 调到 1.5，输出更发散了，但错得也更多。温度到底该取多少，凭感觉调不动——需要知道它作用在分布的哪个量上。

这三件事都指向一件事：**输出是从分布里抽出来的随机变量**。可观测、可复现、可调参，都建立在这个认识上。

## 二、采样是什么

一次 token 的生成分三步：

1. 模型给出**全词表的原始分数**（logits）。
2. 用**温度**缩放后做 softmax，得到概率分布。
3. 用**过滤规则**（top-k / top-p）削掉尾巴，在剩下的候选里**按概率抽取**。

关键认识：**模型输出的不是 token，是分布**。采样是把这个分布变成一个 token 的那一步。

## 三、怎么做

### 3.1 温度：把分布变尖或变平

温度只做一次缩放，再交给 softmax。

```python
def apply_temperature(logits, temperature):
    """温度缩放：logits / T 再 softmax。T<1 更尖锐，T>1 更平坦。"""
    return F.softmax(logits / temperature, dim=-1)
```

算例实测（同一组 logits，5 个候选）：

| 温度 | 分布熵（nats） | top-1 概率 |
|---|---|---|
| 0.25 | 0.1099 | 0.9793 |
| 0.5 | 0.6086 | 0.8292 |
| 1.0 | **1.2065** | **0.5630** |
| 2.0 | 1.4915 | 0.3745 |
| 4.0 | 1.5786 | 0.2821 |

两条被断言验证的单调关系：**温度升高，熵单调增加，top-1 概率单调下降**。

两个极限也验证了：

- 温度趋近 0 时分布趋近 one-hot（top-1 概率到 1.0，误差 0.000e+00）——**这就是贪心解码**。
- 温度很高时趋近均匀分布（5 个候选各 0.2，熵等于 $\log 5$）。

注意最后一个极限的措辞：算例里温度取到 1000，top-1 概率是 0.2003，与 0.2 差 3e-4。**"趋近"不是"等于"**——温度再高也消不掉 logits 之间的原始差距，只能把它压小。这是设计容差时要如实对待的细节。

### 3.2 候选集过滤：top-k 与 top-p

top-k 保留分数最高的 k 个。top-p（核采样）按概率降序累加，保留**累计刚超过 p 的最小集合**：

```python
def top_p_filter(logits, p):
    """核采样：按概率降序累加，保留累计刚超过 p 的最小集合。"""
    probs = F.softmax(logits, dim=-1)
    ordered, indices = torch.sort(probs, descending=True)
    cumulative = torch.cumsum(ordered, dim=-1)
    keep = cumulative <= p
    keep[0] = True                      # 至少留一个
    remove = indices[int(keep.sum()):]
    return logits.masked_fill(torch.isin(torch.arange(logits.numel()), remove), float("-inf"))
```

算例用一组概率 $[0.6096, 0.2243, 0.0825, 0.05, 0.0335]$ 实测：

| top-p | 保留候选数 | 覆盖概率 |
|---|---|---|
| 0.5 | 1 | 1.0000 |
| 0.8 | 1 | 1.0000 |
| 0.95 | 3 | 1.0000 |
| 0.99 | 4 | 1.0000 |

top-p 与 top-k 的差别在于它是自适应的：分布越平，保留的候选越多。分布越尖，保留的越少。而 top-k 无论分布多尖都固定保留 k 个。

### 3.3 可复现性：怎么做到

同一份随机种子必然给出同一串输出：

```python
a = torch.multinomial(probs, 8, replacement=True, generator=torch.Generator().manual_seed(7))
b = torch.multinomial(probs, 8, replacement=True, generator=torch.Generator().manual_seed(7))
```

算例实测：种子 7 两次都得 `[0, 0, 2, 1, 3, 2, 0, 1]`。换成种子 8 得 `[2, 1, 0, 0, 1, 0, 1, 0]`。**同种子相同、异种子不同**，两条都被断言。

而**贪心解码与种子无关**——它直接取概率最大的 token，是确定性的。

要复现一次生成，需要同时固定四样东西：**模型版本、提示的逐字节内容、采样参数（温度 / top-p / 种子）、以及解码顺序**（批处理会改变数值）。

### 3.4 多样性怎么调

算例用 500 次采样统计了"出现过的不同 token 数"与"最高频 token 的占比"：

| 温度 | 最高频占比 |
|---|---|
| 0.5 | 0.662 |
| 1.0 | 0.462 |
| 2.0 | 0.340 |

温度越高，输出越均匀——**但这不代表"更好"**。对需要精确的任务（结构化输出、工具参数、代码），多样性是缺陷而不是优点。

## 四、特殊情况与处理技巧

| 情况 | 为什么 | 处理 |
|---|---|---|
| 需要模型输出严格 JSON | 低温下仍可能抽到非法 token | 温度降到 0 附近，并用 schema 校验兜底 |
| 工具调用的参数被采样破坏 | 参数是"精确值"不是"文本" | 参数生成用确定性解码，或事后校验 |
| 相同提示两次结果不同 | 采样路径不同 | 记录种子与参数，才能复现 |
| 批处理导致结果变化 | 批内数值顺序影响浮点结果 | 复现时固定批大小与顺序 |
| 评测分数波动 | 采样噪声 | 多次运行取分布，先估噪声（见 6.3） |
| 高温下"创造力"没提升 | 阈值与提示的限制更强 | 先确认是采样限制还是提示限制 |
| 换了模型版本，输出全变 | 分布本身变了 | 把模型版本纳入复现记录 |

一条通用技巧：**先区分"不确定性来自采样，还是来自提示"。** 把温度设成 0（贪心）后如果结果仍不稳定，那不稳的来源是模型版本、上下文长度或批处理顺序——**不要继续在采样参数上找原因**。

## 五、理论：单次结果不是判据

算例里有一组数字值得单独讲。用固定种子采样 10000 次，各 token 的观测频率是 0.5061 / 0.3043 / 0.1896，理论值是 0.5 / 0.3 / 0.2——**看起来非常吻合**（最大偏差 0.0104）。

但同一份数据的卡方统计量是 **6.769**，而自由度 2、显著性 0.05 的临界值是 **5.99**。按教科书判据，它"拒绝"了"采样无偏"的假设。

两个结论，第二个更重要：

1. **这不是 bug。** 0.05 显著性的含义就是"即使采样完全无偏，也有 5% 的概率超过临界值"。这个种子恰好落在尾部。
2. **单次检验不能当铁证。** 算例紧接着跑了 40 个不同种子：只有 **1 次**超过临界值（2.5%），与理论假阳性率 5% 相符。看分布，不看单次。

这条规则适用于所有概率性判据：

- 不要因为一次运行"看起来不对"就改动系统。
- 不要因为一次运行"看起来正常"就认为没有 bug。
- **先测噪声下限，再判断差异是否有意义**——这正是 6.3 的评测口径在采样层面的表现。

## 六、工程化

| 项 | 内容 |
|---|---|
| 采样参数记录 | 温度、top-p、种子、最大长度，逐次调用写入日志 |
| 模型版本记录 | 版本变了就是另一个分布，必须与结果一起归档 |
| 复现开关 | 提供"确定性模式"（贪心 + 固定批），便于排查 |
| 参数按任务分层 | 结构化输出用低温、创意任务用高温，配置化而不是硬编码 |
| 多运行统计 | 评测一次跑 N 次，记录均值与区间而不是单点 |
| 噪声监控 | 定期用同版本同参数跑两次，估计当次噪声下限 |
| 回放能力 | 能按记录重放一次历史调用，用于定位偶发错误 |
