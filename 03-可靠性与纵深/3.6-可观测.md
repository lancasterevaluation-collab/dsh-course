## 本篇新词

- 度量（metric） 指一个可从运行中采集、可被比较的数值。它的价值在于可比较，因此口径必须固定。
- 口径（definition of measurement） 指一个指标"算的是什么"的完整说明：包含哪些项、排除哪些项、在哪个位置采集。
- 缓存命中（cache hit） 指本次请求的前缀与上次完全相同，因此这部分可以复用已计算的结果。条件是逐字节相同，不是"意思相近"。
- 延迟分解（latency breakdown） 指把总耗时拆成排队、预填充、逐 token 生成、工具执行四段。
- 分位数（quantile） 指分布上的位置值。均值衡量"平均多快"，分位数衡量"最慢的那部分多慢"。
- 归因（attribution） 指把总量按来源拆分。它回答"这一部分是谁造成的"，而不是"总共多少"。
- 度量腐化（metric corruption） 指一个指标一旦成为优化目标，它作为度量的有效性下降。被优化的是数字，不是数字代表的东西。
- 护栏（guardrail） 指给指标配的边界值：越界即报警或拒绝执行。指标本身不产生行动，护栏才产生行动。

## 一、【设计原因】

### 1.1 缺陷一：一轮跑了多少 token、花了多少钱，答不出来

请求发出去了，回复也拿到了，但没人能说清这一轮消耗了多少。

原因通常不是"没记录"，而是记录的位置不对：只记了响应里的总量，没记分档（输入、输出、缓存写入、缓存读取），也没记这一轮包含几次模型调用。

只记总量的后果是无法优化：看到"这一轮很贵"，但不知道贵在输入还是输出、在第一次调用还是第十次。

### 1.2 缺陷二：一次调用花了八秒，而优化方向完全不明

八秒可能由四段构成：排队等待、预填充、逐 token 生成、工具执行。四段的优化手段完全不同——排队要改并发策略，预填充要缩短输入，生成要减少输出或换模型，工具要改实现。

没有分解就没有优化方向，只能猜。

### 1.3 缺陷三：命中率无从得知，而它的量级影响成本

缓存命中的定价常与未命中相差一个数量级。若前缀每次都因一个小变化而失效（例如提示里嵌入了当前时间），命中率接近 0，成本会成倍上升——而这件事在只记总量时看不出来。

### 1.4 缺陷四：口径不清，同一个指标有两个值

同一个"平均延迟"，前端按用户感知的往返时间算，后端按服务处理时间算。两个值都"对"，但放在一张表里就互相矛盾。

口径不一致比没有指标更糟：它让讨论无法收敛，因为双方都在用正确的数字说不同的事。

### 1.5 由此确定的设计目标

1. 分档计数：输入、输出、缓存写入、缓存读取分开记。
2. 成本可复算：从分档计数与价格表算出，不直接存金额。
3. 延迟分四段：排队、预填充、生成、工具。
4. 口径单一来源：每个指标只有一个定义，且定义写在代码里。

**本节要点**

- 只记总量的后果是无法优化。
- 延迟不分段就没有优化方向。
- 缓存命中的量级影响常被低估。
- 口径不一致比没有指标更糟。
- 四条目标：分档、可复算、分四段、单一来源。

## 二、【直觉】

### 2.1 出租车计价

出租车按里程与时长两个维度计价，且分段单价不同（起步、夜间、长途）。你看到的是总价，但总价是算出来的，不是记下来的。

这个区别很重要：记总价的话，计价规则一改，历史数据的含义就变了。记里程与时长的话，任何时候都能用当时的规则重算，也能用新规则对照。

token 成本同理：记分档计数与价格表版本，而不是记一个金额。

### 2.2 流水线的节拍

一条流水线有四段：等料、上料、加工、下料。总节拍是四段之和。

只看总节拍，你会知道"慢"，但不知道改哪一段。而四段的改进手段各不相同：等料要改排产，上料要改夹具，加工要换刀具，下料要改传送带。把总节拍拆开，才知道该动谁。

::: keypoint 反直觉点
**"平均延迟 800 毫秒"这个数字几乎不包含可行动的信息。** 只有当它被拆成四段、并给出每段的分位数时，才可能指向一个具体改动。一个不能指向改动的指标，无论多精确都没有价值。
:::

### 2.3 一个数字直觉

设缓存命中价为未命中输入价的 0.1 倍、写入价为 1.25 倍。

- 若一份 2 万 token 的前缀在 10 次调用中被完整复用：第 1 次写缓存（2 万 × 1.25），其后 9 次读缓存（每次 2 万 × 0.1）。前缀部分的有效输入价是原来的约 $\frac{1.25 + 9 \times 0.1}{10} = 0.215$ 倍。
- 若前缀每次都变（例如嵌入了时间戳）：10 次都是未命中，前缀部分是原来的 1 倍。

同一份内容，成本差约 4.6 倍，而它在总价里的占比取决于前缀长度。这个量级差就是"命中率必须被测量"的理由。

**本节要点**

- 成本是算出来的而不是记下来的，因此要存分档计数与价格表版本。
- 延迟要拆成四段才知道改哪一段。
- 不能指向改动的指标无论多精确都没有价值。
- 命中与未命中的量级差可到数倍，前缀越长影响越大。

## 三、【严格】

### 3.1 定义

::: theorem 定义 3.6.1（分档用量）
一次模型调用的用量是四元组

$$
U = (u_{\text{in}},\ u_{\text{out}},\ u_{\text{write}},\ u_{\text{read}}) \in \mathbb{N}^4,
$$

分别表示未命中输入、输出、缓存写入、缓存读取的 token 数。它由平台返回的用量字段采集，不由本地估算。

**一轮**的用量是一轮内全部调用用量的按分量求和。
:::

::: theorem 定义 3.6.2（成本函数）
给定价格表 $P = (p_{\text{in}}, p_{\text{out}}, p_{\text{write}}, p_{\text{read}})$（单位：每千 token 的单价）与价格表版本 $v$，一次调用的成本为

$$
\mathrm{cost}(U, P) = \frac{1}{1000}\left(u_{\text{in}} p_{\text{in}} + u_{\text{out}} p_{\text{out}} + u_{\text{write}} p_{\text{write}} + u_{\text{read}} p_{\text{read}}\right).
$$

**成本是算出来的**：存储保留的是 $(U, v)$，而不是 $\mathrm{cost}$ 的数值。
:::

::: theorem 定义 3.6.3（延迟分解）
一次调用的总耗时分解为四段：

$$
T = T_{\text{queue}} + T_{\text{prefill}} + T_{\text{decode}} + T_{\text{tool}}
+ \epsilon,
$$

其中 $T_{\text{tool}}$ 是**工具执行的净耗时**，$\epsilon$ 是未归入四段的残余。

**四段并不连续覆盖整段墙钟时间**：墙钟的工具段包含模型与工具之间的调度、网络往返与重试，而 $T_{\text{tool}}$ 只取工具自身的执行时间。两者的差额落在 $\epsilon$ 里。因此残余不为零是常态，**它偏大才意味着分解漏了一段**。
:::

::: theorem 定义 3.6.4（缓存命中）
设本次请求的消息序列前缀为 $\pi$，缓存中已存的最长前缀为 $\pi'$。**命中长度为**

$$
\ell = \max\{k : \pi[1..k] = \pi'[1..k]\} .
$$

命中要求**逐字节相同**。任何位置的一个字符差异都会把命中长度截断到该位置之前。
:::

::: theorem 定义 3.6.5（分位数）
给定样本 $x_1, \dots, x_n$ 与 $q \in (0,1)$，**第 $q$ 分位数** $\mathrm{Q}(q)$ 是使至少有 $qn$ 个样本不超过它的最小值。

均值 $\bar x$ 与 $\mathrm{Q}(0.95)$ 是分布的两个不同特征：前者对长尾不敏感，后者专门反映长尾。
:::

::: theorem 定义 3.6.6（归因与护栏）
**归因**把总量按来源拆成各项：$T_{\text{total}} = \sum_i T_i$，其中 $i$ 遍历来源（例如按工具、按会话、按阶段）。

**护栏**是指标上的一个谓词 $\mathrm{ok}(m) \in \{\text{true}, \text{false}\}$。指标本身不产生行动。行动由护栏触发。
:::

### 3.2 命题

::: theorem 命题 3.6.1（成本的线性可加性）
成本函数对用量是线性的：$\mathrm{cost}(U_1 + U_2, P) = \mathrm{cost}(U_1, P) + \mathrm{cost}(U_2, P)$。

**证明.** $\mathrm{cost}(\cdot, P)$ 是四个分量的加权和，而加权和是线性映射。对线性映射有 $f(x + y) = f(x) + f(y)$。

↓ **为什么能这么写？** 每个分量的贡献只与它自己的数量有关，不同分量之间不相乘。

$\blacksquare$

::: keypoint 可加性的用处与前提
**可加性使"按会话、按工具、按阶段求和"成为合法操作**——因为总量等于各部分之和。

前提是价格表相同。若两次调用用了不同版本的价格表，求和前必须**分别按各次的价格表算**，不能先合用量再套一个价格。
:::
:::

::: theorem 命题 3.6.2（一个字符的改动使其后全部前缀失效）
设两次请求的前缀在第 $j$ 个字符处首次不同，且缓存按最长公共前缀判定，则命中长度为 $j - 1$，与第 $j$ 个字符之后的内容是否相同无关。

**证明.** 由定义 3.6.5，$\ell = \max\{k : \pi[1..k] = \pi'[1..k]\}$。对 $k \ge j$，$\pi[1..k] \ne \pi'[1..k]$（因为第 $j$ 位已不同）。对 $k \le j-1$，两前缀相同。故 $\ell = j - 1$。

↓ **为什么能这么写？** 最长公共前缀的定义直接给出这个结果，与后续内容无关。

$\blacksquare$

**数值**：若提示模板的第 500 个字符处嵌入了当前时间戳（前缀总长 2 万字符），命中长度被截断到 499，**其余 19,501 个字符全部按未命中计价**。

::: keypoint 把易变内容放到最后
**提示的组装顺序因此是一个设计问题**：稳定部分（系统提示、工具定义、长期记忆）放前面，易变部分（当前时间、本轮输入）放后面。这样版本变化只影响尾部，前缀仍然命中。

**反过来也有一条**：会话内的历史消息本身是追加的，因此"同一会话连续两轮"通常能命中。而"跨会话"是否命中取决于前缀是否一致。
:::
:::

::: theorem 命题 3.6.3（均值不能替代分位数）
存在两个延迟分布，其均值相同而第 95 分位数任意不同。

**证明.** 构造：分布 A 为 $n$ 个值全部取 $100$。分布 B 为 $n-1$ 个取 $0$、1 个取 $100n$。两者均值均为 $100$（B 的均值为 $100n/n = 100$）。而 $\mathrm{Q}_{0.95}(A) = 100$，$\mathrm{Q}_{0.95}(B) = 100n$，$n$ 可任意大。

↓ **为什么能这么写？** 只需给出一个参数化的构造即可证明两者不互相决定。

$\blacksquare$

::: keypoint 所以两个都要报
**均值用于看趋势，分位数用于看体验。** 只看均值会漏掉"1% 的请求慢 100 倍"这类问题，而这类问题恰好是用户抱怨的来源。
:::
:::

::: theorem 命题 3.6.4（口径不一致使比较失效）
若两个数字来自不同口径，则二者之差不能解释为"性能差异"。

**证明.** 设 $m_1 = f_1(\text{run})$、$m_2 = f_2(\text{run})$ 且 $f_1 \ne f_2$。差值 $m_1 - m_2 = f_1 - f_2$ 中包含函数差异项。该项与被测系统无关，因此差值不能被解释为系统性能的差异。

↓ **为什么能这么写？** 差值的构成里同时含有口径差异与真实差异，而两者无法从单个数字中分离。

$\blacksquare$

::: keypoint 口径要写在代码里
**口径写在文档里会被慢慢违反**，写在代码里才能被测试固定。做法是：指标只由一个函数计算，其他位置不得重复实现同一指标。
:::

::: theorem 命题 3.6.5（度量腐化）
若某个指标成为优化目标，则在优化过程中该指标上升而它代表的目标量不一定上升。

**证明.** 优化作用于指标的可测量部分。若指标与目标量之间存在未被指标覆盖的部分（指标是目标量的非充分代理），则优化可以只提升被覆盖的部分。此时指标上升而目标量不变。

↓ **为什么能这么写？** 只要求指标不是目标量的充分统计量，反例即可构造。

$\blacksquare$

**工程含义**：**给每个指标配一个护栏指标**。例如以"token 效率"为优化目标时，同时监控"任务成功率"。前者上升而后者下降即为腐化的信号。
:::

::: theorem 命题 3.6.6（未归因部分必须显式报告）
若分解式 $T = \sum_i T_i$ 中的残余 $\epsilon$ 不报告，则各项之和与总量的差值不可解释。

**证明.** 分解式按定义成立，其中 $\epsilon = T - \sum_i T_i$。若不报告 $\epsilon$，阅读者只能假定 $\epsilon = 0$。当 $\epsilon \ne 0$ 时该假定为假，各项之和与总量不符，而阅读者没有可解释差异的信息。

↓ **为什么能这么写？** 残余的存在由等式本身保证。报告它是使等式可被解读的条件。

$\blacksquare$

::: keypoint 残余不为零是信号而不是噪声
$\epsilon$ 偏大通常意味着**分解漏了一段**（例如模型下载权重的时间、网络重传的时间）。把它报出来，才能发现遗漏的那一段。
:::

### 3.3 本节要点

**本节要点**

- 用量分四档，由平台返回而不是本地估算（定义 3.6.1）。
- 成本是算出来的，存储保留用量与价格表版本（定义 3.6.2）。
- 延迟分解用四个计时点，残余必须显式报告（定义 3.6.3、命题 3.6.6）。
- 命中要求逐字节相同，一个字符的改动使其后前缀全部失效（命题 3.6.2）。
- 成本对用量线性可加，但前提是价格表相同（命题 3.6.1）。
- 均值不能替代分位数（命题 3.6.3）。
- 口径不一致使比较失效（命题 3.6.4）。
- 指标成为优化目标后会腐化，必须配护栏（命题 3.6.5）。

## 四、【回到直觉】

- **定义 3.6.2 说的**：存用量和价格表版本，不存金额。金额随时能算，而算错的口径改不回来。
- **定义 3.6.4 说的**：把稳定内容放提示前面，易变内容放后面。**时间戳要放在最后。**
- **命题 3.6.1 说的**：同一价格表下，各部分成本可以直接相加。换过价格表就要分段算。
- **命题 3.6.2 说的**：改提示模板时注意，**你在第 500 个字符处改一个字，后面两万个字符的缓存全废**。
- **命题 3.6.3 说的**：报均值也要报 P95。用户的抱怨来自长尾，而均值对长尾不敏感。
- **命题 3.6.4 说的**：一个指标只由一个函数算，口径写在代码里。
- **命题 3.6.5 说的**：优化某个指标时，给它配一个反向的护栏指标。
- **命题 3.6.6 说的**：分项之和对不上总量时，差额要单独报出来——它通常意味着漏了一段。

**本节要点**

- 存用量与价格表版本，不存金额。
- 稳定内容放前缀，时间戳放最后。
- 同价格表可直接相加，换表要分段。
- 改前缀中段会废掉其后全部缓存。
- 均值与 P95 都报。
- 指标只由一个函数算。
- 优化指标要配护栏。
- 残余必须显式报告。

## 五、【工具箱】

### 5.1 分位数的算法

小样本直接排序取位置，代价 $O(n \log n)$。流式场景用近似算法（如 t-digest），代价 $O(n)$ 且内存有界。

**报分位数要同时报样本量**：$n = 10$ 时的 P95 只是第 9 個值，它与 $n = 10000$ 时的 P95 不是一回事。

### 5.2 归因分解

总量按维度求和：维度可以是工具、会话、阶段、模型。**维度之间必须互斥且完备**，否则会出现重复计数或遗漏。

检验方法：把各维度之和与总量比对，差额即 $\epsilon$。

### 5.3 命中判定

按定义 3.6.4，命中长度是最长公共前缀的长度。它的计算代价是 $O(\ell)$，$\ell$ 为命中长度。

**实现要点**：比较的单位是 token 而不是字符，因为缓存按 token 索引。因此"第 500 个字符"在实践中是"第若干个 token"，位置由分词器决定。

### 5.4 腐化检测

对每个指标配一个护栏指标，并检验两者的相关性符号。若主指标持续上升而护栏指标同时下降，即腐化信号。

**可行的做法**：把两者画在同一张图上，并记录它们的历史相关系数。相关系数由正转负是一个需要解释的事件。

### 5.5 成本的可复算性

给定 $(U, v)$ 与价格表 $P_v$，成本可复算。检验方法是：取一批历史记录，用当时的价格表重算，应当与当时报告的金额一致（允许浮点误差）。

**这条检验能发现"价格表更新后历史金额被重算"这类错误**——那会让历史趋势失去可比性。

**本节要点**

- 分位数要连样本量一起报。
- 归因维度必须互斥且完备，用差额检验。
- 命中按 token 索引，不是按字符。
- 腐化检测看主指标与护栏指标的相关性符号。
- 成本可复算性用历史记录回算检验。

## 七、施工图与算例

### 7.1 三段结构

| 段 | 职责 | 关键约束 |
|---|---|---|
| 采集段 | 记录用量、四个计时点、命中信息 | 用平台返回值，不本地估算 |
| 聚合段 | 按维度求和与算分位数 | 维度互斥且完备 |
| 呈现段 | 报指标并触发护栏 | 每个指标配护栏 |

### 7.2 采集段：四个计时点

采集段要拿到四个时刻，才能分解延迟。**只记开始与结束是分解不出来的。**

```js
// 延迟分解：四段之和加残余，残余必须显式报告（定义 3.6.3 / 命题 3.6.6）
export function latencyParts(marks) {
  const { enqueuedAt, startedAt, firstTokenAt, lastTokenAt, toolDoneAt } = marks
  const parts = {
    queue: startedAt - enqueuedAt,
    prefill: firstTokenAt - startedAt,
    decode: lastTokenAt - firstTokenAt,
    tool: toolDoneAt - lastTokenAt,
  }
  const total = toolDoneAt - enqueuedAt
  const summed = parts.queue + parts.prefill + parts.decode + parts.tool
  return { ...parts, residual: total - summed, total }
}
```

### 7.3 聚合段：分档求和与分位数

分档用量按分量相加（命题 3.6.1 的可加性），成本在需要时算。

```js
// 分档成本：从用量与价格表算出，不存金额（定义 3.6.2）
export function cost(usage, prices) {
  return (
    usage.input * prices.input +
    usage.output * prices.output +
    usage.cacheWrite * prices.cacheWrite +
    usage.cacheRead * prices.cacheRead
  ) / 1000
}

// 分位数：小样本排序取位置，报告时要连样本量一起给（工具箱 5.1）
export function quantile(values, q) {
  if (values.length === 0) return null
  const sorted = [...values].sort((a, b) => a - b)
  const idx = Math.min(sorted.length - 1, Math.ceil(q * sorted.length) - 1)
  return { value: sorted[Math.max(0, idx)], n: sorted.length, q }
}
```

### 7.4 呈现段：护栏

指标本身不产生行动，护栏才产生行动（定义 3.6.6）。

```js
// 护栏：每个指标配一个边界，越界即触发行动（定义 3.6.6）
export function guardrails(metrics, limits) {
  const breached = []
  for (const [name, limit] of Object.entries(limits)) {
    const v = metrics[name]
    if (typeof v === 'number' && v > limit) breached.push({ name, value: v, limit })
  }
  return breached
}
```

### 7.5 命中判定

按定义 3.6.4，命中长度是最长公共前缀的长度。

```js
// 命中长度：最长公共前缀（定义 3.6.4 / 命题 3.6.2）
export function hitLength(prev, cur) {
  if (!prev || !cur) return 0
  let i = 0
  while (i < prev.length && i < cur.length && prev[i] === cur[i]) i++
  return i
}

// 首个不同位置：改动点之后的前缀全部失效
export function firstDifference(prev, cur) {
  return hitLength(prev, cur)
}
```

### 9.2 失败模式

**（1）检查放在装载期（L9 位置放错）。** 价格表在进程启动时加载一次，之后平台调价仍用旧值。表现是"账单与自算对不上"。修正：按调用时的价格表版本算，并把版本记进用量记录。

**（2）前提会变（L9）。** 命题 3.6.2 的命中判定以"缓存按最长公共前缀匹配"为前提。平台若改变了缓存粒度或最小可缓存长度，同一提示的命中长度会变。修正：把判定逻辑与平台语义绑定，并在平台更新时重测。

**（3）只记总量。** 看到成本高但不知道贵在哪一档。

**（4）存金额而不是存用量。** 价格表一变，历史金额与其他时期不可比。

**（5）延迟只有两个计时点。** 分解不出来，优化只能猜。

**（6）残余不报。** 分项和对不上总量，且不知道漏了什么。

**（7）提示里嵌时间戳。** 命中率归零，成本成倍上升。

**（8）只报均值。** 长尾问题被average掉，而用户抱怨正来自长尾。

**（9）同一指标两处实现。** 口径漂移，两个值互相矛盾。

**（10）优化主指标而不设护栏。** 主指标上升而真实效果下降（度量腐化）。

**本节要点**

- 决策表覆盖 11 种情形。
- 失败模式十条，前两条是位置放错与前提会变。
- 最容易被忽略的是"残余不报"，它掩盖了分解的遗漏。

## 十、仍未解决

- **跨平台用量口径的统一。** 不同平台的用量字段划分不一致（有的把缓存写入并入输入），跨平台比较需要归一化。
- **分位数的流式估计精度。** 近似算法在极端分位数上的误差缺少通用界。
- **归因的责任划分。** 一轮内多个工具与多次调用交错时，某项延迟归给谁取决于划分方式，而划分带有主观性。
- **腐化的早期检测。** 相关性符号的转变需要足够样本，而等到样本足够时损失已经发生。
- **成本的预测。** 事前估算一轮成本需要预测用量，而用量与任务内容强相关。
- **缓存命中的跨会话保持。** 平台侧的缓存保留时长不可控，因此命中率会随外部策略变化。

**本节要点**

- 跨平台用量口径不一致。
- 流式分位数缺少误差界。
- 归因的责任划分带主观性。
- 腐化检测需要样本，而损失先发生。
- 成本预测依赖用量预测。
- 缓存保留时长不可控。
