## 本篇新词

- 状态三分类 指把状态分为权威（不可重建）、派生（可从权威重建）、临时（可丢弃）。判据是"能不能重建"。
- 真相源（source of truth） 指某份状态被当作权威副本的那一处。同一份状态只能有一个真相源。
- 可逆性四级 指按"撤销需要动什么"划分：无需动（内存）、动一份数据、动多份数据、动外部世界。
- 原子性（atomicity） 指一组改动要么全部生效要么全部不生效。它把"中断后状态未知"变成"中断后状态可判定"。
- 先写日志（write-ahead log） 指在改动正式数据之前先把意图写下来。它使中断后的恢复可以依据日志判断。
- 有界状态（bounded state） 指容量有限的状态容器。写满时的策略必须显式选择：失败、丢弃最旧、还是外置。
- 快照（snapshot） 指某一时刻状态的独立副本。它有浅有深，深复制保证副本不被后续改动影响。
- 幂等重放（idempotent replay） 指恢复时重复应用同一操作不改变结果。它要求操作是赋值型的（与 3.5 同源）。

## 一、【设计原因】

### 1.1 缺陷一：重启之后，系统表现得像丢了最近几分钟的记忆

系统把最近的状态只放在内存里，重启后它消失了。对使用者而言，这表现为"系统忘了几分钟前做过什么"。

根源是状态分类没做：哪些是可以重建的派生状态、哪些是不可重建的权威状态，在设计时没有区分。

### 1.2 缺陷二：准备回滚时才发现，数据已经被改过了

改动之前没有留副本，于是回滚时无路可退。或者留了副本，但副本是浅复制，被后续改动同时改掉了。

这两种情况都属于可逆性判断错误：把"能撤销"当成了默认，而没有逐项检查"撤销需要动什么"。

### 1.3 缺陷三：有界容器静默丢弃，使用者永远不知道自己失去了什么

一个有容量上限的容器写满之后，新数据覆盖旧数据，而没有任何信号。

静默丢弃的问题不是丢了数据，而是丢失这件事不可观测。 使用者无法区分"本来就没这条"与"它被挤掉了"。

### 1.4 缺陷四：迁移中断，数据既不是旧格式也不是新格式

把一份数据从旧格式改成新格式，中途崩溃。此时数据处于半新半旧的状态，两种格式的读取代码都无法处理。

根源是迁移不具备原子性，且迁移前没有留下可回退的副本。

### 1.5 由此确定的设计目标

1. 状态先分类：按"能否重建"分成权威、派生、临时。
2. 可逆性逐项判断：不假设，逐项问"撤销需要动什么"。
3. 有界策略显式：写满时失败、丢弃还是外置，必须写下来并让使用者可观测。
4. 迁移要原子且可回退：先复制、再原子切换、保留回退路径。

**本节要点**

- 重启丢记忆的根源是状态分类没做。
- 回滚失败常因为没留副本或只留了浅副本。
- 静默丢弃的问题在于丢失不可观测。
- 迁移中断会留下两种格式都无法读取的状态。
- 四条目标：先分类、逐项判断、显式策略、原子迁移。

## 二、【直觉】

### 2.1 草稿纸、账本与副本

一个会计的工作台上有三样东西：草稿纸（随时可扔）、账本（唯一权威）、报表（从账本算出来）。

- 扔掉草稿纸没有损失——这就是临时状态。
- 账本丢了就完了，它不可重建——这就是权威状态。
- 报表丢了可以重算——这就是派生状态。

三者的设计处置完全不同：临时状态不需要持久化，权威状态必须持久化且要能恢复，派生状态可以持久化（为了性能）但必须能重建。

### 2.2 副本的深浅

复印一份文件，得到的是独立副本。而如果你给的是文件夹的快捷方式，那么原件被改之后"副本"也变了。

这就是浅复制与深复制的区别。回滚用的是副本，所以副本必须是深的——否则"我留了备份"这句话是假的。

::: keypoint 反直觉点
**浅复制在回滚场景下比没有副本更危险。** 没有副本时你会谨慎。有浅副本时你以为自己安全，于是在改动前不再检查，而实际上副本与原文一起被改了。
:::

### 2.3 一个数字直觉

设有界容器容量 1000 条，写入速率 5 条/秒，淘汰策略是"丢弃最旧"。那么容器覆盖的时间窗是 200 秒。

这意味着任何超过 200 秒前的写入都无法查到。 若某个诊断流程需要查 10 分钟前的记录，它必然失败——而失败的表现是"查不到"，不是"被淘汰了"。

结论是：有界容器的容量必须与"最长的查询回溯需求"对齐，否则它会在需要时静默地不给数据。

**本节要点**

- 三类状态对应草稿纸、账本、报表。
- 回滚用副本，因此副本必须是深复制。
- 浅复制比没有副本更危险。
- 有界容器的容量要与查询回溯需求对齐。

## 三、【严格】

### 3.1 定义

::: theorem 定义 1.5.1（状态三分类）
系统状态按**可重建性**分为三类：

$$
\mathrm{kind}(s) = \begin{cases}
\text{权威}, & s \text{ 不能从其他状态重建},\\
\text{派生}, & s = f(s_1, \dots, s_k),\ s_i \text{ 是权威或派生},\\
\text{临时}, & s \text{ 的生命周期不超过一次操作}.
\end{cases}
$$

**判据**：能否写出一段程序从其他状态算出 $s$。能，则是派生。不能，则是权威。
:::

::: theorem 定义 1.5.2（真相源）
状态 $s$ 的**真相源**是承载它的权威副本的位置。**唯一性要求**：对任意 $s$，至多存在一个位置被指定为它的真相源。

存在两个真相源时，称该状态处于**双写**状态。
:::

::: theorem 定义 1.5.3（可逆性四级）
操作 $a$ 的**可逆性等级**由撤销它需要改动的对象决定：

$$
\mathrm{rev}(a) = \begin{cases}
\text{L0 内存}, & \text{撤销只需丢弃内存中的值},\\
\text{L1 单份数据}, & \text{撤销需要改写一份本地数据},\\
\text{L2 多份数据}, & \text{撤销需要协调多处数据或跨机器},\\
\text{L3 外部}, & \text{撤销需要影响外部世界（已发送的请求、已公开的数据）}.
\end{cases}
$$
:::

::: theorem 定义 1.5.4（原子性）
一组改动 $\{a_1, \dots, a_k\}$ 是**原子的**，当且仅当对任意的中断点，最终状态要么是所有 $a_i$ 都未生效，要么是全部生效。

**中断后状态可判定**：存在一个有限程序判定这组改动是否生效。
:::

::: theorem 定义 1.5.5（先写日志）
**先写日志**指在应用改动之前先把意图记录到日志。恢复时读日志判断哪些改动已应用。

$$
\text{应用顺序} = \mathrm{log}(a) \ \prec\ \mathrm{apply}(a).
$$
:::

::: theorem 定义 1.5.6（有界策略）
容量为 $C$ 的状态容器在写满时的**策略**是三种之一：

$$
\mathrm{policy} \in \{\text{失败}, \text{丢弃最旧}, \text{外置}\}.
$$

策略必须显式声明，且**丢弃与外置两种都必须让"发生了丢弃"可观测**。
:::

### 3.2 命题

::: theorem 命题 1.5.1（派生状态不可作为真相源）
若 $s$ 是派生状态而它被指定为真相源，则存在一个更新顺序使 $s$ 与其来源不一致。

**证明.** 设 $s = f(s_0)$。因 $s$ 被当作真相源，其他组件读取 $s$ 而不读 $s_0$。取一次改动 $s_0 \to s_0'$，若该改动之后 $s$ 尚未重算（任何非原子实现都存在这样一个时刻），则读取者看到的是基于 $s_0$ 的旧值，与当前 $s_0'$ 不一致。

↓ **为什么能这么写？** 只要重算与来源更新之间存在时间差，就存在不一致窗口。

$\blacksquare$

::: keypoint 实际中的表现
**"缓存被当成真相源"是最常见的形态**：一个加速用的副本逐渐变成了唯一被读的地方，而原始数据不再被维护。此时两者不一致的修法不是同步，而是**把真相源改回原始数据**。
:::

::: theorem 命题 1.5.2（浅副本不提供回滚能力）
若副本 $s'$ 与原件 $s$ 共享可变子结构，则对 $s$ 的改动会同时改变 $s'$，副本无法用于回滚。

**证明.** 共享子结构意味着 $s$ 与 $s'$ 指向同一份可变数据。对 $s$ 的改动通过共享结构反映到 $s'$。故 $s'$ 不保留改动前的值，无法用于恢复。

↓ **为什么能这么写？** 副本的价值在于保留旧值，而共享可变结构使旧值被覆盖。

$\blacksquare$

::: keypoint 深复制的替代
**深复制的成本可以避免：改用不可变结构与写时复制。** 不可变结构使"改动"实际产生新对象，旧对象自然保留。写时复制则在真正写入时才复制。两者都比"每次改动前做一次深复制"便宜。
:::

::: theorem 命题 1.5.3（可逆性等级决定验证强度）
按 1.1 命题 1.1.5，可容忍的缺陷率与回滚代价成反比。而回滚代价随可逆性等级单调增（L0 < L1 < L2 < L3），故

$$
\text{L0} \prec \text{L1} \prec \text{L2} \prec \text{L3} \quad \text{⟹} \quad p_0 \ge p_1 \ge p_2 \ge p_3 ,
$$

其中 $p_i$ 是等级 $i$ 的可容忍缺陷率。**L3 的验证强度需求最高**。

**证明.** 由 1.1 命题 1.1.5，$p \le L/c(a)$。等级越高 $c(a)$ 越大，故 $p$ 的上界越小。四个等级的成本递增，故上界递减。

↓ **为什么能这么写？** 可容忍缺陷率与回滚代价成反比，而代价随等级递增。

$\blacksquare$
:::

::: theorem 命题 1.5.4（有界容器的覆盖窗口）
容量 $C$、写入速率 $r$ 的"丢弃最旧"容器，其**覆盖窗口**为

$$
T_{\text{cover}} = \frac{C}{r} .
$$

任何回溯时间超过 $T_{\text{cover}}$ 的查询必然找不到目标记录。

**证明.** 容器在 $T_{\text{cover}}$ 内被写满一次，此后每次写入淘汰一条最旧记录。因此任意时刻容器中最早的记录年龄不超过 $T_{\text{cover}}$，更早的记录已被淘汰。

↓ **为什么能这么写？** 稳态下容器容纳的记录数固定为 $C$，而单位时间产生 $r$ 条。

$\blacksquare$

**数值**：$C = 1000$、$r = 5$ 条/秒时 $T_{\text{cover}} = 200$ 秒。**需要回溯 10 分钟的查询必然失败**，而失败表现为"查不到"。
:::

::: theorem 命题 1.5.5（静默丢弃使丢失不可观测）
若丢弃策略不产生任何可观测信号，则使用者无法区分"从未有过该数据"与"该数据被淘汰"。

**证明.** 使用者的观测来源只有容器的内容。未被淘汰时不存在该数据，被淘汰后也不存在该数据——两种情形的观测相同。故不可区分。

↓ **为什么能这么写？** 区分需要观测上的差异，而静默丢弃不产生差异。

$\blacksquare$

::: keypoint 所以要有淘汰计数
**加一个累计淘汰计数即可区分**：计数不变说明从未有过，计数增长说明发生过淘汰。这个计数本身应当是容器对外的公开属性。
:::

::: theorem 命题 1.5.6（先写日志使中断可判定）
若应用顺序满足"先写日志、后应用"，则中断后可通过日志判定改动是否已生效。

**证明.** 恢复时读日志：日志中存在 $a$ 的记录即表示 $a$ 已进入应用阶段。若应用是幂等的（与 3.5 命题 3.5.3 同源），则重复应用不改变结果，恢复可以安全地重做。若日志中无记录，则 $a$ 未开始。

↓ **为什么能这么写？** 日志给出了一个可查询的"意图记录"，而它是判定的依据。

$\blacksquare$
:::

### 3.3 本节要点

**本节要点**

- 状态按可重建性分权威、派生、临时（定义 1.5.1）。
- 派生状态不可作为真相源（命题 1.5.1）。
- 浅副本不提供回滚能力，替代方案是不可变结构与写时复制（命题 1.5.2）。
- 可逆性分四级，等级越高验证强度需求越高（命题 1.5.3）。
- 有界容器的覆盖窗口是 $C/r$，超出窗口的查询必然失败（命题 1.5.4）。
- 静默丢弃使丢失不可观测（命题 1.5.5）。
- 先写日志使中断可判定（命题 1.5.6）。

## 四、【回到直觉】

- **定义 1.5.1 说的**：逐个状态问"能不能写段代码算出来"。能，就把它当派生管。不能，就必须持久化。
- **命题 1.5.1 说的**：别让派生状态变成唯一被读的东西。**缓存可以加速，但真相源仍在原始数据。**
- **命题 1.5.2 说的**：回滚用的副本必须是深的。**做不到深复制就用不可变结构。**
- **定义 1.5.3 说的**：问"撤销要动什么"。只动内存是 L0，动外部世界是 L3。等级决定你要花多少验证。
- **命题 1.5.4 说的**：有界容器的容量要对齐最长的回溯需求——否则它会在你需要时静默不给数据。
- **命题 1.5.5 说的**：加一个淘汰计数。它是区分"没有"与"被挤掉"的唯一手段。
- **命题 1.5.6 说的**：先写日志、后应用，中断就变成可判定的。

**本节要点**

- 问"能否重建"决定状态归属。
- 派生状态不做真相源。
- 回滚副本必须深。
- 撤销要动什么决定验证强度。
- 容量对齐回溯需求。
- 加淘汰计数。
- 先写日志。

## 五、【工具箱】

### 5.1 重建性判据

对每个状态写一个假设：**"如果我只有 X、Y、Z，能算出它吗？"** 能，即派生。

**输出**：一张表，列出状态、类别、真相源位置、持久化与否。

### 5.2 可逆性四级的判断

四个问题逐层问：

1. 撤销只需丢弃内存值吗？是则 L0。
2. 只需改写一份本地数据吗？是则 L1。
3. 需要协调多处或跨机器吗？是则 L2。
4. 需要影响外部世界吗？是则 L3。

**L3 的操作要单独列表管理**——它们是 1.1 意义上的单向门。

### 5.3 原子写的三步

写临时文件 → 落盘 → 重命名（与 3.5 工具箱 5.2 同一方法）。

**迁移的原子切换**：新数据写到临时位置，验证通过后重命名覆盖。旧数据保留一份用于回退。

### 5.4 有界策略的选择

| 策略 | 适用 | 代价 |
|---|---|---|
| 失败 | 数据不可丢 | 调用方需要处理失败 |
| 丢弃最旧 | 只需要最近一段 | 覆盖窗口有限 |
| 外置 | 需要全部但内存有限 | 需要存储与取回 |

**三种都必须带可观测信号**（失败返回错误、丢弃计数增长、外置留下指针）。

### 5.5 幂等重放

按 3.5 命题 3.5.3，重放的操作用赋值型。累加型要带唯一标识并记录已应用集合。

**与先写日志的配合**：日志给出"要做哪一步"，幂等保证"做两次与一次相同"。

**本节要点**

- 重建性判据输出一张状态表。

- 原子写三步同样用于迁移切换。
- 有界策略三种都要带可观测信号。

### 7.2 分类段与归属段

分类段判定每个状态可否定重建，归属段检查真相源是否唯一。

```js
// 定义 1.5.1 / 命题 1.5.1：状态分类与真相源唯一性
export const STATE_KINDS = ['authoritative', 'derived', 'ephemeral']

export function classifyState(rebuildable, lifetimeWithinOneOp = false) {
  if (lifetimeWithinOneOp) return 'ephemeral'
  return rebuildable ? 'derived' : 'authoritative'
}

export function checkSourceOfTruth(ownership) {
  const byState = new Map()
  for (const [owner, states] of Object.entries(ownership)) {
    for (const s of states) {
      if (!byState.has(s)) byState.set(s, [])
      byState.get(s).push(owner)
    }
  }
  const duplicated = [...byState.entries()].filter(([, owners]) => owners.length > 1)
  return { ok: duplicated.length === 0, duplicated }
}
```

### 7.3 可逆段

可逆段由内到外四级判定，并给出各等级的可容忍缺陷率。

```js
// 定义 1.5.3 / 命题 1.5.3：可逆性四级，等级越高验证强度需求越高
export function reversibilityLevel(scope) {
  if (scope.touchesExternalWorld) return 'L3'
  if (scope.spansMultipleStores || scope.crossesMachines) return 'L2'
  if (scope.writesLocalData) return 'L1'
  return 'L0'
}

// 按等级给出可容忍缺陷率（与 1.1 命题 1.1.5 同一公式）
const COST_BY_LEVEL = { L0: 0.1, L1: 1, L2: 10, L3: 100 }
export function tolerableDefectRate(level, lossBudget = 1) {
  return lossBudget / COST_BY_LEVEL[level]
}

export function levelOrder() {
  return ['L0', 'L1', 'L2', 'L3']
}
```

### 7.4 有界与迁移段

这一段覆盖覆盖窗口、有界策略、原子切换与日志恢复。

```js
// 命题 1.5.4 / 1.5.5：覆盖窗口与静默丢弃
export function coverageWindow(capacity, writesPerSecond) {
  if (writesPerSecond <= 0) return Number.POSITIVE_INFINITY
  return capacity / writesPerSecond
}

export function boundedPolicy(policy, evictions) {
  const observable = {
    fail: '返回错误',
    dropOldest: `淘汰计数 ${evictions}`,
    spill: '留下指针',
  }
  return { policy, signal: observable[policy] ?? '无信号（缺陷）', observable: policy in observable }
}

// 工具箱 5.3：原子切换的三步（与 3.5 同一方法）
export function atomicSwitch(staging, target) {
  return [
    { step: 1, action: 'write', path: staging },
    { step: 2, action: 'fsync', path: staging },
    { step: 3, action: 'rename', from: staging, to: target },
  ]
}

// 命题 1.5.6：先写日志使中断可判定——恢复时按日志重做
export function recoverFrom(log, apply, state) {
  let s = state
  for (const entry of log) {
    if (entry.applied) continue
    s = apply(s, entry.op)
  }
  return s
}
```

### 9.1 决策表

| 情形 | 选什么 | 依据 | 代价 |

| 新增一份状态 | 先判它可否定重建 | 定义 1.5.1 | 分类时间 |

| 操作触及外部世界 | 归入 L3，单独列表 | 定义 1.5.3 | 验证强度最高 |

| 需要迁移数据 | 先复制、再原子切换、留回退 | 工具箱 5.3 | 需要额外空间 |

### 9.2 失败模式

**（1）检查放在装载期（L9 位置放错）。** 可逆性等级在系统启动时判定一次，而同一操作的等级会因配置而变（例如从本地写变成跨机写）。表现是"按 L1 的验证强度做了 L2 的改动"。修正：按每次操作的实际作用域重新判定。

**（2）前提会变（L9）。** 命题 1.5.4 的覆盖窗口以"写入速率稳定"为前提。速率上升时窗口缩短，原本可回溯的查询开始失败。修正：监控速率并据此调整容量。

**（3）派生状态被当成真相源。** 缓存逐渐变成唯一被读的地方。

**（4）浅复制当深复制。** 回滚时发现副本与原文一起变了。

**（5）静默丢弃。** 使用者无法区分"没有"与"被挤掉"。

**（6）容量与回溯需求不匹配。** 需要在时查不到，且表现为"查不到"而非"被淘汰"。

**（7）迁移无原子性。** 中断后数据既不是旧格式也不是新格式。

**（8）迁移无回退路径。** 新格式出错时无法退回。

**（9）无日志的恢复。** 中断后无法判断改动是否生效。

**（10）重放非幂等操作。** 重复应用产生重复副作用（与 3.5 同一问题）。

**本节要点**

- 决策表覆盖 11 种情形。
- 失败模式十条，前两条是位置放错与前提会变。
- 最隐蔽的是"浅复制当深复制"——它在你以为安全时取走了安全性。

## 十、仍未解决

- **可重建性的边界。** "能从其他状态重建"依赖其他状态的完整性，而后者可能也不完整。
- **双写的检测。** 唯一性可静态检查，但运行时的实际写入点可能多于声明。
- **可逆性的动态判定。** 同一操作的等级依赖运行时配置，静态判定会过时。
- **深复制的成本。** 大对象深复制代价高，而不可变结构的采用需要全链路配合。
- **迁移的原子性上限。** 跨多个存储的迁移无法用单次重命名完成，原子性只能近似。
- **幂等标识的存储。** 已应用集合自身也要持久化，而它的规模随时间增长。

**本节要点**

- 可重建性依赖来源的完整性。
- 运行时的写入点可能多于声明。
- 可逆性等级依赖运行时配置。
- 深复制成本高，不可变结构需要全链路配合。
- 跨存储迁移无法真正原子。
- 已应用集合自身会增长。
