## 本篇新词

- 十站（ten stations） 指一个功能要依次经过的十个判断点。它是地图而不是流程：站与站之间的顺序由依赖决定，可以跳站，但跳过的站要留痕。
- 可逆性等级（reversibility level） 指一个动作能否被撤销，以及撤销的代价。它决定该动作需要多少验证，而不是取决于它看起来多重要。
- 单向门（one-way door） 指不可逆或撤销代价极高的决定，例如数据格式的公开、对外接口的承诺。
- 影响面（blast radius） 指一次改动会波及的范围。验证成本与它同阶增长，因此它是"要不要拆小"的判断依据。
- 错误预算（error budget） 指一个功能在单位时间内允许出现多少次不符合预期的结果。它把"能不能发布"从判断变成算术。
- 完成判据（completion criterion） 指"这个功能算做完了"的可观测条件。它必须在方案之前写下。
- 技术债利息（debt interest） 指为了绕开一个结构问题而付出的重复代价。它在每次触及该处时都要再付一遍。

## 一、【设计原因】

### 1.1 缺陷一：能说出"要做这个功能"，说不出它要经过哪些站

被问"这个功能怎么做"时，回答通常从"先改哪几个文件"开始。

这跳过了三站：成功判据（什么算做对了）、影响面（会波及谁）、回滚路径（做错了怎么退）。跳过它们的直接后果是这三个问题会在动手之后以更贵的形式回来。

### 1.2 缺陷二：把"先做什么"当成排序问题，而它实际是依赖问题

"先做 A 还是先做 B"看起来是优先级问题。但如果 B 的正确性依赖 A 的结论，那么"先做 B"不是优先级低，而是不可能做对。

排序问题有多个解，依赖问题只有一个可行序（可能不唯一，但受约束）。 把后者当前者，会得到一个看起来合理而执行不下去的计划。

### 1.3 缺陷三：对所有改动用同一种谨慎程度

改一个文案和改一个持久化格式用了同样多的评审。前者的代价是重发一次，后者的代价是数据迁移。

谨慎程度应当由可逆性决定，而不是由感觉或惯例决定。 统一谨慎的后果是：容易的改动被过度管控，而危险的改动没有得到额外防护。

### 1.4 缺陷四：说不出"完成"是什么

功能做完了，但没人能说出它算不算完成。表现是"还要再打磨一下"、"再看看有没有问题"——这类表述没有终止条件。

没有可观测的完成判据，就没有完成。 任务会一直挂在"进行中"，而资源无法释放。

### 1.5 由此确定的设计目标

1. 地图先于方法：先说要经过哪些判断点，再谈每一站怎么做。
2. 顺序由依赖决定：依赖关系写出来，排序从它推出。
3. 谨慎程度由可逆性决定：分级而不是统一。
4. 完成判据先于方案：判据写在方案之前，且可观测。

**本节要点**

- 直接谈"改哪些文件"会跳过成功判据、影响面与回滚路径。
- 依赖问题只有一个可行序，排序问题有多个解。
- 谨慎程度应当由可逆性决定，统一谨慎两头都错。
- 没有可观测的完成判据就没有完成。
- 四条目标：地图先于方法、顺序由依赖决定、谨慎由可逆性决定、判据先于方案。

## 二、【直觉】

### 2.1 装修房子

装修一套房子，判断点大致是：想住成什么样 → 量房 → 定预算 → 拆改（含承重墙） → 水电 → 瓦木油 → 家具 → 验收 → 入住 → 若干年后的翻新。

其中只有一个判断点是单向门：承重墙。拆错了不能靠"再拆回来"恢复，代价是结构安全。其余各站都可以改，代价从"多花一天"到"多花一个周"不等。

这条直觉给出两张表：十站是地图，每站的代价决定它需要多少验证。

### 2.2 墙里 vs 墙外

装修里最贵的事是把做完的活拆开重做。水电埋进墙里之后，改一个插座位置要砸墙。

软件里对应的东西是已经公开出去的东西：接口、数据格式、用户已经依赖的行为。它们一旦出去，改动就要考虑兼容。

这条对比给出可逆性的判据：改动是否需要别人的配合才能完成。 需要，则是单向门。不需要，则是双向门。

::: keypoint 反直觉点
**可逆性不是"能不能改回来"，而是"改回来是否需要外部配合"。** 一个改动即使自己在技术上能回滚，只要已经有人依赖它，它就是单向门——因为你无法单方面撤回别人的依赖。
:::

### 2.3 一个数字直觉

设一个功能每周产生 4 处需要绕开某结构问题的调整，每次 0.5 小时。那么这笔债的利息是每周 2 小时，一年约 100 小时。

而重构一次的代价通常是几十小时。也就是说，这笔债在半年到一年之间就还清了它的重构成本——超过这个时间，不还债的代价更高。

这个算术不精确，但它给出判断的量级：债要不要还，取决于它还打算存在多久。

**本节要点**

- 十站里真正单向的门很少，识别它比记住全部站名重要。
- 最贵的工序是拆开重做，对应软件里"已公开出去的东西"。
- 可逆性的判据是"是否需要外部配合"。
- 债的利息按周累积，与重构成本的比较给出还债的时间窗。

## 三、【严格】

### 3.1 定义

::: theorem 定义 1.1.1（十站）
一个功能的生命周期包含十个判断点：

$$
\mathcal{S} = \{\text{意图},\ \text{判据},\ \text{影响面},\ \text{方案},\ \text{依赖序},\ \text{实现},\ \text{验证},\ \text{发布},\ \text{观测},\ \text{退役}\} .
$$

每一站有四个要素：**输入**（这一站需要什么）、**产出**（这一站给出什么）、**判据**（什么算这一站做对了）、**失败代价**（这一站做错要付多少）。
:::

::: theorem 定义 1.1.2（可逆性等级）
动作 $a$ 的**可逆性**由其回滚代价与外部影响共同决定，分为三级：

$$
\mathrm{rev}(a) = \begin{cases}
\text{双向门}, & \text{回滚代价 } c(a) \le c_{\text{low}} \text{ 且无外部依赖},\\
\text{缓开门}, & \text{回滚代价中等，或外部依赖可协调},\\
\text{单向门}, & \text{回滚代价 } c(a) > c_{\text{high}} \text{ 或依赖不可单方面撤回}.
\end{cases}
$$
:::

::: theorem 定义 1.1.3（影响面）
给定依赖图 $G = (V, E)$（边表示"依赖"），变更集合 $\Delta \subseteq V$ 的**影响面**为

$$
\mathrm{BR}(\Delta) = \Delta \cup \{v \in V : \exists u \in \Delta,\ u \to^* v\} ,
$$

即 $\Delta$ 及所有（传递地）依赖它的节点。
:::

::: theorem 定义 1.1.4（完成判据）
**完成判据**是一组断言 $C = \{c_1, \dots, c_k\}$，每个 $c_i$ 是当前状态的一个可观测谓词。功能**完成**当且仅当 $\bigwedge_i c_i$ 为真。

判据必须**可观测**：存在一个有限程序判定 $c_i$ 的真假。
:::

::: theorem 定义 1.1.5（错误预算）
设功能在窗口 $W$ 内的请求数为 $N$，允许的失败数为 $E$。**错误预算**为 $E/N$。

功能在 $W$ 内**可发布**，当且仅当实际失败率不超过 $E/N$。
:::

::: theorem 定义 1.1.6（技术债与它的利息）
**技术债**是为绕开结构问题而采取的工作方式。它的**利息**是因此重复付出的代价：

$$
I(n) = n \cdot i,
$$

其中 $i$ 是单位时间内触及该问题一次的平均代价，$n$ 是触及次数。
:::

### 3.2 命题

::: theorem 命题 1.1.1（完成判据必须可观测，否则无法判定完成）
若完成判据中存在不可观测的 $c_i$，则无法判定功能是否完成。

**证明.** 判定的过程是对每个 $c_i$ 求值。不可观测意味着不存在有限程序给出 $c_i$ 的真假。故合取式的值不可得。

↓ **为什么能这么写？** 合取式的值依赖每个合取项的值。

$\blacksquare$

::: keypoint 不可观测判据的典型形式
**"体验好"、"足够稳定"、"没有明显问题"都是不可观测的。** 可观测的版本是"P95 延迟低于 800 毫秒"、"连续 7 天失败率低于 1%"、"三个指定场景全部通过"。
:::

::: theorem 命题 1.1.2（依赖约束下的可行序唯一性）
设依赖关系构成偏序 $\prec$。若存在 $A \prec B$，则任何满足依赖的执行序中 $A$ 必须早于 $B$。

**证明.** $\prec$ 是偏序，故其传递闭包定义了必要的前后关系。执行序必须是该偏序的一个线性扩展，而线性扩展保持所有 $\prec$ 关系。故 $A \prec B \Rightarrow A$ 在 $B$ 之前。

↓ **为什么能这么写？** 可行性由"是偏序的线性扩展"定义，而线性扩展按定义保持偏序关系。

$\blacksquare$

**推论**：**依赖关系是可以从计划里读出来的**——把"必须先做"的关系画出来，计划就是它的线性扩展。画不出依赖而只给出顺序时，那个顺序大概率不可行。
:::

::: theorem 命题 1.1.3（验证成本随影响面单调增）
$\mathrm{BR}(\Delta_1) \subseteq \mathrm{BR}(\Delta_2) \Rightarrow \mathrm{cost}_{\text{verify}}(\Delta_1) \le \mathrm{cost}_{\text{verify}}(\Delta_2)$。

**证明.** 验证必须覆盖受影响的全部节点（否则未覆盖部分的正确性无保证）。受影响节点集合的包含关系决定了验证工作量的包含关系，故成本单调不减。

↓ **为什么能这么写？** 验证工作量是受影响节点集合的单调函数。

$\blacksquare$

**推论**：**"把这个改动拆小"的收益可以直接算**——拆小使每个子变更的影响面收缩，从而验证成本下降。这也是"小步提交"的定量依据，而不只是风格偏好。
:::

::: theorem 命题 1.1.4（债的利息与还债决策）
设重构成本为 $R$，单位时间利息为 $i$。则债存在时间 $t$ 时，不还债的累计代价为 $it$。**当 $it > R$ 时，还债更划算**，即临界时间

$$
t^{*} = \frac{R}{i} .
$$

**证明.** 累计利息 $it$ 随 $t$ 线性增长，重构成本为常数 $R$。两者之差 $it - R$ 在 $t > R/i$ 时为正，故此时不还债的代价超过还债。

↓ **为什么能这么写？** 一边是线性增长的累计量，一边是常数，比较两者即可。

$\blacksquare$

**数值**：$R = 60$ 小时、$i = 2$ 小时/周时，$t^{*} = 30$ 周。**这笔债在半年左右之后就应当还**。
:::

::: theorem 命题 1.1.5（单向门需要额外的验证量）
设动作 $a$ 为单向门（回滚代价 $c(a) > c_{\text{high}}$）。则其期望损失为 $p \cdot c(a)$，其中 $p$ 是未被现有验证捕获的缺陷率。为使期望损失不超过阈值 $L$，需

$$
p \le \frac{L}{c(a)} .
$$

**证明.** 期望损失为"未捕获缺陷率 × 回滚代价"（考虑单次）。要求它不超过 $L$ 即得上式。由于 $c(a)$ 大，满足该式需要 $p$ 小，即验证必须更强。

↓ **为什么能这么写？** 期望损失是缺陷率与代价的乘积。代价大时，容忍的缺陷率必须小。

$\blacksquare$

**数值**：双向门 $c = 0.1$ 小时、$L = 1$ 小时时 $p$ 可容忍到 1。单向门 $c = 100$ 小时时 $p$ 必须低于 0.01。**两者的验证强度需求相差两个数量级。**
:::

::: theorem 命题 1.1.6（错误预算使发布决策可计算）
若错误预算为 $b = E/N$，则"是否可以发布"等价于一个可计算的比较（实际失败率 $\le b$），而不依赖主观判断。

**证明.** 发布决策的两种取值对应失败率与 $b$ 的比较。该比较使用可观测的计数，故可由有限程序完成。

↓ **为什么能这么写？** 把主观判断替换为计数比较，后者可判定。

$\blacksquare$

::: keypoint 预算的作用是让"能不能发"不再是争论
**没有预算时，"这个失败率能接受吗"是一个观点问题**，取决于参与者的风险偏好。有预算时它是一个算术问题，且预算本身可以在团队层面统一设定。
:::

### 3.3 本节要点

**本节要点**

- 十站各有四个要素，站间顺序由依赖决定（定义 1.1.1）。
- 可逆性分三级，判据是回滚代价与外部依赖（定义 1.1.2）。
- 影响面是变更集合及其全部传递依赖（定义 1.1.3）。
- 完成判据必须可观测（命题 1.1.1）。
- 依赖关系给出唯一的可行序（命题 1.1.2）。
- 验证成本随影响面单调增，这是"拆小"的定量依据（命题 1.1.3）。
- 债的临界时间是 $R/i$（命题 1.1.4）。
- 单向门需要的验证强度可高两个数量级（命题 1.1.5）。
- 错误预算把发布决策变成算术（命题 1.1.6）。

## 四、【回到直觉】

- **定义 1.1.1 说的**：十站是**地图**不是流程。画一遍，看哪几站的产出你答不上来——答不上来的那几站就是风险所在。
- **定义 1.1.2 说的**：问"这个改动要不要别人配合"。要，就是单向门。
- **定义 1.1.3 说的**：影响面 = 改了它，还有"谁"要跟着改。它是"要不要拆小"的依据。
- **命题 1.1.1 说的**：把"完成"写成一个能跑的判断。"体验好"不是判据，"P95 低于 800 毫秒"是。
- **命题 1.1.2 说的**：先画依赖，再排顺序。只给顺序不给依赖的计划，大概率执行不下去。
- **命题 1.1.3 说的**：拆小的收益能算出来——每个子变更的影响面更小，验证成本更低。
- **命题 1.1.4 说的**：债要不要还，看它还打算存在多久。$R/i$ 给出时间窗。
- **命题 1.1.5 说的**：单向门要更强的验证，强度差别可以到两个数量级。
- **命题 1.1.6 说的**：有错误预算，"能不能发"就不是观点问题。

**本节要点**

- 画十站，找出答不上产出的那几站。
- 单向门的判据是"要不要别人配合"。
- 影响面决定要不要拆小。
- 完成判据要能跑。
- 先画依赖再排顺序。
- 拆小的收益可算。
- 债的时间窗是 $R/i$。
- 单向门需要高两个数量级的验证。
- 错误预算让发布决策可计算。

## 五、【工具箱】

### 5.1 依赖的拓扑排序

给定偏序 $\prec$，其线性扩展由拓扑排序给出。Kahn 算法的代价是 $O(|V| + |E|)$。

**它的副产品是环检测**：若排序输出的节点数少于总数，说明依赖里存在环，而环意味着**这个计划不可能执行**——必须先打破环。

### 5.2 可逆性分级的操作化

三级判据可以写成三个问题：

1. **回滚要多久？** 分钟级是双向门，小时级是缓开门，天级或不可回滚是单向门。
2. **有外部依赖吗？** 有则至少是缓开门。
3. **回滚需要别人配合吗？** 需要则是单向门。

### 5.3 影响面的计算

从变更集合出发在依赖图上做正向可达，代价 $O(|V| + |E|)$。

**注意方向**：影响面是"依赖它的节点"，不是"它依赖的节点"。方向搞反会把影响面算成"前置条件"，从而严重低估。

### 5.4 债的利息估算

按 $i = f \cdot c$ 估算，其中 $f$ 是单位时间内触及该问题的次数，$c$ 是单次绕开的额外代价。两者都从实际记录中统计，而不是估计。

**数值**：$f = 4$ 次/周、$c = 0.5$ 小时 → $i = 2$ 小时/周。$R = 60$ 小时 → $t^{*} = 30$ 周。

### 5.5 完成判据的写法

每条判据写成"可观测的量 + 比较 + 阈值 + 时间窗"：

$$
\underbrace{\text{P95 延迟}}_{\text{可观测的量}} < \underbrace{800\text{ ms}}_{\text{阈值}} \quad \text{（连续 7 天）}_{\text{时间窗}} .
$$

**缺时间窗的判据会在"某次刚好达标"时误判为完成。**

**本节要点**

- 拓扑排序给出线性扩展，并检测依赖环。
- 可逆性分级可操作化为三个问题。
- 影响面是正向可达，方向不能反。
- 债的利息从实际记录统计，不估计。
- 完成判据要含时间窗。

### 7.2 依赖与顺序

依赖关系写成偏序，顺序由它的线性扩展给出。

```js
// 工具箱 5.1：Kahn 拓扑排序——给出线性扩展，并检测依赖环
export function topoOrder(nodes, edges) {
  const indeg = new Map(nodes.map((n) => [n, 0]))
  const out = new Map(nodes.map((n) => [n, []]))
  for (const [from, to] of edges) {
    out.get(from).push(to)
    indeg.set(to, indeg.get(to) + 1)
  }
  const queue = nodes.filter((n) => indeg.get(n) === 0)
  const order = []
  while (queue.length) {
    const n = queue.shift()
    order.push(n)
    for (const m of out.get(n)) {
      indeg.set(m, indeg.get(m) - 1)
      if (indeg.get(m) === 0) queue.push(m)
    }
  }
  return { order, cyclic: order.length < nodes.length }
}
```

顶点数为 0 的队列处理是标准写法。`cyclic` 标志给出环的存在性——**有环的计划不可能执行**。

### 7.3 可逆性分级

三级的判据可以写成三个问题，下面的实现把它们合为一个函数。

```js
// 定义 1.1.2：三级判据——回滚代价、外部依赖、是否需他人配合
export function reversibility({ rollbackMinutes, externalDependents, needsCoordination }) {
  if (needsCoordination || rollbackMinutes > 60 * 24) return 'one-way'
  if (externalDependents > 0 || rollbackMinutes > 60) return 'slow'
  return 'two-way'
}

// 命题 1.1.5：单向门可容忍的缺陷率远低于双向门
export function tolerableDefectRate(lossBudget, rollbackCost) {
  return lossBudget / rollbackCost
}
```

### 7.4 影响面

影响面是正向可达，方向不能反——反了会把受影响范围算成前置条件。

```js
// 定义 1.1.3 / 工具箱 5.3：正向可达——影响面是"依赖它的节点"，不是"它依赖的节点"
export function blastRadius(delta, graph) {
  const seen = new Set(delta)
  const queue = [...delta]
  while (queue.length) {
    const v = queue.shift()
    for (const w of graph.get(v) ?? []) {
      if (!seen.has(w)) { seen.add(w); queue.push(w) }
    }
  }
  return [...seen]
}
```

### 7.5 债的利息与完成判据

债的临界时间与完成判据各是一个短函数，后者要求判据含时间窗。

```js
// 命题 1.1.4：临界时间 t* = R / i
export function debtBreakEven(refactorHours, interestPerWeek) {
  return refactorHours / interestPerWeek
}

// 定义 1.1.4 / 工具箱 5.5：完成判据必须可观测，且含时间窗
export function checkCompletion(criteria, observations) {
  const failed = criteria.filter((c) => {
    const v = observations[c.metric]
    return v === undefined || v >= c.threshold
  })
  return { done: failed.length === 0, failed: failed.map((c) => c.metric) }
}
```

### 9.2 失败模式

**（1）检查放在装载期（L9 位置放错）。** 可逆性只在项目开始时判断一次，而功能会演进——一个最初的双向门（内部接口）在对外公开后变成单向门。表现是"用早期的判断对待后期的改动"。修正：每次变更前重新分级，而不是沿用立项时的结论。

**（2）前提会变（L9）。** 命题 1.1.3 的验证成本以"影响面可由依赖图算出"为前提。若依赖关系是隐式的（运行时才确定），算出的影响面会偏小。修正：把隐式依赖（动态注册、反射调用）显式登记，否则影响面不可信。

**（3）把依赖问题当排序问题。** 得到看起来合理而执行不下去的计划。

**（4）对所有改动一样谨慎。** 容易改动被过度管控，危险改动防护不足。

**（5）完成判据不可观测。** "体验好"这类判据使完成无法判定。

**（6）完成判据缺时间窗。** 某次刚好达标就判为完成。

**（7）影响面方向算反。** 把"它依赖的"当成"依赖它的"，严重低估影响面。

**（8）依赖图有环而不自知。** 计划排不出来，误以为是资源问题。

**（9）债的利息不统计。** 没有 $f$ 与 $c$ 的记录，$R/i$ 算不出来，还债决策只能靠感觉。

**（10）跳过十站而不留痕。** 后续接手的人不知道哪些判断点被略过了。

**本节要点**

- 决策表覆盖 11 种情形。
- 失败模式十条，前两条是位置放错与前提会变。
- 最隐蔽的是"可逆性只在立项时判断一次"。

## 十、仍未解决

- **影响面的完备性。** 依赖图是否覆盖了全部真实依赖，无法自证。隐式依赖是它的主要缺口。
- **可逆性分级的阈值。** "分钟级、小时级、天级"的界缺少客观依据，且随团队而异。
- **错误预算的设定。** 预算本身定多少没有推导方法，只能按业务容忍度给。
- **债的利息的统计口径。** "触及一次该问题"的判定带主观性，不同人算出的 $f$ 可能不同。
- **探索型任务的跳站规则。** 允许跳站但要求留痕，而"留痕"的最小内容没有标准。
- **十站的跨规模适用性。** 小改动走完整十站成本过高，而"多小可以简化"缺少判据。
