# 习题总纲 · 75 道题的全清单（以 dsh-mini 为对象）

> **这份文档是什么**：`v1-体系设计-已归档.md` 里那 75 道题的完整清单。
> 每道题给出六件事：**场景 / 任务 / 约束 / 判据 / 陷阱 / 延伸**，并标注它练的是 `问题清单.md` 里的哪几条。
>
> **怎么用它**：
> 1. 先做 `7.0` 的基线自评（在 `问题清单.md` 末尾的打分表里）
> 2. 按你要走的路线挑题（路线 C 的推荐顺序在本文末尾）
> 3. 每题都要求**产出物**——那是你的能力证据，也是作品集
> 4. 做完一题，回打分表把对应条目 +1（**没有涨分说明题做空了**）

| **延伸** | ① 怎么把这条规则变成 CI 门禁？ ② 反过来：framework 能不能 import kernel？ |

## 九、这份习题体系自身的缺陷（诚实清单）

| 缺陷 | 后果 | 修法 |
|---|---|---|
| **没有标准答案**（除 D 类外） | 你无法知道"我这次判断对不对" | D 类可对照文档；J/W 类靠"是否可证伪、是否给代价、是否留回退"三条自检；真正的验证要等真实项目 |
| **靠自律** | 没人检查你是否真的做了产出物 | 产出物必须能给别人看（作品集）—— 公开是最强的自律 |
| **dsh-mini 会演进** | 题目引用的结构可能过期 | 只引用**结构性事实**（文件职责、扩展点），不引用行号 |
| **单人项目缺少协作类练习** | 5.x 那组（跨职能）练不真 | 可以用"扮演另一个角色"的方式做（写一份你会怎么反驳自己的方案） |
| **没有时间压力** | 真实工作中判断要在几小时里做出 | 给部分题加计时（如 J 类限时 30 分钟出结论） |
| **评分是自评** | 容易高估 | 每题的产出物是外部可检验的 —— 让别人读，看他要问几个问题 |
