## 读完这一篇你会知道什么

1. **这门课的载体**：一个真实的 agent harness，从最小闭环一路加到可靠、可进化、可规模化。
2. 七卷的分工：每一卷解决一类问题，而且后一卷依赖前一卷。
3. 每篇讲义的固定结构：是什么 / 为什么 / 怎么做 / 特殊情况 / 工业界做法 / 学术界结论 / 工程化清单 / 练习 / 算例。
4. 三种学习路径：自顶向下、问题驱动、速通。
5. 算例的用法：每个数都来自可运行的代码，你可以自己跑出来。
6. 能力等级：从"能读懂"到"能设计"的四级，以及每一级的具体判据。

## 一、这门课教什么

这门课教的是**怎么把一个 LLM agent 系统做成可靠、可维护、能规模化的工程产物**。

它的载体不是幻灯片，而是一个**真实的 harness**：从"能发一次请求、执行一次工具"的最小闭环开始，逐卷加能力，最后得到一个具备可靠性纵深、学习进化、规模化与评测能力的系统。

**这门课不教什么**（同样重要）：

| 不教 | 因为它属于 |
|---|---|
| 模型训练与预训练 | 见第 7 卷的基础算例，但不涉及大规模训练 |
| 具体框架的 API | 会过时，而原理不会 |
| 提示词技巧清单 | 技巧会失效，判据才可靠 |

这门课的核心主张：**工程判断力来自"能算出来的判据"，而不是来自经验口诀。** 所以每一篇都给出可运行的算例与可断言的数字——不是"一般来说应该这样"，而是"在这个配置下，这个值是这么多"。

## 二、七卷的地图

| 卷 | 解决什么问题 | 你会得到 |
|---|---|---|
| **01 判断力地基** | 怎么判断一个改动值不值得做、多大谨慎 | 十站清单、可逆性分级、债的利息模型 |
| **02 最小闭环** | 怎么让 agent 跑起来 | 模型层、工具系统、容器、事件、作用域、装配、会话日志 |
| **03 可靠性与纵深** | 出错了怎么办 | 重试、守卫与审批、上下文压缩、进程管理、持久化、可观测 |
| **04 学习进化** | 怎么让它越用越好 | 记忆、技能、用户建模、诊断、演化、复盘、长程任务 |
| **05 规模化与交互** | 多人多任务时怎么办 | 预设、并发调度、审批交互、多智能体 |
| **06 科研出口** | 怎么把工程问题变成研究问题 | 开放问题、实验方法、评测、从观察到问题 |
| **07 大模型基模** | 模型本身怎么回事 | 分词、注意力与 KV cache、训练与对齐、采样、推理成本、能力评测 |

依赖关系：**01 是判断工具（后面每卷都要用）。02 是地基（03–05 都建立在它上面）。03–05 之间相对独立。06 是把前面所有经验转成研究问题的出口。07 可以独立学。**

## 三、怎么学

### 3.1 每篇的固定结构

每篇讲义都是同一套骨架，你可以按需跳读：

| 节 | 内容 | 什么时候看 |
|---|---|---|
| 导语 | 这一篇解决什么问题 | 先看 |
| **目录** | 可点击的直达链接 | 跳读用 |
| **读完你会知道什么** | 学完的收获清单 | 先看 |
| 一、为什么需要 | 用真实故障场景引入 | 不理解背景时看 |
| 二、机制总览 | 一张表讲清全貌 | 建立框架 |
| 三、怎么做 | 具体做法与代码 | **要动手时看** |
| 四、特殊情况 | 常见坑与处理技巧 | 用之前看 |
| **五、工业界怎么做** | 真实产品怎么配、参数怎么定、实施清单 | **要落地时看** |
| **六、学术界结论** | 相关研究给出了什么结论 | **要深入时看** |
| 七、理论 | 公式与可检查性质 | 要理解为什么时看 |
| 八、工程化清单 | 上线前逐项核对 | 交付前看 |
| 九、练习 | 三道题（一道进阶） | 检验掌握程度 |
| 十、算例 | 可运行的代码 | **必跑** |
| 只要记住一句 | 全篇浓缩 | 复习用 |

**"工业界怎么做"与"学术界结论"是这门课区别于普通教程的地方**：前者给你能照抄的参数与清单，后者告诉你这些做法背后的理论依据与已知边界。

### 3.2 三种学习路径

**路径一：完整学（推荐）**

按 01 → 02 → 03 → 04 → 05 的顺序，每篇都读、都跑算例、都做练习。**预计投入远大于一门普通课程**，因为它覆盖了从工程判断到可靠性的完整链条。

**路径二：问题驱动**

带着一个具体问题进来，按需查找：

| 你遇到的问题 | 去看 |
|---|---|
| 上下文总是超限 | 3.3 上下文压缩与溢出 |
| 重试把下游压垮了 | 3.1 重试与错误分类 |
| 一个长任务挡住了其他会话 | 5.2 多会话与并发 |
| 记不住用户的偏好 | 4.1 记忆 |
| 审批弹得太频繁 | 5.3 交互与权限 |
| 不知道优化哪一段 | 3.6 可观测 |
| 派发子任务反而更贵 | 5.4 多智能体与外部工具 |

**路径三：速通**

只读每篇的**导语 + 学习目标 + "只要记住一句"**，用三十分钟建立全貌，再决定深入哪几篇。算例仍然建议跑一遍——它是判断"我是否真懂了"的最快方式。

### 3.3 算例怎么用

**每个数字都来自可运行的代码**，你可以自己跑出来：

```powershell
cd D:\dsh-course
node examples/sa01_retry.mjs        # 看结果
node examples/test_sa01_retry.mjs   # 跑断言
```

用法建议：

| 做法 | 收益 |
|---|---|
| 先跑一次看输出 | 建立直觉 |
| 改一个参数再跑 | 看结论怎么变 |
| 跑 `test_*.mjs` | 验证你理解的性质 |
| 把输出与讲义的数字对照 | 确认口径一致 |

**第 7 卷需要 Python**（PyTorch CPU 版），安装方式见该卷卷首。其余各卷只需要 Node。

为什么强调"自己跑"：**这门课的数字是判据而不是结论**。参数换了，判据要重算——会跑算例，你才能在自己的系统上重算。

### 3.4 能力等级

| 等级 | 判据 | 典型表现 |
|---|---|---|
| **L1 能读懂** | 能说清每卷解决什么问题 | 能向别人解释"为什么要上下文压缩" |
| **L2 能复现** | 能照着算出同样的数字 | 能算出自己系统的重试预算 |
| **L3 能判断** | 面对新问题能选出做法并给出依据 | 能判断一次改动该走多重的流程 |
| **L4 能设计** | 能为新场景设计机制并给出可验证的判据 | 能设计一套审批体系并写出门槛值 |

**每一级的判据都是"能说出数字或写出检查"**，而不是"感觉懂了"。这也是这门课反复强调的：可机械验证的才是知识。

## 四、常见问题

| 问题 | 回答 |
|---|---|
| 需要什么基础 | 会写 JavaScript 或 Python，理解基本的 Web 与进程概念 |
| 需要 GPU 吗 | 不需要。第 7 卷的算例在 CPU 上可跑 |
| 要多久 | 完整学远超一门常规课程的时间。速通可在一小时内建立全貌 |
| 学完能做什么 | 能独立设计并实现一个可用的 agent 系统，并为它的关键决策给出量化依据 |
| 这些数字会过时吗 | 公式与判据不会，具体参数会。**所以每篇都给了公式，而不只是给数字** |
| 为什么每篇都有"学术界"一节 | 工程做法需要知道边界在哪，而边界来自研究结论 |
| 能做研究吗 | 第 6 卷专门讲怎么把工程观察转成研究问题 |

## 五、卡住了怎么办

三种常见的卡住与解法：

| 卡在哪 | 原因 | 解法 |
|---|---|---|
| 看不懂公式 | 缺前置概念 | 回到该篇的"二、机制总览"表，先建立框架再看公式 |
| 算例跑不出同样的数字 | 环境或版本差异 | 对照算例里的参数。差异本身也是学习材料 |
| 知道做法但不知道参数 | 没有从自己的场景反推 | 用该篇的公式反推（例如样本量、重试预算、覆盖窗口） |

一条通用建议：**遇到任何"应该怎么选"的问题，先找该篇有没有给出可计算的判据。** 如果只有口诀没有判据，那说明这一层还没被讲透——把它记下来，向上一卷找答案。

## 七、练习

### 第一题：定位你要学的内容

写出三个你当前工作中真实遇到的 agent 相关问题，然后：

- 用 3.2 的对照表定位到具体篇目。
- 说明你预计会在哪一节找到答案（三、怎么做 / 五、工业界 / 六、学术界）。
- 跑一遍对应篇目的算例，记下它的输出。

---

### 第二题：给自己定一个等级目标

要求：

- 用 3.4 的四级判据，评估自己现在在哪一级（给出具体证据）。
- 写出你希望达到的等级，以及达到它的判据。
- 指出哪几篇是你的必经之路，说明依据。

---

### 第三题（进阶）：设计你的学习顺序

要求：

- 从七卷里选出与你工作最相关的三篇。
- 说明它们之间的依赖关系（哪些必须先学）。
- 为每一篇写出"学完之后我会用它做什么"的一句话。
- 指出你可能跳过的部分，以及跳过的风险。
