## 本篇新词

- 观察（observation） 指一次被记录下来的、与预期不符的现象。它与失败的区别是失败有明确对错，而观察没有——"任务超时了"是失败，"这类任务在压缩阈值调高后反而更快"是观察。
- 意外（surprise） 指与已有预期冲突的观察。它是观察里价值最高的一类，因为冲突意味着某个既有认识不完整。
- 异常（anomaly） 指偏离常态但不与预期冲突的观察（例如某任务耗时是其他的十倍）。它与意外的区别是它可能只是长尾样本。
- 观察记录（observation log） 指按固定字段记录观察的载体。它的必要性来自一个经验事实：同一现象第二次出现时，人通常不记得第一次的细节。
- 排除已知解释（ruling out） 指在把观察转成问题之前，先排除它已有的解释。三种方式：查、做、找反例。
- 最小反例（minimal reproduction） 指能把现象复现出来的最小条件集。它让"你说的这个现象"变成"任何人跑这三步都能看到"。
- 机制问题（mechanism question） 指"为什么会这样"的问题，区别于"这样做会不会更好"的比较问题（6.2 处理）。
- 转化率（conversion rate） 指观察中被转成可执行问题的比例。它是这套流程的直接产出指标。

## 一、【设计原因】

### 1.1 缺陷一：现象发生过，而事后想不起细节

几周前看到过一个异常，当时觉得"记住了"。现在要写下来，却发现关键的几项都对不上：是哪个任务、当时改了什么、前后各跑了多少次。

记忆对"现象"的保留是定性而非定量的：它会记住"慢了很多"，但记不住"从 1.2 秒到 8.4 秒"。

### 1.2 缺陷二：异常被当成噪声忽略

一次运行明显偏离常规，被归为"偶发"，于是没有记录。第三次出现时，仍然被归为"偶发"——因为没有第一次的记录可比对。

"偶发"这个判断需要一个频率估计，而频率估计需要记录。 没有记录时，"偶发"只是一个无根据的印象。

### 1.3 缺陷三：局部修补掩盖了原因

现象出现了，直接改代码把它按下去。现象消失了，于是没有下文。

这类处置的代价在别处显现：原因是系统的，而修补是局部的，所以同一原因会在另一个地方再表现为一次不同的现象。

### 1.4 缺陷四：有一个现象，而说不清它是什么问题

知道"这里不太对"，但说不清问的是什么。这通常是把机制问题与比较问题混在一句话里。

比较问题有现成的框架（6.2 的实验方法）。机制问题需要不同的验证方式（预测新现象并检验）。混在一起时，两者都无法推进。

### 1.5 由此确定的设计目标

1. 记录必须极简且固定字段：字段固定才能比对，极简才能坚持。
2. 记录与整理分离：记的时候不判断价值，否则会漏掉当时看不出价值的现象。
3. 转化前先排除已知解释：不排除就转，得到的是重复已有的问题。
4. 机制问题与比较问题分开：两者的验证方式不同。

**本节要点**

- 记忆对现象是定性的，记不住数量。
- "偶发"需要频率估计，而频率估计需要记录。
- 局部修补会掩盖系统原因，使同一原因在别处再现。
- 机制问题与比较问题的验证方式不同，混在一起则都推不动。
- 四条目标：极简固定字段、记录与整理分离、先排除、两类问题分开。

## 二、【直觉】

### 2.1 现场记录与办案

侦探到现场的第一件事不是推理，是拍照、标号、记录时间。原因是现场会被破坏，而推理可以事后做。

记录与推理必须分开，因为它们的时效不同：现场的时效是小时，推理的时效是无限。把它们混在一起（"先想清楚这个线索有没有用再决定记不记"），就会漏掉大量当时看不出用途的东西。

这条直觉对应第一、二条设计目标：字段固定、记录与整理分离。

### 2.2 对照与排除

看到一个现象，第一反应是"这是不是因为 X"。要回答它，做法不是论证，是对照：把 X 换掉，看现象还在不在。

- 还在 → X 不是原因。
- 不在了 → X 是候选原因。
- 变了一半 → 存在多个原因。

::: keypoint 反直觉点
**排除不是"证明它不可能"，而是"做一次它不成立时现象会消失的检验"。** 前者的成本无穷大，后者是一次实验。把"排除"理解成前者，会使人跳过这一步直接进入推测。
:::

### 2.3 最小反例的价值

一个能复现现象的最小条件集，其价值有三层：可传递（别人能照做）、可归因（条件少则原因范围小）、可对照（改动其中一项就能看出差异）。

而它的构造过程本身就是理解：当你能把条件减到最少时，你已经知道哪些是必要的了。

### 2.4 一个数字直觉

设每天运行 200 次，其中 1% 的运行会出现某异常，即每天约 2 次。

若第一次出现时判定为"偶发"而不记录，那么第三次出现时（约一天后）你仍然无法判断它的频率。而记下三次之后，频率估计的区间宽度才收窄到可用（与 6.3 的区间估计同源：$n = 3$ 时 95% 区间几乎是全区间）。

"记录三次再判断"是一条低成本的纪律。

**本节要点**

- 记录与推理的时效不同，必须分开。
- 排除是一次实验，不是无穷论证。
- 最小反例可传递、可归因、可对照，构造过程本身即理解。
- 每天 1% 的异常约出现 2 次。记三次之前，频率估计没有意义。

## 三、【严格】

### 3.1 定义

::: theorem 定义 6.4.1（观察与预期）
一次**观察**是二元组 $o = (\text{fact}, \text{prediction})$：$\text{fact}$ 是实际观测到的结果，$\text{prediction}$ 是观测前对该情形的预期。

$o$ 是**意外**，当且仅当 $\text{fact}$ 与 $\text{prediction}$ 冲突。否则是**符合预期**。若 $\text{prediction}$ 未事先形成，则 $o$ 既非意外也非符合——它是**无预期观测**。
:::

::: theorem 定义 6.4.2（异常与常态）
设某量在基线条件下的分布为 $F$。观测值 $x$ 是**异常**，当且仅当 $x$ 落在 $F$ 的尾部区域（例如 $x > \mathrm{Q}_{0.99}$）。

注意异常与意外是两个维度：异常可以与预期一致（"我知道它会慢"），意外也可以不异常（"它居然快了"）。
:::

::: theorem 定义 6.4.3（观察记录）
**观察记录**是形如

$$
r = (\text{task}, \text{config}, \text{metric}, \text{before}, \text{after}, \text{trials}, \text{timestamp})
$$

的元组。**字段固定**是它的核心设计：只有字段相同，两次记录才能比对。
:::

::: theorem 定义 6.4.4（排除已知解释）
设现象 $o$ 的候选解释集合为 $\{H_1, \dots, H_k\}$。**排除** $H_i$ 指执行一次检验 $T_i$，其结果为：若 $H_i$ 成立则现象应消失，反之现象仍在。

$H_i$ 被排除，当且仅当 $T_i$ 显示现象在 $H_i$ 被抵消后仍然存在。
:::

::: theorem 定义 6.4.5（最小反例）
**反例**是使现象可复现的条件集 $C$。它是**最小的**，当且仅当移除 $C$ 的任一元素后现象不再复现：

$$
\forall c \in C:\ \lnot\,\mathrm{repro}(C \setminus \{c\}) .
$$
:::

::: theorem 定义 6.4.6（两类问题）
**机制问题**形如"为什么 $X$ 会发生"，其验证方式是**预测一个新现象并检验**。

**比较问题**形如"$A$ 与 $B$ 哪个更好"，其验证方式是比较两个处理的响应（6.2）。

两类问题的判别标准是**问题的答案是否指向一个可预测的新现象**。
:::

### 3.2 命题

::: theorem 命题 6.4.1（意外的必要条件）
若观测前未形成预期，则该观测不构成意外。

**证明.** 由定义 6.4.1，意外要求 $\text{fact}$ 与 $\text{prediction}$ 冲突。若 $\text{prediction}$ 不存在，则该冲突关系无定义，故不构成意外。

↓ **为什么能这么写？** 冲突是两个对象之间的关系，缺一个对象则关系不成立。

$\blacksquare$

::: keypoint 所以要先写下预期
**这条结论给出一条可执行的纪律：观测之前把预期写下来。** 不写的话，事后回溯时会不自觉地用观测结果"构造"一个预期，从而把意外降级为显然——这是最常见的自我欺骗形式。
:::

::: theorem 命题 6.4.2（未排除的已知解释使归因无效）
设现象 $o$ 的候选解释集中存在未被排除的 $H_i$。则把 $o$ 归因于其他解释 $H_j$（$j \ne i$）的结论不成立。

**证明.** $H_i$ 未被排除意味着存在一种情形使 $H_i$ 成立而 $o$ 仍然出现。故 $o$ 的出现不能反推出 $H_i$ 不成立，也就不能反推出 $H_j$ 成立。

↓ **为什么能这么写？** 归因要求排除其他候选。只要有一个候选未被排除，归因的排他性就不成立。

$\blacksquare$
:::

::: theorem 命题 6.4.3（最小反例的归因范围）
设反例 $C$ 最小。则现象的原因必然落在 $C$ 的某个非空子集的作用范围内。

**证明.** 由最小性，对任意 $c \in C$ 有 $\lnot\,\mathrm{repro}(C \setminus \{c\})$，即去掉 $c$ 后现象不出现。故 $c$ 对现象的产出生效，即原因涉及 $c$。由于上述对每个 $c$ 成立，原因涉及 $C$ 的每个元素。又因 $C$ 之外的条件不被包含，原因的作用范围不超过 $C$。

↓ **为什么能这么写？** 最小性对每个元素给出了必要性证据，从而把原因范围限制在 $C$ 内。

$\blacksquare$

::: keypoint 反例越小，归因范围越小
**"最小"不是审美要求，它直接决定归因范围的大小。** 一个包含二十个步骤的反例，说明不了二十个步骤里哪个是关键。而三步的反例，候选原因只剩三个。
:::

::: theorem 命题 6.4.4（转化的充分条件）
若观察 $o$ 满足：① 有事先预期且与之冲突。② 候选解释已排除到一个。③ 已构造最小反例，则 $o$ 可转化为一个可回答的机制问题。

**证明.** ② 使原因唯一，③ 使原因的作用范围有界，① 保证该原因与既有认识冲突（即有信息量，见 6.1 命题 6.1.4）。三者合起来给出一个明确的原因假设，而 6.1 的可回答性要求该假设有判别程序——由 ③ 的反例，判别程序是"移除该条件后现象是否消失"。

↓ **为什么能这么写？** 逐条检查 6.1 的可回答性条件，三条恰好覆盖因变量、自变量与判别程序。

$\blacksquare$
:::

::: theorem 命题 6.4.5（无记录则频率不可估）
设现象的真实发生率为 $p$。若不记录发生次数与总运行次数，则 $p$ 无法估计，因而"偶发"这一判断没有依据。

**证明.** 估计 $p$ 需要分子（发生次数）与分母（运行次数）。不记录时两者都不可得，故估计不存在。而"偶发"是"$p$ 很小"的断言，缺少估计则该断言无依据。

↓ **为什么能这么写？** 频率是计数之比，缺少计数则比不存在。

$\blacksquare$

**数值**：每天 200 次运行、$p = 0.01$ 时每天约 2 次。在记录 3 次之前，Wilson 区间几乎覆盖 $[0, 1]$，无法区分"偶发"与"常见"。
:::

::: theorem 命题 6.4.6（机制问题的验证成本高于比较问题）
机制问题的验证要求构造一个尚未观测的现象并检验其出现与否。比较问题只需比较既有处理下的响应。因此机制问题的单次验证成本包含"构造新观测"这一项。

**证明.** 比较问题的响应在实际处理下已被产生，验证只是测量与统计。机制问题要求预测一个新现象，而该现象尚未发生，因此需要额外构造产生它的条件。

↓ **为什么能这么写？** 两者的差别在于响应是否已经存在。

$\blacksquare$

**推论**：**机制问题值得做，但要做在已经有最小反例的地方**——反例提供了构造新观测的现成条件。
:::

### 3.3 本节要点

**本节要点**

- 没有事先预期就没有意外（命题 6.4.1）——观测前要写下预期。
- 未排除的已知解释使归因无效（命题 6.4.2）。
- 最小反例把原因范围限制在反例元素内（命题 6.4.3）。
- 转化充分条件三条：有冲突的预期、解释排除到一个、有最小反例（命题 6.4.4）。
- 无记录则频率不可估，"偶发"无依据（命题 6.4.5）。
- 机制问题的验证成本高于比较问题，应做在有反例的地方（命题 6.4.6）。

## 四、【回到直觉】

- **定义 6.4.1 说的**：**观测前把预期写下来**。否则事后会不自觉地"构造"一个预期，把意外降级为显然。
- **定义 6.4.3 说的**：记录字段固定且极简。字段不固定则无法比对，不极简则坚持不下去。
- **命题 6.4.2 说的**：还有一个解释没排除，就不能说"原因是某某"。排除不是论证，是做一次对照。
- **命题 6.4.3 说的**：反例越小，能怀疑的范围越小。把二十步的条件减到三步，这一步减的过程就是在做研究。
- **命题 6.4.4 说的**：转化的三个条件是**可检查的清单**：有预期且冲突、解释只剩一个、有最小反例。
- **命题 6.4.5 说的**：说"偶发"之前先记够三次，否则这个词没有含义。
- **命题 6.4.6 说的**：机制问题更难验证，所以只在有反例的地方做。

**本节要点**

- 观测前写预期。
- 记录字段固定且极简。
- 排除靠对照，不靠论证。
- 缩小反例即在做研究。
- 转化条件是可检查的清单。
- "偶发"需要至少三次记录。
- 机制问题做在有反例处。

## 五、【工具箱】

### 5.1 意外的检测

按定义 6.4.1，检测要求同时有 fact 与 prediction。实现上，预测写成断言，观测后逐条比较：

$$
\text{surprise} = \{a \in \text{assertions} : a.\text{expected} \ne a.\text{observed}\} .
$$

**成本**：预测的书写成本是主要成本，而它必须在观测之前付出。

### 5.2 排除清单

候选解释的三种排除方式：

- **查**：已有知识是否解释它。成本最低，先做。
- **做**：消融或对照是否让现象消失。成本中等，给出因果证据。
- **找反例**：有没有与它预测相反的现成现象。成本最低，但只给否证。

**顺序**：先查、再找反例、最后做。前两者几乎零成本。

### 5.3 反例最小化

从完整条件集开始，逐个尝试移除：

$$
C \leftarrow C \setminus \{c\} \quad \text{若} \quad \lnot\,\mathrm{repro}(C \setminus \{c\}) .
$$

代价是 $O(|C|)$ 次复现尝试。**贪心即可**——最小反例不唯一时，任一个最小集都能给出有界的原因范围（命题 6.4.3）。

### 5.4 复现检验

一个观察值得继续的前提是它能被复现。检验方式是按反例重跑 $n$ 次，报告复现率及其区间（与 6.3 工具箱 5.1 同一方法）。

**数值**：$n = 5$、全部复现时，95% 区间下界约 0.48——**即"五次全复现"只能说明真实复现率高于约 0.57**，不能说"稳定复现"。

### 5.5 记录的三次纪律

按命题 6.4.5，同一现象记满 3 次之前不判断频率。这条纪律的成本是每次一条记录，收益是避免"偶发"这类无依据的判断。

**本节要点**

- 意外检测要求预测先写成断言。
- 排除顺序：先查、再找反例、最后做。
- 反例最小化用贪心，代价 $O(|C|)$。
- 复现检验要报区间：5 次全复现只说明率高于约 0.48。
- 同一现象记满 3 次再判断频率。

### 7.2 记录段：固定字段与极简

记录段的实现要点是**字段固定**与**不做判断**。判断放到整理段。

```js
// 定义 6.4.3：观察记录的固定字段。字段固定才能比对
export const RECORD_FIELDS = ['task', 'config', 'metric', 'before', 'after', 'trials', 'timestamp']

export function validateRecord(r) {
  const missing = RECORD_FIELDS.filter((k) => r[k] === undefined || r[k] === null)
  return { ok: missing.length === 0, missing }
}

// 定义 6.4.1：意外检测要求预测事先写成断言
export function detectSurprises(assertions) {
  return assertions.filter((a) => a.expected !== a.observed)
}
```

### 7.3 整理段：补预期与排频率

整理段做三件事：补上事后仍能确认的预期、合并同类观察、按次数做频率判断。

```js
// 命题 6.4.5：同一现象记满 minTrials 次之前不判断频率
export function frequencyVerdict(records, key, minTrials = 3) {
  const hits = records.filter((r) => r[key] === true).length
  if (hits < minTrials) return { verdict: 'undetermined', hits, reason: `记录 ${hits} 次，不足 ${minTrials} 次` }
  const rate = hits / records.length
  return { verdict: 'estimated', hits, rate }
}

// 定义 6.4.2：异常判定（落在基线的尾部区域）
export function isAnomaly(x, baseline, q = 0.99) {
  const sorted = [...baseline].sort((a, b) => a - b)
  const idx = Math.min(sorted.length - 1, Math.ceil(q * sorted.length) - 1)
  return x > sorted[Math.max(0, idx)]
}
```

### 7.4 转化段：排除与最小化

转化段实现定义 6.4.4 与 6.4.5。

```js
// 定义 6.4.4：排除——若 H 成立则现象应消失，反之现象仍在
export function ruleOut(results) {
  const remaining = results.filter((r) => r.stillPresent).map((r) => r.hypothesis)
  const ruledOut = results.filter((r) => !r.stillPresent).map((r) => r.hypothesis)
  return { remaining, ruledOut, unique: remaining.length === 1 }
}

// 定义 6.4.5 / 工具箱 5.3：贪心最小化反例——逐个尝试移除
export function minimizeRepro(conditions, repro) {
  let c = [...conditions]
  let i = 0
  while (i < c.length) {
    const trial = c.filter((_, k) => k !== i)
    if (repro(trial)) { c = trial } else { i++ }
  }
  return { minimal: c, size: c.length }
}

// 命题 6.4.4：转化三条件
export function canConvert(observation) {
  const checks = {
    surprise: observation.prediction !== undefined && observation.prediction !== observation.fact,
    uniqueExplanation: observation.remaining.length === 1,
    minimalRepro: Array.isArray(observation.minimalRepro) && observation.minimalRepro.length > 0,
  }
  return { ok: checks.surprise && checks.uniqueExplanation && checks.minimalRepro, checks }
}

// 定义 6.4.6：两类问题的判别——答案是否指向一个可预测的新现象
export function classifyQuestion(question) {
  return question.predictsNewPhenomenon ? 'mechanism' : 'comparison'
}
```

### 7.5 复现率的区间

按工具箱 5.4，复现率要连区间一起报。

```js
// 工具箱 5.4：Wilson 区间（与 6.3 同一方法）
export function wilson(successes, n, z = 1.96) {
  const p = successes / n
  const z2 = z * z
  const denom = 1 + z2 / n
  const center = (p + z2 / (2 * n)) / denom
  const half = (z / denom) * Math.sqrt((p * (1 - p)) / n + z2 / (4 * n * n))
  return { p, lo: center - half, hi: center + half }
}
```

### 9.2 失败模式

**（1）检查放在装载期（L9 位置放错）。** 预期在观测**之后**补写。表现是"回顾时觉得一切都在预料之中"，意外被系统性地降级为显然。修正：预期必须写在观测之前，并在记录里保留书写时刻。

**（2）前提会变（L9）。** 命题 6.4.3 的最小性以"复现函数 $\mathrm{repro}$ 稳定"为前提。环境变化后（任务集换版、依赖升级），原反例可能不再复现，最小性失效。修正：反例要与它依赖的环境版本一起记录。

**（3）不记录。** 说"偶发"而没有频率依据。

**（4）记录字段不固定。** 两次记录无法比对，等于没记。

**（5）记录时做价值判断。** 当时看不出价值的现象被丢掉，而它可能正是关键。

**（6）候选解释未排除就归因。** 结论是相关性而不是因果。

**（7）反例未最小化。** 原因范围过宽，无法定位。

**（8）把 5 次全复现当"稳定复现"。** 区间下界只有 0.566。

**（9）局部修补后不追因。** 同一原因在别处再现为不同现象。

**（10）机制问题与比较问题混写。** 两种验证方式冲突，问题推不动。

**本节要点**

- 决策表覆盖 11 种情形。
- 失败模式十条，前两条是位置放错与前提会变。
- 最隐蔽的是"观测后补写预期"——它系统性地消灭意外。

## 十、仍未解决

- **预期的事前性。** 要求预测在观测前写下，而很多现象是在无预期的探索中出现的。这类"无预期观测"如何处理，缺少统一做法。
- **排除的完备性。** 候选解释集合是否完整无法自证——没被想到的解释不会被排除。
- **最小反例的非唯一性。** 多个最小集可能给出不同的原因范围，而贪心只给其中一个。
- **复现率的判定门槛。** "多高算稳定复现"缺少依据，取决于后续用途。
- **记录成本与信息量的权衡。** 字段越多信息越全，而记录成本上升会降低记录率。
- **跨环境的反例迁移。** 一个环境里的最小反例在另一环境是否仍最小，取决于两环境的差异。

**本节要点**

- 无预期观测的处理缺少统一做法。
- 候选解释集合的完整性无法自证。
- 多个最小反例给出不同范围。
- 复现率的门槛缺少依据。
- 字段数与记录率存在权衡。
- 反例的跨环境迁移性未定。
