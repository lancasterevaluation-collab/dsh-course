## 本篇新词

- 开放问题（open question） 指尚无公认答案、但有一个可执行的判别程序的问题。只有未知而没有判别程序的，不是开放问题，是话题。
- 三要素（three elements） 指一个研究问题的三个组成：因变量（观测什么）、自变量（改变什么）、测量手段（怎么观测）。
- 可回答性（answerability） 指存在一个有限成本的测量程序，能对问题给出肯定或否定的证据。它不等于"容易回答"。
- 测量手段（measurement instrument） 指把现象变成数值的装置与协议。它是研究中最稀缺的一环，因为因变量的选择范围受它限制。
- 问题分解（decomposition） 指把一个不可直接回答的问题拆成一组可直接回答的子问题。分解是选题工作的主要形态。
- 信息量（information gain） 指回答一个问题后观测者不确定性的减少量。已经高度确信的问题，回答后信息量小。
- 清单时效（list expiry） 指问题清单会因测量手段的进步而改变：原本不可回答的变成可回答，原本有价值的变成常识。
- 负面结果（negative result） 指否证型回答。它与肯定型回答具有同等的判别价值，但发表阻力更大。

## 一、【设计原因】

### 1.1 缺陷一：有经验而提不出问题

在工程里做久了，人会积累大量"感觉这里不对"的判断，却提不出一个能被检验的问题。

原因是缺因变量：感觉对应的是整体印象，而研究问题要求一个可以取值的量。把"感觉不清爽"变成问题，第一步是找出哪个量在变。

### 1.2 缺陷二：问题听起来重要而无法回答

反方向的失效同样常见。"agent 会不会真正理解意图"这类表述有分量，但它没有判别程序——没有人能说出"理解"在这个语境下对应哪个可观测的量。

它的问题不是难，而是没有终点。 研究投入这类问题会得到持续的讨论而没有可积累的结果。

### 1.3 缺陷三：同一个问题被反复讨论而没有进展

一个问题被讨论了三年，论文很多，而结论没有收敛。这通常意味着每次讨论都换了一个因变量：有人用任务成功率，有人用人工评分，有人用延迟。三者的结论都"对"，但不可比。

因变量不统一，讨论就无法收敛。

### 1.4 缺陷四：把工程问题当成开放问题

"怎么让工具调用更可靠"是一个工程问题——它有明确的目标、可测的结果、已知的手段。把它当研究问题去做，会得到一篇把已知手段重新包装的论文。

工程问题与研究问题的分界是可判定的：前者有已知的解法空间，后者没有。

### 1.5 由此确定的设计目标

1. 问题必须有判别程序：没有可观测的判别标准，不算开放问题。
2. 三要素必须齐备：因变量、自变量、测量手段缺一不可。
3. 因变量要统一：同一个问题下不同工作必须用同一个量。
4. 分解是主要工作：不可直接回答的问题要拆到可回答为止。

**本节要点**

- 提不出问题通常是缺因变量，不是缺经验。
- 没有判别程序的问题不是难点，而是没有终点。
- 讨论不收敛的原因通常是因变量不统一。
- 工程问题与研究问题的分界是可判定的。
- 四条目标：有判别程序、三要素齐备、因变量统一、分解到可回答。

## 二、【直觉】

### 2.1 侦探与取证

侦探的结论（"是他做的"）本身不是一个可回答的问题，因为它没有证据形式。真正可回答的是它的分解：他在案发时间在哪里、他的指纹为什么在凶器上、他账户里那笔钱从哪来。

每一条都有取证手段：监控、指纹、银行流水。而没有取证手段的怀疑就不能立案——不是因为它不重要，而是因为它无法推进。

研究问题的处境与此相同：测量手段决定哪些问题在当前阶段能被提出。

### 2.2 秤与重量

想比较两个物体的重量，前提是有秤。在没有秤的年代，"哪个更重"只能在明显差异时被回答。差异不大时，它退化成争论。

这条直观给出一个不太显然的推论：测量精度的提升会一次性打开一批问题。 当秤的精度从"克"到"毫克"，原本无法回答的"这两种合金哪个更耐磨"变成了可回答的。

::: keypoint 反直觉点
**选题的瓶颈通常不在想法，而在测量。** 同一个想法在测量手段出现之前是不可回答的，出现之后可能在一周内被回答。所以判断一个方向是否"到时候了"，先看它依赖的测量手段是否已经存在。
:::

### 2.3 一个数字直觉

设两个候选问题，各自的判别结果只有两种取值。

- 问题 A：领域内的共识概率是 0.5（完全不确定）。
- 问题 B：共识概率是 0.95（基本已经知道）。

回答后的信息量按 $\log_2(1/p)$ 计：A 是 1 比特，B 是约 0.07 比特。

同一个"重要"的题目，如果答案已经基本确定，它能带来的信息量小一个数量级以上。 选题时要问的不是"它重要吗"，而是"它还可能不是这样吗"。

**本节要点**

- 没有取证手段的怀疑不能立案。测量手段决定哪些问题能被提出。
- 测量精度的提升会一次性打开一批问题。
- 选题瓶颈通常在测量而不是想法。
- 选题目要问"它还可能不是这样吗"，而不是"它重要吗"。

## 三、【严格】

### 3.1 定义

::: theorem 定义 6.1.1（问题的判别程序）
一个**开放问题**是二元组 $Q = (S, \Delta)$：$S$ 是问题的表述，$\Delta$ 是**判别程序**——一个把有限次观测映射到 $\{\text{支持}, \text{否证}, \text{不确定}\}$ 的过程。

只有表述而没有 $\Delta$ 的，称为**话题**，不属于本篇讨论范围。
:::

::: theorem 定义 6.1.2（三要素）
研究问题 $Q$ 的**三要素**为

$$
Q = (Y, X, M),
$$

其中 $Y$ 是因变量（被观测、取值的量），$X$ 是自变量（被改变或被分层比较的量），$M$ 是测量手段（把现象变成 $Y$ 的取值的过程）。

**缺任何一项**：缺 $Y$ 则无法判别，缺 $X$ 则无从比较，缺 $M$ 则 $Y$ 不可得。
:::

::: theorem 定义 6.1.3（可回答性）
问题 $Q$ 在资源预算 $B$ 下**可回答**，当且仅当存在一个使用 $M$ 的观测程序，其代价不超过 $B$，且该程序的输出能被 $\Delta$ 映射到"支持"或"否证"。

记作 $\mathrm{Ans}(Q, B) = \text{true}$。**注意可回答性依赖预算**：同一问题在小预算下不可回答，在大预算下可能可回答。
:::

::: theorem 定义 6.1.4（问题分解）
问题 $Q$ 的**分解**是一组子问题 $\{Q_1, \dots, Q_n\}$ 满足：子问题的判别结果合起来蕴含 $Q$ 的判别结果。

分解**不是**把 $Q$ 在字面上拆成短句，而是要求子问题的结论能合成父问题的结论。
:::

::: theorem 定义 6.1.5（信息量）
设问题 $Q$ 在回答前对某假设 $H$ 的先验概率为 $p$。一次观测 $o$ 带来的**信息量**为

$$
I(o) = \log_2 \frac{\Pr[o \mid H = 1]}{\Pr[o]},
$$

当观测使 $H$ 成为确定时，$I = \log_2(1/p)$。反过来，若观测使 $H$ 被否证，$I = \log_2(1/(1-p))$。
:::

::: theorem 定义 6.1.6（清单时效）
问题 $Q$ 在时刻 $t$ **有效**，当且仅当 $\mathrm{Ans}(Q, B_t) = \text{true}$ 且 $Q$ 的信息量大于阈值 $\iota$。

其中 $B_t$ 是时刻 $t$ 可用的测量手段与预算。时效的两种失效形式：**手段到位使原本不可回答的变可回答**（从无效变有效），以及**共识确立使信息量降到阈值以下**（从有效变无效）。
:::

### 3.2 命题

::: theorem 命题 6.1.1（因变量不可测量则不可回答）
若问题 $Q$ 的因变量 $Y$ 在预算 $B$ 下不可测，则 $\mathrm{Ans}(Q, B) = \text{false}$。

**证明.** 判别程序 $\Delta$ 的输入是观测结果，而观测结果的具体形式是 $Y$ 的取值。若 $Y$ 不可测，则 $\Delta$ 的输入不可得，$\Delta$ 无法输出"支持"或"否证"。按定义 6.1.3，$Q$ 不可回答。

↓ **为什么能这么写？** 判别程序的输入必然来自某种观测，而观测的对象正是因变量。

$\blacksquare$

::: keypoint 这条结论的用法
**遇到无法推进的题目时，先查因变量能不能测，而不是继续讨论它重不重要。** 如果 $Y$ 不可测，唯一的推进方式是先做出测量手段——那本身是一个工程任务，应当单列，而不是混在研究提问里。
:::
:::

::: theorem 命题 6.1.2（可提出的问题集合受测量手段限制）
设时刻 $t$ 可用的测量手段集合为 $\mathcal{M}_t$。则在该时刻可回答的问题集合满足

$$
\mathcal{Q}_t \subseteq \{Q : Y(Q) \in \mathrm{Measurable}(\mathcal{M}_t)\} .
$$

**证明.** 由命题 6.1.1，$Y$ 不可测则 $Q$ 不可回答。故可回答的问题，其因变量必然落在测量手段能覆盖的范围内。取补集为空集，得包含关系。

↓ **为什么能这么写？** 这是命题 6.1.1 的逆否命题按集合写出来的形式。

$\blacksquare$

**推论**：$\mathcal{M}$ 扩张（新测量手段出现）时 $\mathcal{Q}$ 随之扩张——这解释了为什么某些领域会"突然"出现一批成果：不是想法变新了，是测量手段到位了。
:::

::: theorem 命题 6.1.3（分解的充分性）
若 $Q$ 分解为 $\{Q_1, \dots, Q_n\}$ 且每个子问题可回答，则 $Q$ 可回答。

**证明.** 依次执行各子问题的判别程序，得到一组结论。由定义 6.1.4，这组结论蕴含 $Q$ 的判别结果。总代价为各子问题代价之和，因此存在一个不超过该和的程序回答 $Q$。

↓ **为什么能这么写？** 分解的定义保证了结论可合成，而可回答性只要求程序存在。

$\blacksquare$

::: keypoint 充分但非必要
**子问题都可回答是父问题可回答的充分条件，不是必要条件。** 存在父问题可回答而某个子问题不可回答的情形（该子问题可从其他子问题推出）。因此分解不必覆盖全部细节，只需要覆盖**判别所需的那部分**。
:::
:::

::: theorem 命题 6.1.4（信息量随先验概率单调减）
设观测使假设 $H$ 成为确定，则信息量 $I = \log_2(1/p)$ 随先验 $p$ 单调递减。当 $p \to 1$ 时 $I \to 0$。

**证明.** $\log_2(1/p) = -\log_2 p$，而 $-\log_2 p$ 在 $(0,1)$ 上随 $p$ 单调递减。当 $p \to 1$ 时 $-\log_2 p \to 0$。

↓ **为什么能这么写？** 对数函数的单调性直接给出结论。

$\blacksquare$

**数值**：$p = 0.5$ 时 $I = 1$ 比特。$p = 0.95$ 时 $I \approx 0.074$ 比特。$p = 0.99$ 时 $I \approx 0.0145$ 比特。**先验 0.95 与 0.5 的信息量相差约 13.5 倍。**

::: keypoint 选题的直接推论
**先问"这个结论有没有可能不成立"，再问"它重不重要"。** 一个已被普遍相信的结论，即使重要，回答它也带不来多少信息。反之，一个领域内分歧很大的问题，即使看起来琐碎，信息量也高。
:::
:::

::: theorem 命题 6.1.5（负面结果的信息量与肯定结果对称）
若观测否证 $H$（先验 $p$），则 $I_{\text{neg}} = \log_2(1/(1-p))$。当 $p = 0.5$ 时两者相等。

**证明.** 否证即观测到 $\lnot H$，其先验为 $1-p$，代入定义 6.1.5 得 $I_{\text{neg}} = \log_2(1/(1-p))$。$p = 0.5$ 时 $1/(1-p) = 2 = 1/p$，故两者相等。

↓ **为什么能这么写？** 定义 6.1.5 对"成为确定"的两个方向对称。

$\blacksquare$

::: keypoint 发表阻力不是判别价值的度量
**否证一个被广泛相信的结论，其信息量往往高于再确认它一遍**（因为后者先验高）。而现实中前者的发表阻力更大。做选择时，应当按信息量排序，而不是按"好不好发"排序。
:::
:::

::: theorem 命题 6.1.6（清单会因手段到位而重排）
设新测量手段 $m \notin \mathcal{M}_t$ 出现。则原本因 $Y$ 不可测而无效的问题可能变为有效，从而改变清单的排序。

**证明.** 记 $Q$ 的因变量 $Y(Q) \in \mathrm{Measurable}(\{m\}) \setminus \mathrm{Measurable}(\mathcal{M}_t)$。由命题 6.1.1，$Q$ 在 $t$ 不可回答。加入 $m$ 后 $Y$ 可测，若代价在预算内则 $Q$ 变为可回答。

可回答性的改变使 $\mathrm{Ans}$ 取值改变，而清单按可回答性与信息量排序，故排序可能改变。

↓ **为什么能这么写？** 清单的排序键包含可回答性，该键发生变化则排序变化。

$\blacksquare$

**推论**：清单需要定期重排，而不是一次定稿。重排的触发事件是"新测量手段出现"，而不是"想到新点子"。
:::

### 3.3 本节要点

**本节要点**

- 开放问题必须有判别程序。没有判别程序的是话题（定义 6.1.1）。
- 三要素缺一不可：因变量、自变量、测量手段（定义 6.1.2）。
- 因变量不可测则问题不可回答（命题 6.1.1）。
- 可提出的问题集合受测量手段限制，手段扩张则问题集合扩张（命题 6.1.2）。
- 子问题可回答是父问题可回答的充分条件（命题 6.1.3）。
- 信息量随先验概率单调减，先验 0.95 时只有 0.074 比特（命题 6.1.4）。
- 负面结果与肯定结果的信息量对称（命题 6.1.5）。
- 清单会因测量手段到位而重排，需要定期更新（命题 6.1.6）。

## 四、【回到直觉】

- 定义 6.1.1 说的：先把判别程序写出来。"这个方向很重要"不是问题，因为没人能说出什么结果会让它被否证。
- 定义 6.1.2 说的：写问题的时候把三要素写全——观测什么、改变什么、怎么观测。缺哪一项就补哪一项，而不是先动手。
- 命题 6.1.1 说的：推进不下去时先查因变量能不能测，不要继续讨论重要性。
- 命题 6.1.2 说的：判断一个方向是否"到时候了"，看它依赖的测量手段是否已经存在。
- 命题 6.1.3 说的：分解到"判别所需的那部分"为止，不必覆盖全部细节。
- 命题 6.1.4 说的：先问"它还可能不是这样吗"。共识度 0.95 的题目，回答它的信息量比五五开的题目小一个数量级以上。
- 命题 6.1.5 说的：否证被广泛相信的结论，信息量往往更高，尽管发表阻力更大。按信息量排序，不按好不好发排序。
- 命题 6.1.6 说的：清单不是一次定稿的。新测量手段出现时重排一次。

**本节要点**

- 先写出判别程序，再判断问题价值。
- 三要素写全再动手。
- 推进不下去先查因变量。
- 判断方向看测量手段是否到位。
- 分解到判别所需为止。
- 按"是否可能不成立"选题。
- 按信息量排序，不按发表阻力。
- 清单随测量手段更新。

## 五、【工具箱】

### 5.1 信息量的计算

$I = -\log_2 p$（肯定）或 $I = -\log_2(1-p)$（否证）。混合情形用期望信息量

$$
\mathbb{E}[I] = -p \log_2 p - (1-p)\log_2(1-p),
$$

即二元熵，它在 $p = 0.5$ 时取最大值 1 比特。

用途：比较候选问题的上限。注意这里是上限——实际得到的信息量还取决于实验能分辨多小的差异。

### 5.2 分解的检验

分解是否成立，检验方式是把子问题的结论当作前提，推导父问题的结论。推得出来则分解成立。

最常见的分解错误：子问题只覆盖了父问题的一部分，剩下部分无人负责。检验方法是逐条问"这条结论对父问题的判别贡献了什么"。

### 5.3 测量手段的覆盖率

给定清单 $\mathcal{Q}$ 与手段集 $\mathcal{M}$，覆盖率定义为因变量落在 $\mathcal{M}$ 覆盖范围内的问题占比：

$$
\mathrm{cov} = \frac{\lvert\{Q \in \mathcal{Q} : Y(Q) \in \mathrm{Measurable}(\mathcal{M})\}\rvert}{\lvert\mathcal{Q}\rvert} .
$$

用途：覆盖率低说明清单里大量问题当前无法回答，应当先把它们移到"需要先做测量"的分组，而不是留在待研究清单里。

### 5.4 可分辨差异与样本量

即使因变量可测，能分辨多小的差异由样本量决定（与 6.3 工具箱 5.2 同一公式）。

这条限制了信息量的实际值：一个理论上信息量很高的问题，若实验只能分辨 10 个点的差异，实际能提取的信息量就被截断在"能否区分 10 个点"这一档。

### 5.5 清单的维护周期

按命题 6.1.6，重排的触发条件是"新测量手段出现"，而不是固定周期。可行的做法是维护一张手段清单与一张问题清单，并在手段增加时检查哪些问题的因变量因此变得可测。

**本节要点**

- 信息量公式与二元熵给出问题的上限。
- 分解要用"子结论能否推出父结论"来检验。
- 覆盖率低时先把问题移到"需要先做测量"分组。
- 实验的可分辨差异会截断实际信息量。
- 清单重排由手段清单的变化触发。

## 七、施工图与算例

### 7.1 三段结构

| 段 | 职责 | 关键约束 |
|---|---|---|
| 校验段 | 检查问题的三要素与判别程序 | 缺项直接拒绝，不做"先做着看" |
| 排序段 | 按可回答性与信息量排序 | 排序键要显式，不靠直觉 |
| 维护段 | 手段变化时重排 | 由手段清单的变化触发 |

### 7.2 校验段：三要素齐备才入库

校验段拒绝缺项的问题。拒绝而不是标记"待补充"——待补充的条目会一直留在清单里，使清单失去"可执行"的含义。

```js
// 校验三要素与判别程序：缺任何一项即拒绝入库（定义 6.1.1、6.1.2）
export function validate(question) {
  const missing = []
  if (!question.dependent) missing.push('因变量')
  if (!question.independent) missing.push('自变量')
  if (!question.instrument) missing.push('测量手段')
  if (typeof question.decide !== 'function') missing.push('判别程序')
  return { ok: missing.length === 0, missing }
}

// 可回答性：因变量在手段集覆盖范围内，且预算允许（定义 6.1.3）
export function answerable(question, instruments, budget) {
  if (!question.instrument || !instruments.includes(question.instrument)) return false
  return question.cost <= budget
}
```

### 7.3 排序段：显式的排序键

排序键是信息量上界与可回答性的组合。写成函数，不靠印象。

```js
// 信息量：肯定方向为 -log2(p)，否证方向为 -log2(1-p)（定义 6.1.5）
export function informationGain(p, observed = 'support') {
  if (observed === 'support') return -Math.log2(p)
  return -Math.log2(1 - p)
}

// 二元熵：p=0.5 时取最大值 1 比特（工具箱 5.1）
export function binaryEntropy(p) {
  if (p <= 0 || p >= 1) return 0
  return -p * Math.log2(p) - (1 - p) * Math.log2(1 - p)
}

// 排序键：不可回答的排最后，其余按信息量上界降序（7.3）
export function rank(questions, instruments, budget, priorOf = () => 0.5) {
  return [...questions].sort((a, b) => {
    const ra = answerable(a, instruments, budget) ? 1 : 0
    const rb = answerable(b, instruments, budget) ? 1 : 0
    if (ra !== rb) return rb - ra
    return binaryEntropy(priorOf(b)) - binaryEntropy(priorOf(a))
  })
}
```

### 7.4 维护段：手段变化的触发

维护段维护两张清单，并在手段清单增长时检查问题清单。

```js
// 覆盖率：因变量落在手段集范围内的问题占比（工具箱 5.3）
export function coverage(questions, instruments) {
  if (questions.length === 0) return 1
  const covered = questions.filter((q) => instruments.includes(q.instrument)).length
  return covered / questions.length
}

// 时效：手段到位使原本不可回答的变可回答，或信息量降到阈值以下（定义 6.1.6）
export function classify(question, instruments, budget, prior, iota = 0.1) {
  if (!answerable(question, instruments, budget)) return 'blocked-by-instrument'
  if (binaryEntropy(prior) < iota) return 'settled'
  return 'active'
}
```

`blocked-by-instrument` 这一档是清单维护的关键输出：它直接告诉你要先做哪个测量手段。

### 7.5 分解

分解的检验是"子结论能否推出父结论"。下面的实现只做结构检查（子问题集非空、每个子问题自身合法），语义上的蕴含关系仍需人工确认。

```js
// 分解的结构检查：子问题集非空且每个子问题自身合法（定义 6.1.4）
export function decompose(question, subquestions) {
  const invalid = subquestions.map(validate).filter((r) => !r.ok)
  return {
    ok: subquestions.length > 0 && invalid.length === 0,
    count: subquestions.length,
    invalid,
  }
}
```

### 7.6 算例的用法

下面的接口可以直接导入使用。参数与返回值见各函数的文档注释。

```js
import { validate, answerable, informationGain, binaryEntropy, rank, coverage, classify } from './sa12_openq.mjs'

validate({ dependent: '任务成功率', independent: '压缩阈值', instrument: 'bench-v1', decide: () => 'support' }).ok
binaryEntropy(0.5)          // 1 —— 上限
informationGain(0.95)       // 约 0.074 —— 共识度高则信息量小
coverage(questions, ['bench-v1'])   // 覆盖率
classify(q, instruments, budget, 0.99)  // 'settled'
```

`examples/test_sa12_openq.mjs` 对每个函数做断言。

**本节要点**

- 三段：校验、排序、维护。
- 校验拒绝缺项，不做"待补充"。
- 排序键显式写出，包含可回答性与信息量。
- 维护由手段清单变化触发。
- `blocked-by-instrument` 直接指出要先做哪个测量手段。

### 9.2 失败模式

- （1）检查放在装载期（L9 位置放错）。 可回答性的判定在选题时做了一次，此后测量手段进步了而清单没更新。表现是"清单里还留着已经能回答的问题，而新出现的机会没被认出来"。修正：把重排绑定到手段清单的变化上。

- （2）前提会变（L9）。 命题 6.1.3 的分解充分性以"子结论能推出父结论"为前提。实验条件变化后（例如任务集换版），原子问题的结论可能不再蕴含父结论。修正：分解要与它所依赖的实验条件一起记录。

- （3）只有表述没有判别程序。 问题无法推进，讨论不断而结论不收敛。

- （4）缺因变量。 交付物变成"某种机制"，而"它好不好"无从判断。

- （5）因变量不统一。 同一问题的不同工作结论不可比。

- （6）把工程问题当研究问题。 解法空间已知的问题被重新包装成论文。

- （7）只按重要性排序。 忽略信息量，导致选题集中在共识度高的地方。

- （8）分解只覆盖一部分。 剩下的部分无人负责，父问题实际无法回答。

- （9）忽略可分辨差异。 理论上信息量高的问题，实际只能区分粗差异。

- （10）清单一次定稿。 手段进步后清单过期，而没人负责重排。

**本节要点**

- 决策表覆盖 11 种情形。
- 失败模式十条，前两条是位置放错与前提会变。
- 最隐蔽的是"分解只覆盖一部分"——它使父问题看起来已有安排。

## 十、仍未解决

- 先验概率的估计。 按信息量排序需要先验 $p$，而它通常只能主观给出，且估计误差会直接影响排序。
- 分解的自动检验。 目前只能做结构检查，"子结论是否蕴含父结论"依赖人工确认。
- 测量手段的分类。 "可测"是一个程度概念，用二值判定会丢掉精度信息。
- 跨领域的信息量可比性。 不同领域的一比特是否等价，缺少公认基准。
- 清单的规模化维护。 手段与问题两张清单的交叉检查在条目多时成本上升。
- 负面结果的可发表性。 信息量与发表阻力不一致，这一结构性因素不因方法改进而消失。

**本节要点**

- 先验只能主观估计，误差会传递到排序。
- 分解的语义检验无法自动完成。
- 可测性是程度概念，二值判定丢信息。
- 跨领域的信息量缺少可比基准。
- 清单规模化维护成本上升。
- 负面结果的可发表性是结构性因素。
