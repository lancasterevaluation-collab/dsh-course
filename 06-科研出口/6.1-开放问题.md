## 读完这一篇你会知道什么

1. **三要素**：算例里缺"测量手段"或"判别程序"都会报错。
2. 可回答性的两个条件：手段可用（`true`）且预算足够。缺手段或预算不足都判为不可回答（`false`）。
3. 信息量：算例里 $p = 0.50$ 时肯定得到 1.0000，$p = 0.95$ 时肯定只有 0.0740，而 $p = 0.95$ 时否证得到 4.3219。
4. 比值：0.50 与 0.95 的信息量之比是 13.51 倍。
5. 熵：算例里二元熵在 $p = 0.5$ 时是 1.0000，$p = 0.95$ 时降到 0.2864。
6. 覆盖率：算例里只有一种手段时覆盖率是 0.667。
7. 工业界怎么做：技术雷达、研究立项、可证伪的立项标准。
8. 学术界：可证伪性、信息论、以及"好问题"的判据。

## 一、为什么"没人做过"不等于"值得做"

### 1.1 问题是空的

"agent 能不能更聪明？"——**它没有测量手段，也没有判别程序，所以永远不会有答案。**

### 1.2 手段不可用

"长期记忆对任务成功率有多大影响？"——**但你没有测量成功率的基准，也没有能跑足够次数的预算。**

### 1.3 做什么都无关紧要

"我们能不能把通过率从 98% 提到 99%？"——**即使成功，也不改变任何决策。**

这三件事分别对应：**三要素齐备、可回答性、信息量。**

## 二、可回答性的三个前提

| 前提 | 回答 | 缺了会怎样 |
|---|---|---|
| **测量手段** | 用什么量它 | 得不到数字 |
| **判别程序** | 什么结果算"是" | 有数字也无法判断 |
| **预算** | 做多少次付得起 | 结论不可靠 |

**三个前提缺一不可**。而且前两个是"结构性"的（齐备或不齐备），第三个是"定量"的（够不够）。

## 三、怎么做

### 3.1 三要素校验

实现如下。

```js
// 问题校验：三要素齐备才是一个可研究的问题
export function validateQuestion(question) {
  const required = ['测量手段', '判别程序', '预算']
  return required.filter((key) => !question[key])
}
```

算例实测：

| 情况 | 结果 |
|---|---|
| 齐备 | **`true`** |
| 缺测量手段 | **`["测量手段"]`** |
| 缺判别程序 | **`["判别程序"]`** |

**注意输出是"缺哪些"的清单**（与 1.4 的契约校验同一个形式）：它可执行——照着补就行。

"判别程序"是最容易被漏的一项：**它必须写清楚"什么样的结果算支持假设，什么样的算否定"**。没有它，实验做完也不知道结论。

这与 4.4 的"预期结果"是同一件事：**判别程序就是研究层面的预期结果。**

### 3.2 可回答性

算例实测：

| 情况 | 可回答 |
|---|---|
| 手段可用、预算足够 | **`true`** |
| 手段缺失 | **`false`** |
| 预算不足 | **`false`** |

"手段缺失"与"预算不足"是两种不同的不可回答：

| 类型 | 含义 | 处理 |
|---|---|---|
| **手段缺失** | 目前无法测量 | 先做测量工具（这是另一项研究） |
| **预算不足** | 原则上可测，但做不起 | 或者缩小问题，或者等（成本下降） |

区分的价值：**手段缺失是"换一个问题"，预算不足是"缩小或等待"。** 把两者混为一谈会导致错误决策。

### 3.3 信息量

这是本篇最有价值的一节。**一个假设被证实或被否定，带来的信息量取决于它原本的可能性。**

$$
I = -\log_2 P(\text{结果})
$$

算例给出的四个数字：

| 假设的先验 | 结果 | 信息量 |
|---|---|---|
| $p = 0.50$ | 肯定 | **1.0000** |
| $p = 0.95$ | 肯定 | **0.0740** |
| $p = 0.99$ | 肯定 | **0.0145** |
| **$p = 0.95$** | **否证** | **4.3219** |

三个关键读法：

1. **"我早就知道会这样"的验证价值极低**：$p = 0.95$ 被证实的贡献是 0.074，只有真正不确定的问题（$p = 0.5$，贡献 1.0）的 1/13.5。
2. "推翻一个被广泛相信的东西"价值极高：$p = 0.95$ 被否证带来 4.32——比 50/50 问题被证实还高 4 倍多。
3. 算例验证的比值是 13.51 倍：同样一个假设，两种可能结果的信息量差一个数量级。

这条结论直接改变选题方式：

| 选题 | 信息量 | 评价 |
|---|---|---|
| 验证一个大家都同意的做法 | 低 | 消耗预算，不改变认知 |
| **挑战一个被广泛相信但没被严格验证的做法** | **高** | 最有价值的选题 |
| 探索一个完全未知的方向 | 高 | 有价值，但需要手段 |
| 微调一个已经很好的指标 | 低 | 除非它影响决策 |

"挑战通行做法"这一行是最值得追求的：**它的信息来源不是"没人做过"，而是"大家都这么做但从没人验证过"**（这正是 6.4 的"意外"要捕捉的东西）。

### 3.4 覆盖率

一个问题往往需要多种测量手段。**覆盖率衡量"现有手段能回答这个问题的多少部分"。**

算例实测：**手段只有 `bench-v1` 时，覆盖率是 0.667**。

读法：**三分之二的问题可以用现有手段回答，剩下三分之一不能。** 这个数字告诉你：

| 覆盖率 | 含义 | 处理 |
|---|---|---|
| 1.0 | 手段齐备 | 直接做 |
| **0.5–0.9** | 部分可回答 | **缩小问题范围，或先补手段** |
| 接近 0 | 手段缺失 | 换问题 |

"缩小问题范围"是最实用的做法：**把问题限制在现有手段能覆盖的部分**。这比"等有了手段再做"更实际。

注意覆盖率与"部分可回答"的区别：**一个 0.667 覆盖率的问题，其结论也是部分的**——必须在报告里说明覆盖范围，否则会被误读为完整结论。

### 3.5 问题排序

把前面的量组合起来，可以得到一个排序依据：

$$
\text{优先级} \approx \text{信息量} \times \text{可回答性} \times \text{覆盖率}
$$

注意"可回答性"是 0/1 的因子：**不可回答的问题，信息量再高也是 0 优先级**。

排序的实践做法：

| 步骤 | 动作 |
|---|---|
| 1 | 先筛掉不可回答的（手段或预算不够） |
| 2 | 剩下的按信息量排序 |
| 3 | 用覆盖率标注"结论的完整程度" |
| 4 | 取覆盖率高的先做 |

"先筛掉"这一步不要跳过：**一个不可回答的高价值问题看起来很有吸引力**，而它永远不会有结论。

## 四、特殊情况与处理技巧

| 情况 | 为什么 | 处理 |
|---|---|---|
| 问题永远没有答案 | 缺判别程序 | 先写清"什么算支持" |
| 实验做完不知结论 | 判别程序缺失 | 与 4.4 的预期结果对齐 |
| 测量不了 | 手段缺失 | 换问题，或先做测量工具 |
| 做不起 | 预算不足 | 缩小范围或等成本下降 |
| 结论不重要 | 信息量低 | 换一个不确定度更高的问题 |
| 结论只覆盖一部分 | 覆盖率低 | 报告里明确覆盖范围 |
| 挑战了通行做法但无人信 | 证据强度不足 | 提高证据强度（见 4.4） |
| 问题太大 | 无法一次回答 | 分解成可回答的子问题 |

最后一条值得展开：**大问题要分解，但分解后的子问题可能各自"可回答但不重要"。** 所以分解时要保持"每个子问题的结论都改变某个决策"。

## 五、工业界的做法（可照做）

### 5.1 研究立项的实践

| 实践 | 做法 | 值得学的点 |
|---|---|---|
| **技术雷达** | 把技术分为采纳/试验/评估/暂缓 | 明确"现在做什么" |
| **研究立项** | 写立项书（问题、假设、方法、判据） | **判据必须在做之前写** |
| **RFC** | 公开讨论技术决策 | 结论留档 |
| **预注册** | 实验前登记假设与分析计划 | **防止事后编故事** |

"预注册"值得重点推荐：**在做实验之前写下假设、测量方式、判别程序**。它的价值是防止"看到结果再编假设"（这正是 6.4 的"意外"与"事后解释"的区分依据）。

**没有预注册时，人往往会把任何结果都解释成支持自己的假设**——判别程序在事后写，总可以写得刚好通过。

### 5.2 什么值得立项

一条在实践中反复验证的判据：

| 判据 | 说明 |
|---|---|
| **结论会改变决策** | 否则不做 |
| **有可用的测量手段** | 否则换问题 |
| **结果有不确定性** | 否则不用做 |
| **能在一个周期内完成** | 否则分解 |

"结论会改变决策"是第一条：**它比"有意思"重要得多。** 一个有趣但不改变任何决策的结论，对工程系统没有价值。

这与 1.1 的"判据"是同一个要求：**先能回答"怎么知道做成了"，再动手。**

### 5.3 参数与设计起点

| 参数 | 推荐 | 依据 |
|---|---|---|
| 三要素 | 全部齐备 | 缺一不可 |
| 信息量门槛 | 大于 0.5 | 低于此不值得单独立项 |
| 覆盖率门槛 | 大于 0.8 | 低于此需说明局限 |
| 预算 | 按样本量公式算（见 6.2） | 不是拍脑袋 |
| 预注册 | 必做 | 防止事后解释 |

### 5.4 一份可落地的实施清单

1. **三要素**：测量手段、判别程序、预算。
2. 判别程序前置：做实验前写清"什么算支持"。
3. 可回答性判定：区分"手段缺失"与"预算不足"。
4. 信息量估计：先估假设的先验，算两种结果的信息量。
5. 优先级：先筛不可回答的，再按信息量排。
6. 覆盖率：标注结论能覆盖多少。
7. 预注册：假设与方法先登记。
8. 决策关联：写清"结论会改变哪个决策"。
9. 分解：大问题拆成"各自都影响决策"的子问题。
10. 记录：问题、方法、结论、局限一起留档。

## 六、学术界的结论

### 6.1 可证伪性

Popper 提出的**可证伪性**是科学命题的判据：

> **一个命题是科学的，当且仅当存在可能的观察能反驳它。**

它对研究的直接含义：**"agent 能不能更聪明"不可证伪**（没有任何观察能反驳它），而"缓存命中率提升 10% 能让端到端延迟下降 5%"可证伪。

可证伪性正是 3.1 的"判别程序"的哲学基础：**写不出判别程序 = 不可证伪 = 不可研究。**

一条实用的改造方法：**把不可证伪的问题改写成可证伪的**。

| 不可证伪 | 可证伪 |
|---|---|
| "记忆有用吗" | "打开记忆后，X 类任务成功率提升多少" |
| "多智能体更好吗" | "在 Y 类任务上，派发与自做的成功率与成本各是多少" |

### 6.2 信息论

信息论给出的度量与算例完全对应：

$$
I(x) = -\log_2 P(x), \qquad H = -\sum p_i \log_2 p_i
$$

算例验证：

| 量 | 值 |
|---|---|
| $H(p = 0.5)$ | **1.0000**（最大） |
| $H(p = 0.95)$ | **0.2864** |
| $I(\text{肯定} \mid p = 0.5)$ | 1.0000 |
| $I(\text{肯定} \mid p = 0.95)$ | 0.0740 |
| $I(\text{否证} \mid p = 0.95)$ | **4.3219** |

熵的最大值在 $p = 0.5$：**这解释了为什么"真正不确定的问题"信息量最大。**

"否证的信息量与肯定的信息量相反"：**这是信息量不对称的来源，也是"挑战通行做法"高价值的定量依据。**

### 6.3 实验设计中的偏差

实验设计领域列出的偏倚来源与本篇直接相关：

| 偏倚 | 含义 | 本课程对应 |
|---|---|---|
| **选择偏差** | 挑样本的方式影响结论 | 见 6.2 |
| **确认偏差** | 倾向于找支持自己的证据 | 预注册 |
| **事后解释** | 看到结果再编假设 | 判别程序前置 |
| **发表偏差** | 只报告显著结果 | 记录全部尝试 |

"记录全部尝试"是最容易被违反的一条：**只报告成功的尝试会让结论虚假乐观。** 正确做法是记录所有尝试及其结果（即使大部分是阴性）。

这与 2.7 的"会话日志是唯一真相源"是同一个纪律：**只记录一部分，就无法复现也无法审计。**

### 6.4 研究问题的类型

研究方法里常把问题分为几类，它们的信息量与手段需求不同：

| 类型 | 例子 | 特点 |
|---|---|---|
| **描述性** | "当前成功率是多少" | 直接测量 |
| **比较性** | "A 与 B 哪个好" | 需要对照与样本量 |
| **机制性** | "为什么 A 更好" | 需要排除其他解释（6.4） |

**三类的难度递增**，因为：

- 描述性只需测量。
- 比较性还需控制变量与样本量（见 6.2）。
- **机制性还需排除替代解释**（见 6.4 的"唯一解释"条件）。

选题建议：**先做描述性（低成本、建立基线），再做比较性，最后才做机制性。** 跳过前两类的机制性研究会因为缺少基线而无法判断结果。

## 七、理论：信息量与熵

### 7.1 单次观察的信息量

$$
I = -\log_2 P(\text{结果})
$$

算例实测：$p = 0.5$ 肯定 → **1.0000**。$p = 0.95$ 肯定 → 0.0740。$p = 0.99$ 肯定 → 0.0145。$p = 0.95$ 否证 → 4.3219。

两条可以直接使用的推论：

| 推论 | 含义 |
|---|---|
| **验证已知的事没有价值** | $p \to 1$ 时肯定的信息量 $\to 0$ |
| **推翻低概率事件价值极高** | $I = -\log_2 P$ 在 $P$ 小时很大 |

**第二条是"意外"的定量定义**（见 6.4）：意外就是低概率事件发生了。

### 7.2 熵与不确定性

$$
H = -\sum_i p_i \log_2 p_i
$$

算例实测：$H(p = 0.5) = 1.0000$（二元分布的最大值），$H(p = 0.95) = 0.2864$。

读法：**先验熵 $H$ 是"预期能从这次实验获得多少信息"的上界**。$p = 0.95$ 的假设，无论结果如何，平均只能给你约 0.29 比特。

这给出一个选题判据：**优先做先验熵高的问题**（即你对答案真的不确定的）。

### 7.3 比值的含义

算例验证：**0.50 与 0.95 的信息量之比是 13.51 倍**。

对应到实验成本：**在 $p = 0.5$ 的问题上做一次实验，等于在 $p = 0.95$ 的问题上做 13.5 次。**

**这是一条可以直接用于分配预算的换算。** 如果你的实验成本相同，同样预算放在高熵问题上收益高一个数量级。

## 九、练习

### 第一题：判断哪些问题可研究

实现如下。

```
A  "agent 用的模型换新版本后，任务成功率会提高吗？"（有基准、有预算）
B  "agent 会变得更智能吗？"
C  "把上下文压缩阈值从 70% 调到 80%，成本会降多少？"（有成本记账，但没跑过这个对比）
D  "派发与自做在检索类任务上的成本谁更低？"（有记账，需要 200 次实验，预算只够 50 次）
```

要求：

- 逐个判断三要素是否齐备，缺什么。
- 对可回答的，估计它的信息量（先给一个先验）。
- 对不可回答的，说明是"手段缺失"还是"预算不足"，以及该怎么处理。

### 第二题：用信息量排序

场景：你有三个候选问题，各自的先验如下：

```
P1  你估计有 95% 把握答案是"是"
P2  你完全没把握（50/50）
P3  你估计有 10% 把握答案是"是"
```

要求：

- 算出每个问题"得到肯定"与"得到否定"两种结果的信息量。
- 按"期望信息量"（即熵）排序，说明哪个最值得做。
- 如果 P1 的答案是否定的，它的信息量是多少？说明了什么？
- 给出一个从 P1 改造出高信息量问题的方法。

### 第三题（进阶）：设计一个研究立项

要求：

- 选一个你关心的 agent 相关问题，写出三要素。
- 写清判别程序（什么结果算支持、什么算否定），并说明如何在实验前固定它。
- 估计先验与信息量，说明它是否值得做。
- 给出覆盖率分析：现有手段能覆盖多少，不能覆盖的部分怎么办。
