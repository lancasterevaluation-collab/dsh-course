# kit —— 你的作业环境

这是你**唯一需要动手的地方**。作业文档在上一级目录（`../作业引导.md`），判分器在另一侧的 `../grade/`，你都不需要改它们。

```
homework/3.3/
├── 作业引导.md    ← 先读它（指导文档）
├── kit/               ← ★ 你在这里工作（作业环境）
│   ├── README.md      ← 你正在读的文件
│   ├── answers.json   ← 你要填的答卷（15 个自动评分项）
│   ├── writeup.md     ← 你要写的报告（推理过程）
│   ├── scripts/       ← 你写的脚本放这里（任务 3）
│   └── tools/         ← 预置工具，不用改
│       ├── depgraph.mjs   依赖图与结构诊断器
│       └── check.mjs      判分入口
└── grade/             ← 判分材料，不要改
    ├── check-answers.mjs   判分器本体
    └── answers.example.json 参考答案（做完再看）
```

## 为什么是这样一个结构

**环境与判分分离**，是因为它们服务于两个不同的目的，混在一起会互相干扰。判分器需要与你的答案**独立**，否则你会在做题时不断去看它（那等于抄答案）；而作业环境里的工具需要与你的**工作流**贴合（顺手可跑）。所以预置工具在 `kit/tools/`，判分器在 `grade/`。

`grade/` 里的 `answers.example.json` 是参考答案。**它对你有用，但请在做完任务 2 之后再看**——理由写在作业引导的第一节（那涉及一个心理学上的效应）。

## 你现在就能做的三件事

```powershell
# 1) 确认能看到 dsh-mini 的结构（这是你所有数据的来源）
node tools/depgraph.mjs --repo D:\dsh-mini

# 2) 看你的答卷长什么样（现在全是 null）
Get-Content answers.json

# 3) 跑一次判分，看看"什么都没做"是多少分
node tools/check.mjs --repo D:\dsh-mini
```

第 3 步的期望输出是 **0.0 / 100**。这个数字不是打击，它是一条**基线**：从 0 到 100 的每一分，你都能说清它是怎么来的。

## 预置工具用在哪一步

`tools/depgraph.mjs` 替你做掉**机械计数**，把时间留给你做**判断**。它的三种用法对应作业的三个阶段：

| 命令 | 什么时候用 | 你会得到 |
|---|---|---|
| `--levels` | 任务 4 之前，先建立层级概念 | 五个层级与允许的依赖方向 |
| `--module <路径>` | 任务 1 的每一步 | 单个模块的扇出、扇入（分值与类型）、I、深度 |
| 不带参数 | 任务 2 之前，找热点与可疑连线 | 全仓诊断：跨层违规、循环依赖、扇入排名 |
| `--json` | 想自己写脚本分析时 | 机器可读的全量数据 |

**它不替你做的事**（这些正是作业要考的）：判断哪些依赖是必要的、哪些"会静默失效"、哪些热点值得保留、以及一次改动到底会波及谁。工具给数据，判断是你的。

## 一条纪律

**不要修改 `D:\dsh-mini` 的任何文件**（任务 3 的临时副本除外，用完就删）。这份作业的目的是让你在不写代码的前提下建立结构理解——一旦动了源码，练习的性质就变了。做完之后可以用这条命令确认：

```powershell
git -C D:\dsh-mini status --short   # 期望：无输出
```
