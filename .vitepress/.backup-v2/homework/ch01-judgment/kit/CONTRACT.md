> 判分只看两样：**这份声明**与**测试**。**声明里没写的，测试不会考；声明里写了的，测试一定会考。**
>
> **为什么只给声明不给实现**：这正是 1.4 的核心能力——**从契约读出一个模块的全部可依赖行为**。你会发现，声明里那些"看起来是细节"的句子，恰恰是测试要抓的地方。

---

## 一、它是什么

一个有**容量硬上限**的记忆容器。它模仿 Hermes Agent 的一个设计立场：

> **写满时失败，而不是丢弃最旧的。**

**为什么这个立场值得单独实现一遍**：因为"丢弃最旧的"是最自然的实现，**而它会让使用者永远不知道自己丢了什么**。选择"失败"，是把"丢弃"的决定权交还给调用方。

---

## 二、行为承诺

| 方法 | 签名 | 行为 |
|---|---|---|
| `add` | `add(entry) => Entry` | 添加一条记忆。**若已达上限，抛 `CapacityError`，不丢弃任何已有条目** |
| `get` | `get(id) => Entry \| undefined` | 取一条；不存在返回 `undefined`（**不抛错**） |
| `remove` | `remove(id) => boolean` | 删除一条；**若 id 不存在，返回 `false` 而不抛错**（幂等） |
| `merge` | `merge(ids, text) => Entry` | 把 `ids` 指定的多条合并成**一条**新条目；被合并的旧条目被移除 |
| `list` | `list() => Entry[]` | 返回当前全部条目。**返回的是副本**——修改它不影响内部状态 |
| `size` | `size() => number` | 当前条目数 |

**`Entry` 的形状**：

```ts
interface Entry {
  readonly id: string         // 唯一
  readonly text: string       // 非空
  readonly createdAt: number  // 毫秒时间戳
  readonly mergedFrom?: number // merge 产生的条目才有：它由几条合并而来
}
```

## 三、时序承诺

| 承诺 | 说明 |
|---|---|
| **不是并发安全的** | 调用方需保证串行调用。**实现不需要加锁**——但也不需要假装安全 |
| **`remove` 后容量立即释放** | 删掉一条后，`add` 应当能成功 |
| **`merge` 的容量语义** | 合并 N 条为 1 条 → **容量减少 N−1**。所以合并**不能在满仓时失败**（它只会让容量更宽松） |
| **`list` 返回的是快照** | 调用后修改内部状态，不影响已经返回的数组 |

**第二与第三条是测试的重点**——因为"删除释放容量"与"合并不受满仓限制"都是**容易写错的地方**。

---

## 四、错误承诺

| 情况 | 抛什么 | 要求 |
|---|---|---|
| **达到上限时 `add`** | `CapacityError` | **必须带 `limit` 与 `current` 两个字段** |
| **`id` 已存在时 `add`** | `DuplicateError` | 带 `id` 字段 |
| **`text` 为空字符串时 `add`** | `TypeError` | 带说明信息 |
| **`merge` 的 `ids` 里有不存在的 id** | `NotFoundError` | 带那个 id |
| **`merge` 的 `text` 为空** | `TypeError` | 同上 |

**错误类型是承诺的一部分**——所以它们**必须能被 `instanceof` 判断**（即必须是导出的类，不是用 `Error` 加 `name` 字段冒充）。

**这一条是很多实现的失分点**：用 `throw new Error('Capacity')` 是不合格的——因为调用方无法可靠地区分错误类型。

## 五、不变量（任何时刻都必须成立）

| # | 不变量 |
|---|---|
| 1 | `size() <= limit` |
| 2 | 所有 `id` 唯一 |
| 3 | 所有 `text` 非空 |
| 4 | `list()` 返回的数组**不是内部状态**（改它不影响内部） |
| 5 | `list()` 的每一项都是**副本**（改它不影响内部） |

**不变量 4 与 5 的区别值得注意**：前者是"数组本身是副本"，后者是"数组的**元素**也是副本"。**只做前者是常见的半成品。**

---

## 六、不属于承诺的部分（明确声明，不要依赖）

| 不属于承诺 | 说明 |
|---|---|
| `entries` 的**存储顺序** | 实现可以按任意顺序存；`list()` 的顺序也不构成承诺 |
| `id` 的**生成规则** | 只要唯一即可；不要依赖它的格式 |
| 内部使用的**数据结构** | 数组、Map、链表都可以 |
| `merge` 后新条目的 **id 与旧 id 的关系** | 不承诺保留任何一个旧 id |

**为什么这一段也重要**：按 Hyrum 定律，**没有明确声明为"实现细节"的行为，一定会有人依赖**。所以一个合格的契约必须**明确划出这条线**——而"写清不承诺什么"也是 1.4 要求的能力。
