## 第一组：派发协议（6 项）

为下面六个任务各写一份**派发协议**，四个要素齐全：

- `goal`：一句**可判定**的话（做完没有能被判断）；
- `context.give`：给它看的材料；
- `context.notGive`：**明确说明不给什么**（非空；它让子 agent 知道自己看不到全貌，从而不做全局判断）；
- `constraints`：至少两条，写成**判据**（含"不得/必须/只能/不允许/不超过/通过/等于"之一）；
- `outputFormat`：含 `kind`（`text`/`patch`/`list`）与 `maxChars`（**容量是必需项**）。

**t2.** "把 5.1 那一节改写得更紧凑。"

**t3.** "研究一下我们用不用得上向量检索。"

**t4.** "修一下那个 bug。"

**t5.** "为 5.2 写一节关于外部工具接入的内容。"

**t6.** "把测试补上。"

**注意**：这六个任务里有两个的目标**本身不可判定**（"看一下"、"修一下那个 bug"）——**你的 `goal` 必须把它们改写成一个可判定的目标**，否则判据会判为不合格。

## 第二组：信任边界（4 项）

为下面四个外部工具各写一份**信任边界**：

- `fs.read` / `fs.write`：路径白名单（**默认最小集**）；
- `net`：域名白名单（不需要网络的填空数组）；
- `budget`：`{ cpuMs, memoryMb, callsPerMinute }`；
- `contextSharing`：`{ parentHistory: false, memory: 'filtered' | 'none' }`（**`parentHistory` 必须是 `false`**）；
- `sideEffectCeiling`：`read` / `write` / `destructive` / `system`（**由配置指定，不信工具自报**）；
- `escapeAttempt`：一次用来验证边界的**越界尝试**（例如"尝试读取白名单外的路径"）。

---

**e1.** 一个声明自己"只读文件"的 MCP 服务。

**e2.** 一个能发起 HTTP 请求的服务。

**e3.** 一个能执行 shell 命令的服务。

**e4.** 一个能访问数据库的服务。

## 判据与答案表（作答之后再看）

| 判据 | 权重 |
|---|---|
| 6 份协议四要素齐全且目标可判定 | 8 |
| `context.notGive` 非空（明确说明不给什么） | 3 |
| 4 条边界四维度齐全且默认最小集 | 4 |

**关于"可判定"**：`goal` 长度 ≥ 8 只是最低要求，而真正的要求是**能判断做完没有**。对照：

| 不可判定 | 可判定 |
|---|---|
| 看一下仓库结构 | 列出仓库的顶层目录与各自的职责，输出一份不超过 20 行的清单 |
| 修一下那个 bug | 定位并修复 `x` 在 `y` 条件下返回错误值的问题，并补一个覆盖该条件的测试 |
| 把测试补上 | 为 `z` 模块的公开函数各写一个用例，且全量测试通过 |
| 研究一下向量检索 | 对比关键词检索与向量检索在本项目语料上的前 3 命中率，输出结论与依据 |

**关于信任边界的最小集**：

| 工具 | `sideEffectCeiling` | 关键判断 |
|---|---|---|
| e1 只读文件服务 | `read` | **等级由配置指定**——它自报"只读"不足以作为依据 |
| e2 HTTP 服务 | `write` | 白名单只列必需域名；`parentHistory: false` |
| e3 shell 服务 | `system` | 最高等级；文件与网络白名单都应为空（除非确实需要） |
| e4 数据库服务 | `write` | 只读账号优先；能访问的表列在白名单里 |
