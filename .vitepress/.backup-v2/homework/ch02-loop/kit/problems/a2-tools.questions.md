## A 组 · 这段东西模型读得懂吗（12 题 × 3 分）

下面是若干工具的**给模型看的那部分**——名字、描述、schema，或者它给出的失败信息。**逐个判断模型能不能只凭它正确地用一次**，填 `usable` 或 `broken`。

判据来自讲义 0.2 的两个工具与 1.2：**把这段文字交给一个没读过代码的人，他能填对参数吗？** 它的读者是模型，而模型和你一样，只能读到这段文字。

| 题号 | 给模型看的那部分 |
|---|---|
| A1 | 名字是 `ReadTheFileContents`，描述与 schema 都很清楚 |
| A2 | 描述是 `见 src/fs.ts 里 readFile 的注释` |
| A3 | 描述是 `当需要查看某个文件的内容时用它。它返回文件的全文；不要用它读二进制文件。` |
| A4 | schema 里 `path` 的类型是 `string`，而它**没有** `description` |
| A5 | schema 用了完整 JSON Schema 的 `$ref` 与 `oneOf` |
| A6 | schema 里 `mode` 的类型是 `string`，`enum` 限定为 `['head','tail']`，`required` 含 `mode` |
| A7 | 一个名叫 `manage_files` 的工具，描述说"根据 `action` 参数决定是读、写还是删除" |
| A8 | 描述是 `这个工具会尽力而为，有时可能会失败` |
| A9 | `required` 列了 6 个参数，而其中 4 个只在极少数情况下才需要 |
| A10 | `path` 的描述是 `要读取的文件路径，必须是相对于工作目录的路径，例如 src/index.ts` |
| A11 | 工具失败时给出的信息是 `操作失败` |
| A12 | 工具失败时给出的信息是 `文件不存在：a.txt。可以用 list_dir 看看目录里有什么。` |

**这一组有两道题的答案都是 `usable` 之外还要看理由**：A3、A10、A12 的写法差异说明的是同一件事的三种形态（讲义 1.2、1.5、1.6 的一般形式：给下游的信息要携带"下一步需要的东西"）。

## B 组 · 副作用等级（8 题 × 3 分）

下面 8 个操作。**按"撤销它要付出什么"给它们分级**，填 `readonly` / `reversible` / `irreversible` / `external`。

判据来自讲义 1.8 的两条分界线：**新建与覆盖的区别**（撤销后者需要它曾被备份过），以及**删除与"已经离开你的控制"的区别**。

| 题号 | 操作 |
|---|---|
| B1 | 读取工作目录内某个文件的内容 |
| B2 | 在工作目录内新建一个原本不存在的文件 |
| B3 | 覆盖工作目录内一个已存在的文件 |
| B4 | 删除工作目录内的一个文件 |
| B5 | 对本地数据库执行 schema 迁移（改写已有数据） |
| B6 | 对外部服务发一个幂等的 GET 请求 |
| B7 | 发送一封邮件 |
| B8 | 调用按量计费的第三方 API 生成一张图片 |

★ **B1 与 B6 都是"只读"，而 B6 会离开本机。** 如果这一点让你犹豫，回看 1.8 那张表的第二列——**这一级判的是"撤销的代价"，而不是"有没有网络访问"**（"离开控制范围"是第四级的判据，而一个不改变任何东西的请求没有需要撤销的东西）。

## C 组 · 术语（10 题 × 2 分）

每题写**术语名**（允许常见同义写法）。

| 题号 | 描述 |
|---|---|
| C1 | 一份能被模型读懂的说明，加上它背后的实现 |
| C2 | 描述"一个 JSON 应该长什么样"的格式，在这一篇里只用它的极小子集 |
| C3 | 一个工具被调用后，外部世界被改动的程度（本篇分四级） |
| C4 | 一个操作能不能被撤销 |
| C5 | 工具名到工具定义的映射，同时也是调用工具的唯一入口 |
| C6 | 插件可以挂上行为的地方（本篇的注册表就是它的最小雏形） |
| C7 | 检查模型给的参数是否符合 schema，位置在调用实现之前 |
| C8 | 本篇最重要的一条设计：可预期的失败用 `ok: false` 表达，而不入异常通道 |
| C9 | 挡住"路径穿越"这一类最常见事故的检查（它不是沙箱） |
| C10 | 这个工具集让 agent 能做什么——它比模型能力更能决定 agent 的上限 |
