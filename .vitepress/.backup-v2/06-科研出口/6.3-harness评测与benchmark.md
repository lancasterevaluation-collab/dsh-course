## 本篇新词

- **评测基准（benchmark）** 指一套固定下来的任务、环境和评分协议。它的价值不在题目本身，而在"同一套题在不同时间、不同系统上给出可比较的结果"。一份 benchmark 要能被别人重跑才有意义。

- **任务族（task family）** 指共享同一构造模板、参数不同的一组任务。它不是按主题分的类，而是按生成方式分的族。任务族的存在使难度可以连续调节，也使误差条可以按族来算。

- **判定器（oracle）** 指独立于被测系统的、确定性的判分程序。它与评分细则的区别是前者给对错，后者给程度。一个任务如果能写出 oracle，它的分数就可复核。

- **评分细则（rubric）** 指把"做得好不好"拆成若干可分别判断的条目。它用在无法写出 oracle 的地方，代价是判分本身也要被检验。

- **harness 依赖度（harness dependence）** 指固定任务、固定模型后端时，某个模型后端在不同 harness 配置之间得分的方差。它衡量这个后端的表现对执行层的敏感程度。

- **执行对齐（execution alignment）** 指 harness 在多大程度上维持了"智能体推理的内容、工作区实际记录的状态、工具真实产生的动作、评估器最终检查的条件"这四者之间的对应关系。四者脱节就是执行对齐失败。

- **饱和（saturation）** 指任务池的平均成功率接近 1，因而失去区分能力。饱和的标志不是分数高，而是分数高且区间窄到无法区分新系统。

- **污染（contamination）** 指评测题目或其答案进入了模型的训练数据。它使分数无法解释，而它的存在往往无法被证明，只能被规避。

- **沙袋化（sandbagging）** 指模型在察觉到被评测时故意降低表现。它是评测的对抗面：测量行为本身改变了被测对象。

## 一、【设计原因】

先说清"为什么需要专门测 harness 的 benchmark"。不解释这个，后面的公式没有目标。

### 1.1 缺陷一：报一个成功率数字，无法归因

早期的 agent 评测报告一个数字，例如"某模型在某某任务集上成功率 43.7%"。这个数字有三个问题，而它们互相独立。

- **第一，它没有误差条。** 43.7% 是 300 道题里的 131 道，还是 1000 道题里的 437 道，读者无从判断。样本量不同，同样的小数点后一位代表的确定性完全不同。

::: keypoint 反直觉点
同一个分数，样本量差 3 倍时，95% 区间宽度可以差近 2 倍。**小数点后的位数和测量的精度没有关系**，它只反映除法算得够不够细。
:::

- **第二，它把模型和 harness 混在一起。** SWE-bench 的实践给出了一个直接的观察：同一个模型在不同执行框架（SWE-agent、Aider、Claude Code 等）下分数明显不同，而涨幅中相当一部分来自框架而不是模型。既然分数不是模型的属性，把它归给模型就是错的。

- **第三，它不区分失败的类型。** 43.7% 意味着 56.3% 失败，而这些失败里有多少是根本没做、多少是做对了但没按格式交、多少是工具调用失败后没有恢复，一个数字全盖住了。归因信息在第一层报告里就丢了，事后无法补。

### 1.2 缺陷二：把三类不同的对象当成一类来测

模型评测与 agent 评测不是同一类问题：

| 维度 | 模型评测 | agent 评测 |
|---|---|---|
| 输入 | 提示 | 任务 + 工具 + 初始状态 |
| 输出 | 一个答案 | 多步动作轨迹 |
| 判分 | 与参考答案比对 | 终态检查 + 轨迹检查 |
| 失败原因 | 不会 | 不会、没做完、做对了没交、工具坏了没恢复 |

把第二类当第一类测，会得到"某个模型比另一个强"，但说明不了强在哪里。而更强的问题是：即使承认了 agent 评测是另一类，还有第三个对象被漏掉——**系统层本身**。

### 1.3 缺陷三：harness 很少被作为变量

现有基准的三种做法都绕开了 harness：

- **把执行抽象掉**：只测静态推理，harness 不在场。
- **测一个完整的智能体系统**：分数是这个系统的，无法分解。
- 固定 harness 比较模型：模型之间可比了，但 harness 的影响被固定成了常数。

三种做法都合理，但合起来留下一个空白：当外部任务条件相同时，换一个 harness 会让分数变化多少？这个问题不回答，harness 工程就没有测量基础——改进只能靠感觉。

::: keypoint 关键结论
`Agent = Model + Harness`。**分数是这一对的属性，不是任何一半的属性。** 一份完整的能力报告必须说明"在什么 harness 条件下"取得了这个分数。
:::

### 1.4 由此确定的设计目标

上面三个缺陷对应三条设计要求。它们构成本篇之后所有内容的目标。

1. **分数必须带不确定度**，并说明样本量与抽样结构。
2. **分数必须可分解**：至少能分开模型、harness、以及两者的交互。
3. **失败必须可分类**，而且分类要能在评分阶段自动产出，不能靠事后人工读日志。

**本节要点**

- 单点成功率丢失三类信息：精度、归属、失败类型。
- 模型评测与 agent 评测在输入、输出、判分、失败原因四个维度上都不同。
- harness 在现有基准里通常是被固定或被抽象掉的常数。
- 设计目标是三条：带不确定度、可分解、失败可自动分类。

## 二、【直觉】

用一个不属于这个领域的场景把问题摆出来，此时还不引入符号。

### 2.1 体检报告

设想两份体检报告。

第一份只有一行：健康评分 72。第二份有分项：血压 128/82，空腹血糖 5.4，总胆固醇 4.9，低密度脂蛋白 2.8，并且给出了每项的参考范围。

第一份报告也能让人做决定，但只能做很粗的决定。第二份能让人做具体决定：哪一项偏离了，偏多少，要不要复查。**两份报告的信息量差别不在那个总分，而在分项与参考范围。**

agent 评测处在第一份报告的阶段已经很久，而它该长成第二份的样子。

### 2.2 三道具体的问题

把体检的类比摊开，就是三道问题。

- **问题一：题目出得对不对？** 一道题如果连出题人自己都说不清"什么算做对了"，它就不能进题库。体检里的参考范围就是这道题的判据。

- **问题二：答对了没有？** 这需要独立于被测者的判定程序。若判定程序本身也是模型，它也会错，而它的错误率必须被报告。

- **问题三：答对了几次？** 一次成功和每次成功是两种能力。一个每次都能成的系统和一个五次成四次的系统，单次成功率相同，可部署性差别很大。

::: keypoint 反直觉点
**跑一次通过不是能力，跑 k 次都通过才是。** 单次成功率 90% 的系统，跑 8 次全对的概率只有约 43%——这解释了为什么很多演示很好的 agent 上线后表现远不如演示。
:::

### 2.3 谁的分数

最后一层直观：如果把考试当作类比，那么是谁在参加考试？

不是模型单独参加。**参加考试的是"模型 + harness"这一对**。模型是它的推理能力，harness 是它的答题工具（能不能翻页、有没有草稿纸、时间到不到、交卷格式对不对）。两个人用同一支笔写同一道题，分数也可能不同，但差别来自人和笔的组合，不来自人。

**本节要点**

- 分项加参考范围的信息量远高于一个总分。
- 评测要回答三问：题对不对、答对没有、答对几次。
- 一次通过与 k 次全通过是两种不同的能力指标。
- 参加考试的是"模型 + harness"这一对。

## 三、【严格】

这一节把上面的直观形式化。符号按出现顺序定义，未定义的符号不使用。

### 3.1 定义

::: theorem 定义 6.3.1（harness）
给定一个模型 $M$，**harness** $H$ 是指把 $M$ 的输出转化为外部动作的系统层，它包含提示模板、动作格式、上下文构造、工具接口、工作区访问、权限边界、预算控制、追踪与恢复策略。

记一次完整运行为 $R = \mathrm{Run}(M, H, E, T)$，其中 $E$ 是沙箱环境，$T$ 是任务。评分写作 $\mathrm{TaskScore} = \mathrm{Eval}(R; J)$，$J$ 是评判器。

记录这一对的动机是：$H$ 的变化会改变 $R$，从而改变分数。
:::

::: theorem 定义 6.3.2（任务与其评判器）
一个任务是一个五元组 $T = (P, S_0, E, B, J)$：$P$ 是提示（或提示序列），$S_0$ 是初始工作区状态，$E$ 是环境，$B$ 是预算与超时，$J$ 是评判器。

确定性评判器（oracle）对 $R$ 给出 $J(R) \in \{0, 1\}$。评分细则（rubric）对 $R$ 给出 $J(R) \in [0, 1]$ 的连续值。
:::

::: theorem 定义 6.3.3（乘法式评分协议）
设任务 $i$ 的运行结果为 $R_i$。安全门控 $\mathrm{Security}_i \in \{0,1\}$，完成度 $\mathrm{Completion}_i \in [0,1]$，过程分

$$
\mathrm{Process}_i = \frac{\mathrm{Robustness}_i + \mathrm{ToolUse}_i + \mathrm{Consistency}_i}{3},
\qquad \mathrm{Robustness}, \mathrm{ToolUse}, \mathrm{Consistency} \in [0,1].
$$

任务总分定义为 $\mathrm{TaskScore}_i = \mathrm{Security}_i \cdot \mathrm{Completion}_i \cdot \mathrm{Process}_i$。
:::

::: theorem 定义 6.3.4（pass^k 与 pass@k）
对同一任务 $T$、同一配置 $(M, H)$ 独立运行 $k$ 次，单次成功指示变量 $X_j \in \{0,1\}$，$j = 1, \dots, k$：

$$
\mathrm{pass}^k := \Pr\left[\bigwedge_{j=1}^{k} X_j = 1\right], \qquad
\mathrm{pass@}k := \Pr\left[\bigvee_{j=1}^{k} X_j = 1\right].
$$
:::

::: theorem 定义 6.3.5（harness 依赖度）
固定任务集与模型后端 $M$，设 $s(M, H)$ 为 $M$ 在 harness $H$ 下的平均分。在 $n$ 个 harness 配置 $\{H_1, \dots, H_n\}$ 上，

$$
\mathrm{HD}(M) := \frac{1}{n}\sum_{l=1}^{n}\bigl(s(M,H_l) - \bar{s}(M)\bigr)^2,
\qquad \bar{s}(M) = \frac{1}{n}\sum_{l=1}^{n} s(M, H_l).
$$
:::

### 3.2 命题

::: theorem 命题 6.3.1（pass^k 的乘积形式）
若同一任务上的 $k$ 次运行独立同分布，单次成功概率为 $p$，则 $\mathrm{pass}^k = p^k$，且 $\mathrm{pass@}k = 1 - (1-p)^k$。

**证明.** 由定义 6.3.4，$\mathrm{pass}^k = \Pr[\bigwedge_{j} X_j = 1]$。独立同分布意味着各 $X_j$ 相互独立且同分布，故联合概率等于各边缘概率之积 $\prod_{j=1}^{k}\Pr[X_j = 1] = p^k$。

对 $\mathrm{pass@}k$，由德摩根律 $\bigvee_j X_j = \lnot\bigwedge_j \lnot X_j$，得 $\Pr[\bigvee_j X_j] = 1 - \Pr[\bigwedge_j (X_j = 0)] = 1 - (1-p)^k$。

↓ **为什么能这么写？** 独立性使"全部成功"这一事件的概率等于各次成功概率的乘积，这一步是全部推导的唯一支点。

$\blacksquare$

数值：$p = 0.9$ 时 $0.9^8 \approx 0.4305$。$p = 0.99$ 时 $0.99^8 \approx 0.9227$。
:::

::: keypoint 注意前提
独立性是假设，不是事实。同一个 harness 在同一道题上失败的原因通常相关，例如某次上下文超限后就每次都超限，此时真实 $\mathrm{pass}^k$ 高于 $p^k$。**$p^k$ 是保守下界意义上的估计**，报告时要写明这一点。
:::

::: theorem 命题 6.3.2（乘法评分的保守性）
在定义 6.3.3 下，$\mathrm{TaskScore}_i \le \min(\mathrm{Security}_i, \mathrm{Completion}_i, \mathrm{Process}_i)$。

若 $\mathrm{Security}_i = 0$，则 $\mathrm{TaskScore}_i = 0$，与其他分量无关。

**证明.** 三个因子均非负，且 $\mathrm{Security}_i \le 1$、$\mathrm{Completion}_i \le 1$、$\mathrm{Process}_i \le 1$（后两者由定义 6.3.3 的取值域，前者由 $\{0,1\}$ 取值）。三数皆不大于 1，其乘积不大于任一因子，故不大于三者最小值。

当 $\mathrm{Security}_i = 0$ 时乘积为零。

↓ **为什么能这么写？** 只需用到"每个因子都在 $[0,1]$"与"非负数的乘积不超过其最小因子"这两条。

$\blacksquare$
:::

::: keypoint 这个设计有意保守
乘法让一次明确的安全违规抹掉整个任务分数，无论完成度和过程分多高。加法式评分做不到这一点：完成 100 分加安全 0 分仍可能得到高分。**这是"宁可低估，不可高估"在评分协议里的具体形式。**
:::

::: theorem 命题 6.3.3（成功率的区间宽度随样本量收敛）
设 $n$ 次独立伯努利试验的观测成功数为 $Y$，$\hat{p} = Y/n$。Wilson 区间在置信水平 $1-\alpha$ 下的半宽 $w$ 满足 $w = O(n^{-1/2})$。特别地，当 $\hat p = 0.5$ 时 $w \approx z_{1-\alpha/2} / (2\sqrt{n})$。

**证明.** Wilson 区间由解 $|\hat p - p| = z\sqrt{p(1-p)/n}$ 得到。在 $\hat p = 0.5$ 处 $p(1-p) = 1/4$，代入得 $w = z\sqrt{(1/4)/n} = z/(2\sqrt n)$，故 $w \propto n^{-1/2}$。

↓ **为什么能这么写？** 区间宽度由标准误 $\sqrt{p(1-p)/n}$ 决定，而标准误随 $n$ 按平方根衰减。

$\blacksquare$

数值：$z = 1.96$ 时，$n = 100$ 得 $w \approx 0.096$，$n = 300$ 得 $w \approx 0.057$，$n = 1000$ 得 $w \approx 0.031$。样本量增加 10 倍，区间只窄到约三分之一。
:::

::: keypoint 常见的误用
拿两个各 300 题的评测结果比较"A 系统 61.0% 对 B 系统 58.7%"，若两者的区间各为 $\pm 5.7$ 个百分点，这个 2.3 个点的差距就落在噪声里。区间重叠时不能宣称优劣，这是最常被违反的一条。
:::

::: theorem 命题 6.3.4（分数的方差分解）
设配置 $(M, H)$ 在任务 $t$ 上的得分为 $s_{M,H,t} = \mu + a_M + b_H + (ab)_{MH} + \varepsilon_{M,H,t}$，其中 $\mu$ 是总均值，$a_M$ 是模型主效应，$b_H$ 是 harness 主效应，$(ab)_{MH}$ 是交互效应，$\varepsilon$ 是任务层残差。

若各效应零均值且互不相关，则

$$
\operatorname{Var}(s) = \sigma_a^2 + \sigma_b^2 + \sigma_{ab}^2 + \sigma_\varepsilon^2 .
$$

**证明.** 将 $s - \mu$ 视为四个互不相关零均值项之和，由方差在协方差为零时的可加性直接得到。

↓ **为什么能这么写？** 方差对互不相关的随机变量可加，而这四类效应按定义被假定互不相关。

$\blacksquare$
:::

::: keypoint 这条结论的用处
$\sigma_b^2$ 是 harness 主效应的方差，$\sigma_{ab}^2$ 是"某些模型配某些 harness 特别好"的部分。**如果不做这个分解，$\sigma_{ab}^2$ 会被混进 $\sigma_b^2$，从而高估 harness 的普遍影响。**
:::

::: theorem 命题 6.3.5（饱和使区分度消失）
设任务池的平均成功率为 $p$。在 $\mathrm{pass@}k$ 指标下，$\mathrm{pass@}k = 1 - (1-p)^k$ 对 $p$ 的导数为 $k(1-p)^{k-1}$，故当 $p \to 1$ 时该导数趋于 0。

**证明.** 对 $p$ 求导得 $\frac{\mathrm{d}}{\mathrm{d}p}\left[1 - (1-p)^k\right] = k(1-p)^{k-1}$。当 $p \to 1$ 时 $(1-p)^{k-1} \to 0$，故导数趋于 0。

↓ **为什么能这么写？** 导数度量能力提升引起的分数变化，导数趋零意味着提升不再反映在分数上。

$\blacksquare$

数值：$k = 8$ 时，$p$ 从 0.90 提到 0.99 使 $\mathrm{pass}^8$ 从 0.430 提到 0.923，提高 0.493。同样这 9 个点的能力提升，在单次成功率指标下只体现为提高 0.09。**同一份能力进步，在更严格的指标下被放大到约 5.5 倍**，这就是饱和池里必须换指标的理由。
:::

### 3.3 评判器本身也要被测量

::: theorem 命题 6.3.6（模型判分的样本效率上限）
设 $\Theta$ 为被评对象的真实质量，$X$ 为其输出，$J$ 为评判者读数，三者构成马尔可夫链 $\Theta \to X \to J$。则 $J$ 关于 $\Theta$ 的信息不超过 $X$ 关于 $\Theta$ 的信息，用模型作评判者最多带来常数倍（上界约 2 倍）的样本效率提升，不能随样本量无限放大监督信号。

**证明.** 该结论由数据处理不等式给出。在马尔可夫链 $\Theta \to X \to J$ 中，$J$ 关于 $\Theta$ 的 Fisher 信息不超过 $X$ 关于 $\Theta$ 的 Fisher 信息。有限的信息损失使达到同一估计精度所需样本数至多多出一个常数因子，该常数在常见的评判噪声水平下不超过 2。

↓ **为什么能这么写？** 数据处理不等式说明再加工不增加信息，因此评判者无法凭空创造关于真实质量的监督信号。

$\blacksquare$
:::

::: keypoint 工程含义
**换一个更强的模型当裁判不能解决评测的规模问题。** 它能把所需样本量减少到约一半，之后就撞到原理上限。要降低标注成本，得换手段（确定性 oracle、程序化任务生成），而不是换裁判。
:::

**本节要点**

- harness 与任务是可定义的对象，运行记作 $R = \mathrm{Run}(M,H,E,T)$。
- $\mathrm{pass}^k = p^k$ 依赖独立性假设，违反时它是保守下界。
- 乘法式评分使安全违规抹掉整个任务分，这是"宁可低估"的形式。
- 区间宽度按 $n^{-1/2}$ 收敛，样本量加 10 倍只把区间缩到约三分之一。
- 分数方差可分解为模型、harness、交互、残差四项，不做分解会夸大 harness 的作用。
- 饱和时 $\mathrm{pass@}k$ 对 $p$ 的导数趋于零，必须换指标。
- 模型判分的样本效率上限约为 2 倍，这是原理性的。

## 四、【回到直觉】

把第三节的形式结论翻译成可以直接用的句子。

- **定义 6.3.1 说的**：分数属于"模型 + harness"这一对。报告分数时若不写 harness 条件，这个分数就无法被别人复现，也无法被归因。
- **定义 6.3.3 说的**：评分用乘法，是为了让安全拥有一票否决权。加法式评分里，安全违规可以被高完成度补偿，而乘法式不能。
- **命题 6.3.1 说的**：一次成功和每次都成功之间的差距，比直觉大得多。90% 的单次成功率听起来很好，跑 8 次全对只有 43%。报告 agent 能力时，pass^k 比成功率更接近"能不能用"。
- **命题 6.3.3 说的**：比较两个系统时先看区间。区间重叠就不要下结论，无论小数点后多几位看起来多精确。
- **命题 6.3.4 说的**：要判断 harness 到底有多重要，必须把交互效应分出去。否则测出来的可能只是"某几个模型在某些 harness 上特别合适"。
- **命题 6.3.5 说的**：当所有系统都能拿 90 分以上时，这个 benchmark 就废了。要么换更严格的指标（例如从 pass@1 换到 pass^8），要么换更难的题。
- **命题 6.3.6 说的**：不要指望用更强的裁判来省标注。省标注要靠确定性判据和程序化出题。

**本节要点**

- 分数必须连着 harness 条件一起报告。
- 乘法评分给安全一票否决权。
- 能力报告用 pass^k，不用单次成功率。
- 比较系统前先看区间是否重叠。
- 判断 harness 重要性要分掉交互效应。
- benchmark 饱和就换指标或换题。
- 省标注靠确定性判据，不靠更强的裁判。

## 五、【工具箱】

补齐本节用到的数学工具，供回头查。

### 5.1 比例的区间估计

小样本下用 Wilson 区间，不用正态近似。给定 $n$ 次试验、$Y$ 次成功、$\hat p = Y/n$，置信水平 $1-\alpha$ 下：

$$
\frac{\hat p + \frac{z^2}{2n}}{1 + \frac{z^2}{n}}
\;\pm\;
\frac{z}{1 + \frac{z^2}{n}}\sqrt{\frac{\hat p(1-\hat p)}{n} + \frac{z^2}{4n^2}} .
$$

什么时候用它：$n < 100$，或 $\hat p$ 接近 0 或 1 时。后一种情形在难任务上很常见。

### 5.2 要跑多少题

要检出两个系统成功率之差 $\Delta = p_1 - p_2$，每组的样本量近似为

$$
n \approx \frac{(z_{1-\alpha/2} + z_{1-\beta})^2 \cdot \bigl[p_1(1-p_1) + p_2(1-p_2)\bigr]}{\Delta^2} .
$$

数值：检出 $0.80 \to 0.90$ 这样 10 个点的差距，在 $\alpha = 0.05$、功效 $0.8$ 下，每组需 197 题。若只想检出 3 个点，每组需要 2626 题。

::: keypoint 这类数字要算在实验设计之前
**跑完再看差多少的做法会系统性地产生假发现**，因为低于门槛的差距无法被区分，而报告只看已经跑过的部分。
:::

### 5.3 方差分解的估计

按命题 6.3.4 的模型，用两因素方差分析（含交互）估计四个方差分量。当设计是"每个模型 $\times$ 每个 harness $\times$ 每个任务"的完整因子矩阵时，交互项与残差可分别估计。

报告什么：至少报告 $\hat\sigma_b^2$（harness 主效应）与 $\hat\sigma_{ab}^2$（交互），以及它们占总方差的比例。

### 5.4 序贯检验

边跑边看会抬高假阳性率。若必须提前停止，用 mSPRT 控制任意时刻的错误率：

$$
\Lambda_n = \sqrt{\frac{\tau^2}{\tau^2 + n\sigma^2}} \exp\left(\frac{n^2 \bar{X}_n^2}{2\sigma^2(\tau^2 + n\sigma^2)}\right) ,
$$

当 $\Lambda_n \ge 1/\alpha$ 时拒绝原假设。

数值：边跑边看的固定 $n$ 检验在真实零假设下假阳性率可达 30% 以上，而 mSPRT 保持名义水平。

### 5.5 任务池的难度校准

用 1PL/2PL 逻辑斯蒂模型把系统能力 $\theta$ 与任务难度 $\beta$ 放到同一尺度：

$$
\Pr[\text{成功} \mid \theta, \beta] = \sigma\bigl(a(\theta - \beta)\bigr) .
$$

用途是判断池子的难度分布是否匹配被测系统，以及任务难度估计是否稳定。METR 的时间跨度是它的特例：把难度轴取成"人类完成时间"，则 $p = c + (1-c)\sigma\bigl(\beta(\log h - \log t)\bigr)$，其中 $h$ 是 50% 成功对应的时间跨度。

**本节要点**

- 小样本与极端比例用 Wilson 区间。
- 样本量在实验设计之前算，不能跑完再看。
- 报告 harness 主效应方差与交互方差，并给出占比。
- 需要提前停止时用 mSPRT，不用固定样本检验。
- 任务难度用 IRT 校准，时间跨度是难度轴的一种取法。

## 七、施工图与算例

这一节回答两个最实际的问题：**题目是怎么设计出来的**，以及 agent 拿到题目后按什么流程作答。

### 7.1 一道题由什么构成

按定义 6.3.2，任务是五元组 $T = (P, S_0, E, B, J)$。落到工程上，一道题的清单（manifest）至少要有这些字段：

| 字段 | 作用 | 缺了会怎样 |
|---|---|---|
| 提示 $P$ | 交代目标与约束 | 题目无法被理解，分数无意义 |
| 初始工作区 $S_0$ | 固定起点 | 两次运行不可比 |
| 环境 $E$ | 沙箱、语言运行时、离线资源 | 依赖外部服务，结果不可复现 |
| 预算与超时 $B$ | 成本与时间上限 | 成本不可控，长轨迹占便宜 |
| 评判器 $J$ | 判对错或判程度 | 无法给出分数 |
| **预期产物** | 明确要交什么文件 | 出现"做对了但没交"的失败 |
| **约束** | 不许做什么 | 出现绕过判据的取巧解 |

::: keypoint 一份任务清单里最容易漏的是"预期产物"
**只写目标不写产物，会把"没做出来"和"做出来了但没交"混成同一种失败。** 这两者对应的 harness 缺陷完全不同：前者是能力或策略问题，后者是产物提交与输出契约问题。
:::

### 7.2 题目如何设计：四项纳入标准

一份合格的题必须同时满足四条。这四条是筛选标准，不是打分标准——不满足的题直接不入库。

::: theorem 四项纳入标准
1. **真实性**：它反映一种合理的真实用户工作流，而不是为了考模型而虚构的场景。
2. **可解性**：用沙箱里提供的资源能完成。不可解的题会表现为全部系统得零分。
3. **可 oracle 校验性**：成功可以由确定性检查或指定评分细则验证。**判据必须能在任务之外独立执行。

**
4. **完整性**：智能体不能通过读取隐藏答案、修改受保护的固定装置、或绕过约束来得分。
:::

第三条与第四条最容易做错，且后果最严重：

- 缺第三条时，题目只能靠人读轨迹打分，规模上不去，且判分本身无法复核。
- 缺第四条时，题目存在捷径，而捷径一旦被某个系统发现，榜单就失去意义。

::: keypoint 完整性验证的具体做法
把参考实现放进沙箱并**故意让它作弊**，看它能不能拿到分数。能拿到就必须补约束。这一步是题库入库的常规检查，不是可选项。
:::

### 7.3 题目的来源：任务族与程序化生成

单题只能测一个点，成规模的评测需要**任务族**：共享同一构造模板、参数不同的一组任务。

程序化生成的结构是：把原子子任务定义成三元组

$$
\text{子任务} = (\mathrm{init}, \mathrm{solution}, \mathrm{assertion}),
$$

其中 $\mathrm{init}$ 构造初始状态，$\mathrm{solution}$ 给出参考解，$\mathrm{assertion}$ 给出判据。互斥的子任务分组后组合成复合任务，于是任务的难度可以按组合数连续调节。

- **真实案例**：τ²-Bench 的 telecom 域从 2,285 个合法组合中抽样出 114 个任务，并按平均动作数分层：service / data / mms 三级分别约为 2.3 / 4.3 / 6.0 个动作。

::: data 一手数据（τ-bench 家族）
- 任务结构：`{policy 文档, tools, tasks, user simulator}`。**用户也是 LLM**，其行为被环境工具约束（telecom 域用户侧 15 个读工具 + 15 个写工具）。
- 任务规模：telecom 从 2,285 个合法组合中抽样 114 个。

- 难度分层：service / data / mms 平均动作数约 2.3 / 4.3 / 6.0。
- 单人任务成本：默认模式约 $0.14 / 任务，全领域约 $40。
- 任务集自身会腐烂：SABER 的独立审计在 τ-bench 家族中发现 75 处以上错误（错误期望动作、歧义约束、不可能约束），τ³ 据此修复。

- 出处：arXiv:2406.12045（τ-bench）、arXiv:2506.07982（τ²-Bench）、arXiv:2512.07850（SABER）
:::

::: keypoint 任务集是会腐烂的资产
**"权威任务集"也需要被第三方校正。** 一旦任务被修正，前后分数不可直接比较——这在文献里被称为 re-grading 事件。引用他人榜单时，必须同时记录榜单版本。
:::

### 7.4 agent 怎么做题：设置 → 执行 → 评判

一次运行的流水线分三段，每段的产物都要落盘。

| 阶段 | 做什么 | 落盘什么 |
|---|---|---|
| 设置 | 渲染任务规格、构造运行时环境、初始化全新沙箱 | 任务清单、初始状态哈希 |
| 执行 | 配置好的 agent 在预算与工作区约束下尝试 | 模型请求与响应、工具调用、工作区变更、用量统计 |
| 评判 | 评估器检查最终工作区与执行证据 | oracle 输出、评分细则输出、各项分量分 |

概念上一次运行为 $R = \mathrm{Run}(M, H, E, T)$，任务分为 $\mathrm{TaskScore} = \mathrm{Eval}(R; J)$。每次运行产生四类证据：**最终工作区状态、执行轨迹、用量统计、校验器输出**。

::: keypoint 参考产物在执行期间不得暴露
隐藏答案、参考产物与评估器脚本在执行阶段对智能体不可见。**一旦可读，完整性标准立刻失效**，而这通常不是设计错误而是实现疏忽（例如评估器脚本被放进了工作区）。
:::

### 7.6 一个 harness 专项基准的整体设计

如果目标是测量 harness 本身，那么"固定什么、变化什么"就是全部设计。下表的每一行都是一个决定。

| 因素 | 处理方式 | 理由 |
|---|---|---|
| 任务提示与固定装置 | 每个任务固定 | 保证题目相同 |
| 初始沙箱状态 | 每个任务固定 | 保证起点相同 |
| 预算、超时、评估器 | 每个任务固定 | 保证判分规则相同 |
| 模型后端 | 在因子矩阵中变化 | 分离模型效应 |
| **harness 配置** | **在因子矩阵中变化** | **这就是被测量的轴** |
| 提示与动作格式 | 各 harness 原生 | 保留 harness 的真实行为 |
| 工具接口与状态策略 | 各 harness 原生 | 同上 |
| 重试与恢复行为 | 各 harness 原生 | 同上 |
| 权限与工具 | 启用最小必需集合 | 避免权限差异污染比较 |

::: keypoint 这里的核心取舍
**不强制所有系统采用相同的内部实现，只固定外部条件。** 这样测到的是"配置级诊断"，不是"某个机制的因果效应"。要把结论说成因果，必须做消融（例如同一 harness 去掉恢复机制再测一遍），那是另一种设计。
:::

### 7.7 可运行算例

配套算例 `examples/sa06_bench.mjs` 实现本篇用到的全部计算：pass^k、Wilson 区间、样本量反解、方差分解、饱和放大倍数。它的用法是：


### 8.3 评审这份评测的五个问题

拿到一份 harness 评测报告，按顺序问这五个问题就能判断它的可信度。

1. **样本量与抽样结构是什么？** 只说题数不够，要说清任务族如何分层。
2. **分数带区间吗？** 不带区间的排名不可比较。
3. **harness 条件是固定的还是变化的？** 固定的只能比模型，变化的才能谈 harness 效应。
4. **评判器是什么？** 确定性 oracle、评分细则、还是模型判分。若是模型判分，它的错误率报了吗？
5. **失败是怎么分类的？** 只有总分的报告无法归因。

**本节要点**

- 引用数字必须标出处与版本。本篇的引用来自 arXiv:2605.27922。
- 最强与最弱 harness 相差 23.8 个点，同任务同模型池。
- token 用得多的 harness 未必分高。
- 全 100% 的安全分意味着该指标已饱和。
- 本篇计算的数字都有断言，讲义与代码不会各自漂移。

### 9.2 被测系统的失败模式

一次 5,194 条轨迹的分析给出五种反复出现的失败症状。它们的共同点是把推理与"可被机器检查的形式"解耦了。

::: data 失败轨迹中的症状分布
| 失败模式 | 比例 | 典型表现 |
|---|---|---|
| 契约 / 格式 | **36.4%** | schema 或输出契约违规，包括畸形 JSON、缺失账本行、不完整清单 |
| 工具 / 恢复 | 24.6% | 工具错误或被阻止的命令之后，没有有效的恢复或计划修订 |
| 证据 / 落地 | 14.6% | 来源覆盖不完整，常伴随无支撑的断言 |
| 产物提交 | 11.1% | 推理看似合理，但未提交所需输出或工作区产物 |
| 状态 / 续行 | 9.3% | 中断或多轮任务中未能保留持久进展 |

出处：Harness-Bench（arXiv:2605.27922）第 5.1 节。各类不互斥，一条轨迹可能同时表现多种症状。
:::

::: keypoint 两个最突出的模式
1. **失败集中在"语义合理"与"机器可检查"的边界**：智能体看起来理解了任务，却仍然违反输出 schema、遗漏必需产物。这是契约问题，不是能力问题。
2. **失败集中在取得部分进展之后**：智能体检查了输入、收到了有用的工具反馈，但没有把这些进展转化为恢复、有依据的断言、被保留的状态或已提交的输出。
:::

这两条直接指向一个工程结论：**失败最大的来源不是"不会做"，而是"做了没让它变成可验证的形式"。** 提高 harness 的收益里，有相当一部分来自把契约、产物提交与恢复做成硬约束，而不是来自更聪明的提示。

### 9.3 评测自身的失败模式

评测系统也会失效。下面十条按"失效发生在哪一段"排列，前三条最常被忽略。

- **（1）测量位置放错（L9）。** 把 harness 当成常数，把分数归给模型。表现是报告里写"某模型在某某基准上 43.7%"，却不写这个分数是在什么执行框架下取得的。**修正方式**：任何分数都必须连配置一起报告。

- **（2）前提会变（L9）。** 任务集与判据是有寿命的资产。SABER 在 τ-bench 家族中发现 75 处以上错误（错误期望动作、歧义约束、不可能约束）。一旦修正，前后分数不可比。**修正方式**：记录榜单版本，引用时注明日期。

- **（3）样本量不足就排名。** 300 题下 2 个点的差距几乎必在噪声里。表现是榜单每周的名次剧烈变动。**修正方式**：排名必须带区间。

- **（4）指标饱和后继续沿用。** 当所有系统安全分都是 100% 时，这个指标已经没有信息。表现是"安全"一栏全是满分，读者误以为安全已解决。**修正方式**：定期评估每个分项的区分度。

- **（5）判分器未经校准。** τ-bench 原版的用户模拟器人工标注错误率在 airline 域达 47%、retail 域 40%（其中关键错误 12% 至 13%）。结构化约束后电信域降到 16% 总错误 / 6% 关键错误。**修正方式**：把判分器本身当作被测对象，报它的错误率。

- **（6）参考产物泄漏。** 评估器脚本或参考答案出现在工作区里，被测系统直接读取。**修正方式**：入库前跑一次"故意作弊"的参考实现。

- **（7）只报总分不报分项。** 总分掩盖失败类型，导致无法归因。**修正方式**：同时报告完成度、安全、过程三项分量与 token、轮数。

- **（8）成本不受控。** 不设 token 与轮数上限时，长轨迹系统会靠"多试"占便宜。**修正方式**：预算与超时按任务固定，并报告用量。

- **（9）以模型判分替代确定性判据。** 能写 oracle 的地方用了 LLM 判分，既引入噪声又撞上 2 倍样本效率上限。**修正方式**：优先 oracle，模型判分只用于无法形式化的维度。

- **（10）测量反应性。** 模型可能察觉到被评测而改变行为（沙袋化或迎合）。黑盒行为检测效果有限。**修正方式**：把它当作已知的测量误差来源记录，而不是假设它不存在。

**本节要点**

- 决策表覆盖 11 种常见情形，默认选项都排在前面。
- 被测系统最大的失败来源是契约与格式（36.4%），不是能力。
- 失败集中在"语义合理但机器不可检查"的边界与"部分进展之后"。
- 评测自身有十条失效模式，前两条分别是测量位置放错与前提会变。
- 判分器本身必须被测量并报告错误率。

## 十、仍未解决

- **任务集如何持续保鲜。** 程序化生成解决了规模，但生成器本身的正确性没有独立保证。目前的做法是事后审计（如 SABER），缺少生成时的形式化保证。

- **配置级结论到因果结论的桥。** 因子矩阵给出的是"这个配置整体如何"，要回答"哪个机制导致了多少差异"，需要做机制消融，而消融可能破坏 harness 的真实行为。这个张力目前没有通用解法。

- **部分可观测下的进度度量。** 终态判分忽略了部分进展，而在长程任务上部分进展恰恰是主要信号。进度率的定义依赖子目标标注，而标注成本高且主观。

- **判分器的理论极限。** 模型判分的 2 倍上限是对"被判分者自报"这一设定的结论。若引入外部验证器（例如可执行的检查程序），上限是否改变，目前没有干净的结论。

- **测量反应性的度量。** 已知模型可能察觉被评测，但缺乏在评测过程中同时测量这种察觉的常规手段。

- **跨平台分数的可迁移性。** 不同评测框架（Inspect、HELM、各家自研）之间的分数互译尚无标准，导致同一能力在不同平台上有多个不可比的数值。

**本节要点**

- 生成器的正确性缺少生成时的保证。
- 配置级结论与因果结论之间有张力。
- 部分进展的度量依赖高成本标注。
- 判分上限在引入外部验证器后是否变化尚不清楚。
- 跨平台分数互译没有标准。

**本节要点**

- 七条评测结论分别改动了前几卷的具体验收方式。
- 最直接的约束是"分数必须连 harness 条件报告"与"验收按 pass^k"。

## 十三、只记一句话 + 记忆锚点

只记一句话：

> **分数是"模型 + harness"这一对的属性，而它只有在带区间、可分解、失败可分类时才算一次测量。**

本篇的所有结论都能从这一句话推出来：说它是"这一对的属性"，就要固定外部条件、变化 harness 配置。说它"要带区间"，就要算样本量与 Wilson 区间。说它"要可分解"，就要做方差分解。说它"失败要可分类"，就要靠任务卡片的约束与确定性判据把失败留在机器可检查的形式里。

如果读完只记得一句话，就记它。其余细节都可以由它推回来。

**记忆锚点**

- **三个缺陷**：无误差条、归错对象、失败不可分类。
- **四项纳入标准**：真实性、可解性、可 oracle 校验性、完整性。
- **三段流水线**：设置、执行、评判。
- 三条公式：$\mathrm{pass}^k = p^k$、$\mathrm{TaskScore} = \mathrm{Security} \cdot \mathrm{Completion} \cdot \mathrm{Process}$、$w = z/(2\sqrt n)$。
- 两个数字：最强与最弱 harness 相差 23.8 个点。失败里契约问题占 36.4%。
