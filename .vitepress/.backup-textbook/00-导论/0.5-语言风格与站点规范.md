# 0.5 · 语言风格与站点规范

> | | |
> |---|---|
> | **适用对象** | 本课程全部 Markdown 讲义、作业引导、导论文档 |
> | **定位** | 本课程是一个**要部署上线的文档项目**，不是一组本地笔记 |
> | **语体基准** | Kubernetes 官方中文文档的《文档样式指南》与《中文本地化样式指南》的可执行条款 |
> | **例外** | 理论化要求带来的【直觉】层例外（见第三节"分层语体"） |
>
> 本文件是**写作与评审的唯一依据**。它与 `0.3-写作与作业规范.md` 的关系：0.3 管**结构与作业形态**，本文件管**语体、术语、站点与交付**。

---

## 一、这个项目是什么

一套**可构建、可预览、可部署**的中文技术课程站点。

| 项 | 决定 |
|---|---|
| 站点生成器 | VitePress（Markdown 优先、内置搜索） |
| 内容根 | 项目根目录（讲义、作业、导论都在同一棵树下；首页在根 `index.md`） |
| 站点配置 | `.vitepress/config.mts`（导航、侧边栏、搜索、KaTeX 插件） |
| 首页 | `index.md`（课程定位 + 三条入口） |
| 主题 | `.vitepress/theme/index.ts`（只做一件事：把 KaTeX 样式表打进产物） |
| 构建产物 | `.vitepress/dist`（不进版本控制） |
| 本地预览 | `npm run docs:dev` |
| 构建校验 | `npm run docs:build`（**构建失败等于交付失败**） |

**这条定位改变了三件事**：文档会被陌生人按标题检索（因此标题必须是名词短语而非口号）、相对链接必须全部有效（构建会检查）、以及术语必须全站一致（因此有术语表）。

## 二、语体规则（可执行条款）

以下十二条来自 Kubernetes 中文文档的样式指南，**逐条可检查**。

### 2.1 人称与语态

| # | 规则 | 反例 |
|---|---|---|
| 1 | **称读者为"你"**，全篇**不使用"我们"** | "我们来看一个例子" → "看一个例子" |
| 2 | **使用主动语态**（除非主动语态导致句子笨拙） | "错误会被抛出" → "实现抛出错误" |
| 3 | **不用"请"**——它是多余的礼貌 | "请将阈值设为 0.8" → "将阈值设为 0.8" |

### 2.2 简洁与用词

| # | 规则 | 反例 |
|---|---|---|
| 4 | **不用"仅仅/简单地/容易/轻松地"** | "简单地调用一下即可" → "调用即可" |
| 5 | **避免行话与习语** | "这条原则一石二鸟" → "这条原则同时解决两个问题" |
| 6 | **避免拉丁语短语** | "per se / de facto / vice versa" → "本身 / 事实上 / 反之" |
| 7 | **不写关于未来的陈述** | "将来会支持分段" → "当前不支持分段（见 L9 的缺陷表）" |

### 2.3 术语与代码样式

| # | 规则 | 示例 |
|---|---|---|
| 8 | **术语首次出现给英文原文**，形式为「中文（English，缩写）」 | 「检查点（checkpoint）」、「干扰预算（Pod Disruption Budget，PDB）」 |
| 9 | **字段名、命令、路径、值用反引号** | `` `maxAttempts` ``、`` `pnpm run test` ``、`` `kit/src/` `` |
| 10 | **字符串与整数字段值不加引号**（除非会与 API 类别混淆） | 「将 `replicas` 设为 2」而不是「设为 "2"」 |
| 11 | **术语全站一致**；统一译法见 [`术语表.md`](术语表.md) | 全站写「会话」而不是混用「会话/对话」 |
| 12 | **标点用全角**（英文命令与 Markdown 语法除外）；英文排比中的逗号改为顿号 | 「类型、状态、幂等三者」而不是「类型, 状态, 幂等」 |

### 2.4 标题

- 正文标题用**句式**（名词短语或动词短语），**不在末尾加句点**；
- 标题里**不使用口号式表达**——它会被检索，因此要能被搜到（「重试与错误分类」而不是「失败就重试是错的」）；
- 层级严格递增，不跳级。

**一处例外**：篇章大标题（`# 3.1 · …`）允许一句判断式副标题，因为它是**读入口**而不是检索入口；而站点侧边栏与导航一律用名词短语。

### 2.5 提示区块

三种标记，各有使用条件。**滥用任何一种都会让读者忽略全部提示。**

| 标记 | 何时用 | 何时不用 |
|---|---|---|
| 说明（`>` 引用块） | 补充信息、延伸阅读 | 主线上必须知道的内容 |
| 注意 | **如果不看会做错** | 只是"值得知道" |
| 警告 | **会造成不可逆后果** | 任何可回退的情形 |

## 三、分层语体（理论化要求的例外）

本课程比一般的产品文档承担更多**推导**，因此语体按层区分。**这是本规范与 K8s 文档唯一的实质性差异。**

| 层 | 语体 | 允许 | 禁止 |
|---|---|---|---|
| 【设计原因】 | 产品文档语体 | 短句、设问 | 口语、比喻 |
| 【直觉】 | **生活语言**（它的目的就是把问题讲活） | 生活场景、比喻 | 夸张修辞、感叹号、"说白了"这类填充语 |
| 【严格】 | **学术文档语体** | LaTeX、编号命题、形式化定义 | 比喻、口语、未定义的符号 |
| 【回到直觉】 | 两者之间 | 对照表、符号的生活翻译 | 新符号、新结论 |
| 【工具箱】 | 参考手册语体 | 定义 + 用途一句话 | 推导过程 |
| 其余各节 | 产品文档语体 | 表格、清单 | 长篇叙述 |

**一处必须保留的固定形式**：【严格】层的每一步推导之后有一行注释，形式为

```
↓ **为什么能这么写？** <一句话依据>
```

这行**不缩写、不改写、不省略**——它是"数学基础一般也能跟完推导"的全部依赖。

**三条硬约束**（无论哪一层）：

1. **符号先定义后使用**；每个命题有编号与名字；
2. **不出现未定义的口语化量词**（"大概""差不多"）——要给出量级或区间；
3. **不用感叹号**。

## 四、结构与文件规范

### 4.1 讲义骨架（v2，16 节）

```
这一课怎么读 → 本篇新词 → 一【设计原因】→ 二【直觉】→ 三【严格】→ 四【回到直觉】
→ 五【工具箱】→ 六、锚点表 → 七、施工图与算例 → 八、判据与数字回归
→ 九、决策表与失败模式 → 十、仍未解决 → 十一、提问训练 → 十二、系统影响回溯
→ 十三、只记一句话 + 记忆锚点 → 全篇知识结构
```

**重写过渡期**：旧骨架（17 节）的篇目仍然存在，检查脚本会标注每篇的骨架版本。重写完成的判定标准是「骨架为 v2 且检查通过」。

### 4.2 文件命名

| 类型 | 命名 | 示例 |
|---|---|---|
| 讲义 | `<卷号>.<篇号>-<名词短语>.md` | `3.1-重试与错误分类.md` |
| 导论 | `0.<序号>-<名词短语>.md` | `0.5-语言风格与站点规范.md` |
| 作业引导 | `作业引导.md`（每个工作区一份） | `homework/ch03-reliability/作业引导.md` |
| 算例 | `examples/<锚点编号>_<短名>.mjs` | `examples/sa01_retry.mjs` |
| 回归测试 | `examples/test_<同上>.mjs` | `examples/test_sa01_retry.mjs` |

### 4.3 每篇的元信息

讲义开头的引用块必须含：篇号、所代际、主要锚点、解决的清单条目、前置、后续、预计阅读、预计动手。**它是站点侧边栏与交叉引用的数据来源**，因此字段名固定。

### 4.4 数学

- 行内公式用 `$...$`，块公式用 `$$...$$`（独占一行）；
- 每个符号在【严格】节开头的**记号表**里定义；
- 命题的形式：**加粗的"命题 N（名字）."**，证明以"**证明.**"开始、以 $\blacksquare$ 结束；
- **渲染在构建期完成（KaTeX）**，样式表由 `.vitepress/theme/index.ts` 引入。产物里公式是现成的 HTML + MathML，**不依赖网络、不受客户端路由影响**，因此可以在构建后直接检查；
- **不要改成客户端渲染（如 MathJax CDN）**。曾经这样做过，症状是"公式没有被渲染成公式"——客户端脚本在单页应用的路由切换下不可靠，且它依赖网络；
- 交付检查时用一条可执行命令验证（而不是靠眼看）：请求产物页面并检查是否含 `class="katex"` 与 `katex-mathml`。

## 五、交叉引用与链接

- 同一仓库内的引用用**相对链接**（`../00-导论/0.3-写作与作业规范.md`），不用绝对路径；
- 引用锚点用 `#`（`[术语表](术语表.md#锚点)`）；
- **构建会检查死链**——死链等于交付失败；
- 引用锚点库用编号（`SA-01`、`TA-07`），并在锚点表里给出它的形态与用途。

## 六、站点配置要点

```ts
// .vitepress/config.mts 的关键决定
export default defineConfig({
  lang: 'zh-CN',
  title: 'Agent Harness 工程',
  description: '从判断力到科研出口的系统课程',
  cleanUrls: true,
  markdown: { math: true },  // 讲义含 LaTeX
  themeConfig: {
    nav: [ /* 六卷 + 导论 + 作业 + 术语表 */ ],
    sidebar: { /* 按卷分组，标题用名词短语 */ },
    search: { provider: 'local' },   // 离线可用的本地搜索
    outline: { level: [2, 3], label: '本页目录' },
  },
})
```

**三条配置决定有理由**：内容根等于项目根，讲义因此保持在自己卷的目录里（不搬动内容）；`search.provider: 'local'` 让站点在没有外部服务时也能检索；`outline` 限制到二三级标题（四级以上在长篇讲义里会让目录失去导航作用）。

## 七、交付检查（提交前逐条）

| # | 检查 | 谁做 |
|---|---|---|
| 1 | `node scripts/check-lecture.mjs --all` 全部通过 | 脚本 |
| 2 | `node scripts/normalize-bold.mjs --all` 无改动（加粗已收敛） | 脚本 |
| 3 | `npm run docs:build` 成功（含死链检查） | 脚本 |
| 4 | 算例与数字回归全部通过 | 脚本 |
| 5 | 抽出公式，抽样检查渲染 | 人工 |
| 6 | 通读一篇，检查是否出现"我们"与禁用词 | 人工 |
| 7 | 新术语已登记进术语表 | 人工 |

**第 5 与 6 条不能自动化**——它们正是"文档质量"里最后那段无法被脚本替代的部分。
