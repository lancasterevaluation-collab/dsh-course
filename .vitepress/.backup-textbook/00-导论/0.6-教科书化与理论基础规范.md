# 0.6 教科书化与理论基础规范

本篇规定两件事：一篇讲义**长什么样才算教科书**，以及**理论基础要达到什么程度才够**。0.5 管语体（怎么写句子），本篇管结构与记忆（写成什么形状）。

## 一、为什么要立这套规范

一份讲义读过之后，读者能复述出多少，取决于它的**结构**，不取决于它的篇幅。

三类写法在记忆上的效果差别很大：

| 写法 | 读者的实际体验 |
|---|---|
| 长散文连续论证 | 读得懂，但合上文档说不出哪几句是要记住的 |
| 短句 + 列表 | 要点可以逐条复述，也能被检索 |
| 定义与命题独立成块 | 可以引用、可以对错、可以拿去考试 |

本课程早先的讲稿偏第一类。**判据 T1、T3、T6、T8 就是为纠正它而设**，它们的量化结果写在第十七节。

## 二、语言层：借用 TensorFlow 文档风格指南

TensorFlow 的官方风格指南给出三条与本课程直接相关的硬要求：

- **保持句子简短**；"如果一个句子可以拆分为两句，则应当这样做"；
- **避免使用分号**；在适当的时候使用**项目符号列表**；
- **解释这样编写代码的原因**，不要未加解释就使用缩写。

第一条解释了为什么要拆分长句：一个句子承载两个判断时，读者要同时维持两个判断才能到达句末。第二条解释了为什么禁用分号：分号把两个可以独立成句的判断粘在一起，而中文读者对分号边界的敏感度低于句号。

## 三、结构层：TensorFlow 教程的组织模式

TensorFlow 的单篇教程遵循固定骨架，本课程采用其中三条：

- **二级标题是流程大阶段**（设置、处理数据、建模、训练、评估），**三级标题是可执行的具体动作**，且用动宾短语（"导入依赖""构造样本""核对判据"）；
- **说明与代码交替**：说明 → 代码 → 结果解读，如此反复。代码块前面**必须有一句说明**它要做什么；
- **代码块内用注释承载"为什么"**，密度可以高于代码本身。

本课程的讲义不完全按流程组织（第三至六卷按能力组织），但**"说明与代码交替"与"三级标题用动宾短语"这两条按原文执行**。

## 四、记忆层：每篇必须齐备的五件

读者能带走的东西，靠这五件承载。缺一件就算不完整。

| 件 | 位置 | 要求 |
|---|---|---|
| 要点小结 | 每节末尾 | 三至五条短句，每条一句话讲完 |
| 术语卡 | 节内首次出现处 | 术语（英文）+ 一句话定义 + 它解决什么 |
| 定义与命题块 | 节内 | 独立成块、有编号、可被引用 |
| 主动回忆题 | 篇末 | 十二题，覆盖全篇，不看原文作答 |
| 只记一句话 | 篇末 | 全篇压缩成一句 |

**要点小结是"记忆的钩子"**：它不重复推导，只把该节压缩成能复述的短句。读者回忆时先想起小结，再由小结回到推导。

## 五、理论层：理论基础独立成块

理论部分的形状固定为六层，缺层要写明为什么缺：

1. **定义**——先定义对象与符号，之后才能使用；
2. **命题**——每条有编号与名字，并写明前提；
3. **证明**——以"**证明.**"开始，以 $\blacksquare$ 结束，每步后用一行"↓ 为什么能这么写？"给出依据；
4. **反例**——前提不成立时会发生什么，用可运行的最小例子；
5. **边界**——结论在什么范围内成立，超出范围怎么办；
6. **回到直觉**——把形式结论翻译成一句可操作的话。

**为什么符号必须先定义**：符号未定义就使用，读者只能靠上下文猜，猜错之后整段推导作废。这是本课程要求"先定义后使用"的全部理由。

## 六、十条判据（可执行）

判据 T1 至 T10 由 `scripts/check-textbook.mjs` 检查，运行 `npm run check:textbook` 得到全量报告。

| 编号 | 判据 | 门槛 |
|---|---|---|
| T1 | 单段长度 | ≤200 字符（超限段落数 ≤ max(2, 5% 段数)） |
| T2 | 长段落占比 | >300 字符的段落 ≤5% |
| T3 | 散文分号 | 0 处 |
| T4 | 禁用词 | 0 处（轻松、仅仅、说白了、很显然、众所周知、很容易、显而易见） |
| T5 | 小标题密度 | 每 1800 字符至少一个 |
| T6 | 列表化 | 每 2500 字符至少 6 个列表项 |
| T7 | 代码块引入 | 每个代码块前有说明句 |
| T8 | 要点小结区块 | 存在 |
| T9 | 标题句式 | 不成问句 |
| T10 | 连续散文段 | ≤5 段 |

**T6 的门槛有理由**：它是"要点能被列举"的代理指标。要点埋在散文里时，读者无法判断自己记住了几条。

## 七、与 0.3、0.5 的关系

| 规范 | 管什么 | 不管什么 |
|---|---|---|
| 0.3 | 文件的物理结构、作业形态、命名 | 句子怎么写 |
| 0.5 | 语体、术语、标点、站点 | 段落有多长、要点怎么摆 |
| **0.6** | **段落与列表的配比、记忆层五件、理论基础六层** | 语体（沿用 0.5） |

三份规范同时生效。冲突时以**更具体者**为准：本篇与 0.5 在"句子长度"上重叠的部分，以本篇的判据为准，因为它是可执行的。

## 八、执行方式

改造一篇讲义的顺序固定如下，不跳步：

1. 跑检查器，记下该篇的违规清单；
2. 按 T4、T3、T1 的顺序做机械修复（这三项有自动化工具，见第九节）；
3. 逐个代码块补引入句（T7）；
4. 把"三点说明""两个原因"这类散文改成列表（T6）；
5. 每节末尾补要点小结（T8）；
6. 按第五节补理论基础；
7. 重跑检查器，直到全绿；
8. 重跑 `npm run check:lecture` 确认骨架与篇幅比例未被破坏。

## 九、自动化工具

| 工具 | 作用 | 命令 |
|---|---|---|
| 检查器 | 输出全量违规报告 | `npm run check:textbook` |
| 文本规范化 | 修 T1、T3、T4（保守替换，改完需人工复核） | `node scripts/normalize-textbook.mjs <路径>` |

规范化工具**只做保守替换**：禁用词直接替换，分号在安全位置改为句号，超长段落在句号处拆分。它改不动的部分会列在报告里，交给人处理。

## 十、验收

一篇讲义判定为"教科书化完成"，要同时满足：

- 检查器 T1 至 T10 全部通过；
- `npm run check:lecture` 骨架与篇幅比例通过；
- 记忆层五件齐备（人工确认，检查器只能查 T8）；
- 理论基础六层齐备（人工确认）。

三项机械检查加两项人工确认，缺一项就不算完成。
