## 第三节 · 前置知识

三处最容易在动手时忘掉的结论：

**第一，测量手段是最稀缺的一环**（6.1 的 1.3）。一个没有测量手段的问题不可回答——**而"建立测量"本身往往比"提出机制"更有杠杆**。

**第二，先写下要发现的差异，再反推样本量**（6.2 的 1.4）。20 个任务只能发现约 30 个百分点的差异——**小样本的"发现"多数是噪声**。

**第三，观察的前提是有预期**（6.3 的 0.0）。没有写下的预期就没有意外，而没有意外的观察只是数据。

## 第六节 · Part A：问题清单（分析题）

### 你要回答什么

`kit/problems/a-problems.questions.md` 里有三组题：

**第一组：分界判据（8 条）。** 每条是一个"问题"（有的来自工程局限、有的是方向、有的是真问题）。你要给出：**分类**（`engineering` / `open` / `not-answerable`）、**判据**（用哪一条判据得出这个分类）、以及**缺什么**（对 `open` 与 `not-answerable` 两类）。

**第二组：三要素（5 条）。** 每条是一个模糊方向（例如"怎么让系统更可靠"）。你要把它写成：**自变量**（含至少两个取值）、**因变量**（含测量手段）、**基准**（三形态之一）。

**第三组：决策影响（4 条）。** 每条是一个命题。你要给出"如果答案是 A"与"如果答案是 B"分别对应什么**不同的行动**，并判断它**是否值得做**。

### 判据

| 判据 | 权重 |
|---|---|
| 8 条分类正确且判据正确 | 10 |
| 5 条三要素齐全（自变量 ≥2 个取值、因变量带测量手段） | 10 |
| 4 条给出两种答案的不同行动且判断正确 | 5 |

## 第七节 · Part B：观察记录与转化（分析题）

### 你要回答什么

`kit/problems/b-observations.questions.md` 里有三组题：

**第一组：观察记录（6 条）。** 每条是一段"我在做大作业时遇到的情况"。你要给出：**是否值得记录**（`log` / `skip`）、**类别**（`surprise` / `anomaly` / `silent-deviation`）、以及**预期与实际**（如果值得记录）。

**第二组：排除已知解释（4 条）。** 每条是一个现象。你要给出**至少三个解释**（**含平凡解释**）与**排除方式**（`lookup` / `experiment` / `counterexample`）。

**第三组：最小反例（3 条）。** 每条是一个现象。你要给出**可执行步骤**、**预期**、以及**每一步为什么必要**（最后一项用一句话说明最简性）。

### 判据

| 判据 | 权重 |
|---|---|
| 6 条记录判定与类别正确 | 8 |
| 4 条含至少三个解释且必含平凡解释 | 6 |
| 3 条给出步骤、预期与最简性说明 | 6 |

## 第八节 · Part C：统计（构建题）

### 交付物

`kit/src/stats.mjs` 里的五个函数：

```js
export function percentile(values, q)                 // 最近秩法
export function noiseFloor(runs)                       // 同一配置多次运行的 2 倍标准差
export function sampleSize(opts)                       // 由目标差异反推样本量
export function bootstrapCI(samples, opts)             // 重采样置信区间（确定性：用种子）
export function compare(a, b, opts)                    // 差异、区间、显著性与效应量
```

### 它检验什么

**最近秩法**（不插值）、**噪声下限由同配置多次运行得出**（不是两个方法的方差）、**样本量随目标差异变小而迅速上升**、**重采样在给定种子下可复现**、**区间重叠即不显著**、**效应量与显著性同时报告**。

### 判据（见 `tests/t3-stats.mjs`）

14 条，其中三条是"看起来对、其实错"的：**噪声必须用同配置估计**、**同一个种子的两次重采样结果必须相同**、**区间重叠时 `significant` 必须为 false**。

## 第九节 · Part D：实验设计与报告（构建题）

### 交付物

`kit/src/experiment.mjs` 里的四个函数：

```js
export function planExperiment(spec)     // 样本量、重复、种子、成本估算
export function planAblation(component)  // 中性替代 + 完整性核对项
export function buildReport(record, result, conclusion)  // 六项必填
export function isReproducible(record)   // 四项记录齐全检查
```

### 它检验什么

**先定差异再反推样本量**、**成本估算是乘法的**（任务数 × 重复 × 每任务成本）、**消融要换中性替代而不是删掉**、**消融要核对其余因素未变**、**报告六项必填**（含**未检出差异也是一条结论**）、**可复现四项记录**（任务集与版本、配置与代码、种子、环境）。

### 判据（见 `tests/t4-experiment.mjs`）

13 条，其中两条是这一卷的特点：**消融的中性替代不能为空**、**报告里"未检出差异"必须带分辨率**。

## 第十一节 · 常见错误

**Part A（问题）**

1. 把"状态过时没有可靠信号"判成 `engineering`——**放大十倍资源也不会解决它**（缺的是可观测的定义）。
2. 自变量只有一个取值（那不是实验变量）。
3. 因变量没有测量手段。
4. 两种答案对应同一个行动（那说明问题没有决策影响）。

**Part B（观察）**

5. 把一个"偶发但无预期"的现象记为 `surprise`——它是 `anomaly`。
6. 三个解释里没有平凡解释（"我读错了数字"、"这次恰好网络快"）。
7. 最小反例给了步骤但没有说明"每一步为什么必要"。

**Part C（统计）**

8. 分位数用插值（**契约要求最近秩法**）。
9. 噪声下限用两个方法各自的方差算（**应当用同配置的多次运行**）。
10. 重采样不可复现（**必须用种子**）。
11. 区间重叠时仍判显著。
12. 只报显著性、不报效应量。

**Part D（实验）**

13. 先跑再看、事后再定判据（**应当先定差异再反推样本量**）。
14. 成本估算只算任务数（**它是任务数 × 重复 × 每任务成本**）。
15. 消融直接删掉组件（**应当换中性替代**）。
16. 报告里"未检出差异"不带分辨率（读者无法判断是"确实无效"还是"测不出来"）。

## 第十四节 · 你要真的做一次实验（进 writeup，不进判分器）

这一节是这一卷的**实质部分**。用你在前面大作业里写过的实现（或 `grade/` 里的参考实现），做下面三件事，并把结果写进 `kit/writeup.md` 的"我的实验"一节。

**第一，建一个基准。** 从三到十个任务起步（规模可以小，但要**稳定**）——每个任务带一个**可运行的检查**与固定条件。记录它的**噪声下限**（同一配置跑三次）。

**第二，做一次消融。** 选一个组件（例如"压缩"、"重试"、"记忆注入"），按讲义 6.2 的 1.3 换成**中性替代**，并核对**其余因素未变**。跑改前与改后各三次。

**第三，写结论。** 用 `compare` 给差异、区间与**效应量**；如果**没有检出差异**，写清**分辨率**（在多少个任务、噪声下限多少的条件下未检出）。

**报告的六项**（讲义 6.2 的 3.5）：问题（三要素）、基准（名称、版本、划分、校验和）、运行记录（四项）、结果（分位数、极值、效应量、区间）、结论（含未检出的情形）、局限。

**这一节不判分，但会被认真读**——因为它是整门课程"科研出口"这个目标的实际交付物：**你从做出一个系统，走到能对它的某个决定给出可检验的答案。**
