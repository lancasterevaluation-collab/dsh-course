## 第一节 · 这个作业要你做出什么

一句话：**给系统装上"多形态、多会话、多执行者"这三种规模能力，并证明它们在边界上不失控。**

六个 Part 与它们的验收形态：

| # | 你要交付的 | 它挡住的失败 | 对应讲义 |
|---|---|---|---|
| A | 一份模式与审批的分析（分析） | 隐式默认导致"在我机器上是好的"、审批疲劳 | 5.1、5.3 |
| B | 一份派发协议与信任边界（分析） | 子 agent 缺信息做错、外部工具越界 | 5.4 |
| C | 四个模式与预设函数（构建） | 覆盖顺序不明、能力集散落、切换有残留 | 5.1 |
| D | 四个多会话与并发函数（构建） | 会话串扰、饥饿、租约冲突、资源泄漏 | 5.2 |
| E | 三个交互与权限函数（构建） | 审批不可读、等待卡死、权限过宽 | 5.3 |
| F | 四个派发与外部工具函数（构建） | 子 agent 提权、结果淹没父会话、外部错误无法处理 | 5.4 |

**这一卷与前几卷的差别**：它的失败大多与"多个东西同时在跑"有关——**而这些失败在单会话的测试里通常不出现**。因此判据会构造多份输入（两个模式、两条会话、两个外部工具），并且核对它们**互不干扰**。

## 第三节 · 前置知识

三处最容易在动手时忘掉的结论：

**第一，模式的全部价值建立在"同一个名字总得到同一组能力"上**（5.1 的 0.0）。因此 Part C 的第一类判据是**可复现性**——而它的敌人是隐式默认与环境推断。

**第二，并发问题的多数根源是"共享了本不该共享的东西"**（5.2 的 0.0）。判据是一条：**正确性是否依赖别的会话在做什么**。因此 Part D 有两条判据在核对"两条会话互不影响"。

**第三，子 agent 不能提权**（5.4 的 1.1）。它的三条理由是绕过父限制、审批量放大、责任链断裂——而 Part F 会用一条判据直接检验它。

## 第六节 · Part A：模式与审批的分析（分析题）

### 你要回答什么

`kit/problems/a-profile.questions.md` 里有三组题：

**第一组：隐式默认排查（10 条）。** 每条是一份模式声明里的一个取值来源（有的显式、有的来自代码常量、有的来自环境推断）。你要给出：**是否可复现**（`reproducible` / `environment-dependent`）、**依据**（哪一层写的、还是由代码/环境决定）、以及**处置**（保留 / 显式化 / 移到生成阶段）。

**第二组：合并结果（6 组）。** 每组给两到三层的配置（含对象与数组）。你要给出**合并后的有效值**与**每个键来自哪一层**。

**第三组：审批呈现（4 条）。** 每条是一段"后果描述"的草稿。你要改写它，使它通过三条检查（不含反引号、不含命令名、含可恢复性），并指出它属于哪一档风险。

### 判据

| 判据 | 权重 |
|---|---|
| 10 条排查正确 | 7 |
| 6 组合并结果与来源正确 | 5 |
| 4 条后果描述通过三条检查且风险档位正确 | 3 |

## 第七节 · Part B：派发协议与信任边界（分析题）

### 你要回答什么

`kit/problems/b-delegation.questions.md` 里有两组题：

**第一组：派发协议（6 个任务）。** 每个任务是"要派给子 agent 的一件事"（有的描述清楚、有的含糊）。你要给出四个要素：**目标**（可判定）、**上下文子集**（给什么，以及**明确说明不给什么**）、**约束**（写成判据）、**产出格式**（含容量）。

**第二组：信任边界（4 个外部工具）。** 每个工具是一个外部服务的描述（例如"能读写文件"、"能发 HTTP 请求"）。你要给出：**四个维度**（能访问什么、能改什么、能用多少、能看到什么）、**副作用等级**（由配置指定而不是自报）、以及一条**越界尝试**（用来验证边界）。

### 判据

| 判据 | 权重 |
|---|---|
| 6 份协议四要素齐全且目标可判定 | 8 |
| 上下文子集明确说明"不给什么" | 3 |
| 4 条边界四维度齐全且默认最小集 | 4 |

## 第八节 · Part C：模式与预设（构建题）

### 交付物

`kit/src/profile.mjs` 里的四个函数：

```js
export function compose(layers)                    // 四层覆盖 + 来源追踪
export function expandCapabilities(profile, registry) // 能力集（含间接依赖）
export function validate(profile, registry, ctx)    // 启动校验（三层）
export function planSwitch(from, to)                // 整体切换计划与残留核对预期
```

### 它检验什么

**覆盖顺序**（从低到高）、**合并规则两类**（对象深合并、数组整体替换）、**来源追踪**（每个键来自哪一层）、**必填项与能力集校验**（含间接依赖与总量上限）、**切换是整体的**（不接受增量重装）、**哪些注册项应当在切换后存活**（由注册时声明而不是事后判断）。

### 判据（见 `tests/t3-profile.mjs`）

14 条，其中三条是"看起来对、其实错"的：**数组必须整体替换而不是深合并**、**能力集必须展开间接依赖**、**切换计划必须是整体的**。

## 第九节 · Part D：多会话与并发（构建题）

### 交付物

`kit/src/session.mjs` 里的四个函数：

```js
export function admit(request, registry, policy)    // 配额（并发、速率、占用）
export function schedule(registry, ctx)              // 调度（优先级 + 配额轮转）
export function acquire(store, workspace, holder, ctx) // 租约（超时、排队、可识别）
export function closeReport(session, ctx)            // 回收（取消、释放、核对）
```

### 它检验什么

**配额三维度**与**拒绝时的可重试信息**、**全局上限与会话上限的先后**、**优先级来自预设而不是调用者**、**轮转让短会话先得到响应**、**写租约互斥**、**租约超时后自动释放**、**等待有排队上限**、**关闭时先取消再释放并核对残留**（`leaking` 报告）。

### 判据（见 `tests/t4-session.mjs`）

14 条，其中两条核对**"两条会话互不影响"**（并发与单跑结果一致、一条异常不终止另一条）。

## 第十节 · Part E：交互与权限（构建题）

### 交付物

`kit/src/interaction.mjs` 里的三个函数：

```js
export function buildRequest(tool, args, ctx)       // 请求结构（六字段 + 人话摘要）
export function decide(request, permissions, presets) // 权限判决（四层来源）
export function fatigueSignals(events)               // 疲劳三信号
```

### 它检验什么

**请求含人话摘要与任务语境**、**风险分级按可逆性与影响范围**、**选项含"换一种做法"且顺序从窄到宽**、**权限判决的优先级**（用户授权 > 项目约定 > 预设拒绝 > 低风险放行）、**预设的拒绝不可被项目约定放宽**、**疲劳三信号**（响应时间、通过率、拒绝比例）**必须合取**。

### 判据（见 `tests/t5-interaction.mjs`）

13 条，其中三条是这一卷的特点：**预设的拒绝在项目约定之后**、**三信号合取**、**选项顺序从窄到宽**。

## 第十一节 · Part F：派发与外部工具（构建题）

### 交付物

`kit/src/delegation.mjs` 里的四个函数：

```js
export function buildDelegation(parent, spec)        // 派发协议（四要素 + 深度）
export function admitDelegation(parent, ctx)          // 三条限制（深度、子任务数、并发）
export function collectResult(child, format, ctx)     // 回收（格式校验 + 容量 + 追溯）
export function normalizeExternalError(err, server)   // 外部错误归一化
```

### 它检验什么

**四要素缺一即拒**、**深度在上限时拒绝**、**子 agent 不能超出父工具集**（不可提权）、**产出格式不符时可重试**、**超长产出被裁剪到容量内**、**回收带追溯元数据**、**外部错误映射到内部类型**、**未识别的外部错误视为 fatal 且需人介入**。

### 判据（见 `tests/t6-delegation.mjs`）

13 条，其中三条是这一卷的核心：**不可提权**、**未识别错误不盲目重试**、**容量限制发生在生成时而不是回收时**。

## 第十三节 · 常见错误

**Part A/B（分析）**

1. 把"并发数取 CPU 核数"判成 `reproducible`——**它是环境推断**，在不同机器上不同。
2. 合并时把数组也做了深合并（**应当整体替换**）。
3. 派发协议里没有说明"不给什么"（判据会检查这一项）。
4. 信任边界按"这个工具需要什么"给（**应当默认最小集，扩大要显式授权**）。

**Part C（模式）**

5. 能力集只展开声明的插件，不含间接依赖。
6. 切换计划允许增量重装（**必须整体**）。
7. 残留核对时把"应当存活的注册项"也算作残留。

**Part D（并发）**

8. 配额只限并发，不限速率与占用。
9. 优先级由调用者临时指定（**应当来自预设**）。
10. 租约没有超时（持有者崩溃后永久占用）。
11. 关闭会话时先释放租约再取消（**顺序反了**：应当先断掉产生资源的路径）。

**Part E（交互）**

12. 权限判决里让项目约定放宽预设的拒绝。
13. 疲劳判定只看通过率（**必须三信号合取**）。
14. 请求里没有任务语境（用户无法判断该不该允许）。

**Part F（派发）**

15. 允许子 agent 使用父会话没有的工具（**不可提权**）。
16. 未识别的外部错误直接重试（**应当视为 fatal 并要求人介入**）。
17. 回收时按字符截断超长产出（**应当在生成时限制容量**）。
