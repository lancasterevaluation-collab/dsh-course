## 一、答错的题与原因

每答错一道，回答两个问题：**我当初选的是什么**，以及**我依据什么选的**。第二个问题比第一个重要——因为错的原因往往是"用了一个不适用于这道题的判据"，而不是"不知道"。

| 题号 | 我选的 | 应该是 | 我当初的依据是什么 |
|---|---|---|---|
| ← 例如 A7 | safe | breaking | 我按"有没有厂商名字"判断，而这道题考的是返回值形态 |
| | | | |
| | | | |

**2.2 的 B 组要写得更具体一层**：那一组的四类答案不能靠"感觉危不危险"选，所以记录时要写清**你用哪条分界线判断的**（"新建还是覆盖"、"有没有离开我的控制范围"）。如果写不出分界线而只写"我觉得它危险"，那说明这一题是猜对的。

## 三、这一卷我要建立的三个判断

每一卷结束时，你应该能带走几条**可以搬迁到别的项目上**的判据（而不只是答案）。在这里写下你自己的版本——**与讲义给的表述不同没关系，重要的是它对你有效**。

**判据一（关于接口宽度）**：

← 例如："看它让调用方多做了什么"比"找厂商名字"更可靠，因为有的破坏方式不带厂商色彩。

**判据二（关于错误分类）**：

← 例如：分类的依据是处理方式，所以同一个底层错误在不同位置可能属于不同类。

**判据三（关于外部输入）**：

← 例如：凡是来自外部的值（模型的输出、对方给的等待时长），都要在边界处校验或设上限。
