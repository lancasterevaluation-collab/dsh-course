## 第三节 · 前置知识

三处最容易在动手时忘掉的结论先列在这里：

**第一，记忆的价值由检索到的对不对决定，而不是由存了多少决定**（4.1 的 0.0）。因此**写入策略的严格程度直接决定了检索的上限**——这也是 Part C 里"写入过滤器"与"检索打分"是同一件事的两端。

**第二，置信度是用户模型与记忆的本质差别**（4.3 的 1.2）。记忆的条目是二元的存在，而用户模型的每条特征带一个强度——**而反驳必须能降低它**（否则置信度只会单向上升）。

**第三，自改的门控必须能拒绝**（4.5 的 0.1）。因此 Part E 的判据里有一半是**负向的**："这个提议应当被拒绝"。**这也是这一卷与前几卷最大的差别：它检验的是系统会不会在正确的时机说"不"。**

## 第六节 · Part A：写入与触发策略（分析题）

### 你要回答什么

`kit/problems/a-memory.questions.md` 里有三组题：

**第一组：写入判定（12 个候选）。** 每个候选是一条可能被写入记忆的信息（例如"用户在这次会话里说要删除那个目录"、"这个项目用 pnpm"、"用户可能更喜欢简短回答"）。你要给出：**是否写入**（`write` / `skip`），**类别**（`fact` / `preference` / `inference`），以及**一句理由**（要提到三个过滤器之一：跨会话有用、可验证、非临时）。

**第二组：技能描述（6 条）。** 每条是一个技能的当前描述（有的写得像主题、有的像主题加场景）。你要改写成**触发条件**（回答"何时用"），并给出一条不适用条件。

**第三组：有界处置（2 题）。** 例如"记忆写满时，一条新条目与两条已有条目高度相似，你的处置是什么"，要给出动作与依据。

### 判据

| 判据 | 权重 |
|---|---|
| 12 个写入判定正确 | 8 |
| 类别与理由（理由需提到过滤器之一） | 3 |
| 6 条技能描述写成触发条件且含不适用条件 | 3 |
| 2 个有界处置与讲义一致（先合并、默认拒绝） | 1 |

## 第七节 · Part B：诊断与可行动性（分析题）

### 你要回答什么

`kit/problems/b-diagnosis.questions.md` 里有两组题：

**第一组：失败分类（9 个场景）。** 每个场景是一次任务失败（例如"任务跑完了但检查不通过"、"超时后没有结果"、"产出与预期不符"）。你要给出：**失败类型**（`error` / `silent` / `goal-miss`）、**候选原因至少两个**、以及**每个候选的证据强度**（`correlation` / `counterfactual` / `reproducible`）。

**第二组：不可行动的结论（5 条）。** 每条是一个"看起来完整但不可行动"的结论（例如"模型能力不足"、"用户表达不清"）。你要把它**改写成一个含可改对象的结论**，并指出改动对象属于哪一类（提示词、阈值、工具描述、技能条件、配置）。

### 判据

| 判据 | 权重 |
|---|---|
| 9 个失败分类正确 | 6 |
| 每个场景给出至少两个候选（含平凡候选） | 4 |
| 证据强度标注正确（复现 > 反事实 > 相关） | 2 |
| 5 条结论改写后含可改对象且对象类别正确 | 3 |

## 第八节 · Part C：记忆系统（构建题）

### 交付物

`kit/src/memory.mjs` 里的四个函数（详见 `kit/CONTRACT.md`）：

```js
export function write(entry, store, policy)       // 写入策略的三个过滤器 + 有界处置
export function retrieve(query, store, opts)      // 三种信号打分 + 阈值 + 抑制与过期过滤
export function inject(entries, budget, opts)     // 双预算 + 按稳定性分层 + 整条跳过
export function observe(store)                     // 四类观测量的统计
```

### 它检验什么

**三个过滤器**（跨会话有用、可验证、非临时）：不过就不写。**有界处置**：写满时先合并，合并不可行才拒绝。**检索**：抑制与过期的条目在**打分之前**被过滤；低于阈值的**不返回**（不硬凑满 k）。**注入**：双预算（条数与字符）、按使用次数分层（稳定在前）、预算不足时**跳过整条而不是截断**。

### 判据（见 `tests/t3-memory.mjs`）

14 条，其中四条是"看起来对、其实错"的：**被抑制的条目不参与检索**、**低于阈值返回空**、**注入时整条跳过**、**写满时先合并**。

## 第九节 · Part D：用户模型的置信度（构建题）

### 交付物

`kit/src/user-model.mjs` 里的四个函数：

```js
export function applyObservation(model, obs)      // 支持、反驳、归零删除
export function decayAndDetect(model, now, opts)   // 时间衰减与漂移报告
export function inject(model, spec, opts)          // 门槛判定 + 执行层调整
export function listFeatures(model)                // 面向人的列表（不含内部字段）
```

### 它检验什么

**反驳的权重高于隐式支持**（一次反对抵消两次支持）。**归零即删除**。**无特征时反驳不创建特征**。**过期即删**。**漂移只报告不自动处置**。**门槛以下的特征不生效**。**中等置信度注入时附带一句说明**（把推断说出来）。**列表不含 `weight` 这类内部字段**。

### 判据（见 `tests/t4-user-model.mjs`）

13 条，其中三条是这一卷的特点：**归零删除**、**反驳不创建特征**、**列表不暴露内部字段**（后者用正则检查）。

## 第十节 · Part E：演化与门控（构建题）

### 交付物

`kit/src/evolution.mjs` 里的四个函数：

```js
export function buildProposal(diagnosis, change)   // 提议构造与校验
export function gate(proposal, current, ctx)       // 三层门控（静态、评估）
export function release(store, proposal, ctx)      // 版本化发布（一组改动一个版本）
export function rollback(store, toVersion, ctx)     // 回滚与状态兼容检查
```

### 它检验什么

**提议必须含改前改后两段文本**（不可机械应用的不算提议）。**元控制对象被拒**（门控、评估集、日志、这份列表本身）。**基线版本过期被拒**。**改善必须大于两倍噪声**（含护栏指标参与判决）。**版本包含一组改动**、**回滚检查状态兼容**。

### 判据（见 `tests/t5-evolution.mjs`）

13 条，**其中五条是"必须被拒绝"的**：元控制对象、过期基线、无法应用的差异、改善落在噪声内、护栏退化。**这一项的分数有一半来自"拒绝对了"。**

## 第十一节 · Part F：长程任务与复盘（构建题）

### 交付物

`kit/src/longhorizon.mjs` 里的四个函数：

```js
export function writeState(state, ctx)             // 状态写入与三条校验
export function resume(state, ctx)                 // 续作：入口、上下文、剩余、检查点、过时警告
export function revise(state, revision, ctx)       // 目标修订（只追加）与范围变更（标记新增）
export function coverage(outputs, ctx)             // 复盘的覆盖率（带理由的放弃计入）
```

### 它检验什么

**唯一下一步存在**（否则拒绝写入）。**约束必须是判据形式**。**进行中只有一项**。**续作返回五样东西**（入口、上下文、剩余、检查点、过时警告）。**目标只追加不修改**（`goal` 字段不可变）。**新增待办被标记**。**覆盖率把带理由的放弃计入**，**覆盖率低时不再新增产出**。

### 判据（见 `tests/t6-longhorizon.mjs`）

14 条，其中三条是这一卷的核心：**`goal` 字段不被修改**（判分器会用冻结对象调用）、**过时警告的三条判据**、**覆盖率低时门控返回 false**。

## 第十三节 · 常见错误

**Part A/B（分析）**

1. 把"用户这次说要用某工具"判成 `write` 且类别是 `preference`——**它是一次性意图（`skip` 或记为事实）**，判据是"跨会话有用吗"。
2. 把推测类信息写成 `fact`——它必须是 `inference` 且带来源。
3. 诊断只给一个候选——**判据要求至少两个**。

**Part C（记忆）**

4. 在打分**之后**才过滤抑制与过期的条目（**应当在打分之前**）。
5. 低于阈值时为凑满 k 而返回不相关条目（**应当返回空**）。
6. 注入时按字符截断一条超预算的记忆（**应当整条跳过**）。
7. 写满时直接拒绝，没有先尝试合并。

**Part D（用户模型）**

8. 反驳与支持等权（**反驳的绝对值应更大**）。
9. 反驳到零时留一个权重为零的空壳（**应当删除**）。
10. 无特征时反驳凭空创建一条反向特征。
11. `listFeatures` 把 `weight` 暴露给用户。

**Part E（演化）**

12. 门控只检查"改善大于零"（**应当大于两倍噪声**）。
13. 护栏指标不参与判决。
14. 允许修改 `eval/dataset`（**那是元控制对象**）。
15. 回滚不检查状态兼容。

**Part F（长程与复盘）**

16. 续作时直接返回状态，没有过时警告。
17. 允许修改 `goal` 字段（**只能追加 `revisions`**）。
18. 覆盖率只统计"完成"，不把带理由的放弃计入。
19. 范围新增不标记（**应当标记 `added`**）。
