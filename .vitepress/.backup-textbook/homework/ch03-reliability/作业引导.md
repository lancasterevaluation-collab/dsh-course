## 第一节 · 这个作业要你做出什么

一句话：**给一个能跑的最小 harness 装上六件可靠性设施，并用可运行的判据证明它们生效。**

六件设施与它们的验收形态：

| # | 设施 | 你要交付的形态 | 它挡住的失败 |
|---|---|---|---|
| A | 错误分类与重试策略 | 一份分类表加一份策略表（可被机械检查） | 对所有错误一视同仁，重试放大拥塞 |
| B | 守卫与审批策略 | 一份三段式规则集加审批请求结构 | 危险操作无闸门，或审批疲劳 |
| C | 压缩与溢出 | 四个函数（纯函数，可测） | 上下文溢出，或被静默截断 |
| D | 进程与作业 | 三个函数（含一个真跑进程的） | 进程逃逸、取消不干净、输出背压死锁 |
| E | 持久化与恢复 | 两个函数（读日志、恢复） | 尾部损坏读不动，重做不幂等 |
| F | 可观测 | 四个函数（成本、延迟、命中率、汇总） | 花了多少算不出，慢在哪说不清 |

**这个作业与"读一遍讲义"的差别在于判据**：每一件设施都要过一个可运行的测试，而测试会构造那些"看起来会工作、其实不工作"的输入。

## 第三节 · 前置知识

这个作业假设你已经读过第 3 卷的六篇。三处最容易在动手时忘掉的结论先列在这里：

**第一，错误分类决定重试方向。** 不是所有错误都该重试，而"可重试"与"不可重试"的判断是**类型问题**而不是次数问题（讲义 3.1 的 1.2）。

**第二，守卫与审批是两件事。** 守卫是规则（系统判断），审批是询问（人判断），而它们的顺序与各自的默认值都是设计决定（讲义 3.2 的 1.2、1.3）。

**第三，可靠性设施的判据都在"边界条件"上。** 正常路径它们都工作，而测试会构造半行日志、超预算的输出、被取消的进程、尾部不完整的日志——**作业的成绩主要来自这些边界**。

## 第六节 · Part A：重试与错误分类（分析题）

### 你要回答什么

`kit/problems/a-retry.questions.md` 里有三组题：

**第一组：错误分类（12 个场景）。** 每个场景给出一段错误信息与上下文，你要判断它属于哪一类（`retryable`、`fatal`、`needs-human`、`unknown`），并给出一句理由。

**第二组：策略设计（3 个问题）。** 例如"一个操作已经重试了两次都因为限流失败，第三次该不该重试"，你要给出判断与依据。

**第三组：反例（2 个问题）。** 例如"给一个场景，说明按你的策略重试会造成损害"。

### 怎么作答

复制模板：

```bash
cp kit/problems/a-retry.template.json kit/answers/a-retry.json
```

然后填写。文件的形状在模板里已给出（`classification`、`policies`、`counterexamples` 三段），**每一段的每一项都有 `answer` 与 `reason` 两个字段**——`reason` 不能为空，而判分器会检查它是否指向了你判断的依据（类型、状态、幂等性之一）。

### 判据（它怎么被判定）

| 判据 | 权重 |
|---|---|
| 12 个分类全部正确 | 8 |
| 每条 `reason` 非空且提到依据（类型/状态/幂等之一） | 3 |
| 3 个策略问题给出与讲义一致的判断 | 3 |
| 2 个反例是具体的（含条件与后果，不是泛泛而谈） | 1 |

**注意**：分类题里有三个是"看起来可重试而实际不可"的（例如一个已经产生副作用的写操作超时）。**它们正是这道题的重点**。

## 第七节 · Part B：守卫与审批策略（分析题）

### 你要回答什么

`kit/problems/b-guard.questions.md` 里有两组题：

**第一组：规则设计（10 个操作）。** 每个操作（例如"删除工作区外的文件"、"向远程仓库推送"、"执行一个来自模型生成的 shell 命令"）你要给出三样：**风险等级**（low/medium/high/critical）、**默认动作**（allow/ask/deny）、以及**一句人话的后果描述**（给审批界面用）。

**第二组：审批策略（3 个问题）。** 例如"同一个操作在一条会话里被批准了三次，第四次该不该继续问"，你要给出判断与它对应的记忆粒度。

### 判据

| 判据 | 权重 |
|---|---|
| 10 个操作的风险等级正确 | 6 |
| 默认动作与等级一致（且不可逆的高风险必须 ask 或 deny） | 4 |
| 后果描述是人话（不含命令原文、提到可逆性） | 3 |
| 3 个策略问题的判断与讲义一致 | 2 |

**重点在"后果描述"这一项**：它会被一个可运行的正则检查（不得包含反引号、不得包含 `rm`/`mv` 这类命令名、必须提到"可恢复/不可恢复"之一）。

## 第八节 · Part C：压缩与溢出（构建题）

### 交付物

`kit/src/context.mjs` 里的四个函数（详见 `kit/CONTRACT.md`）：

```js
export function shouldCompact(state, policy)      // 是否触发压缩
export function compactRange(events, policy)       // 压缩哪一段（返回 from/to）
export function spill(content, budget)             // 超预算内容如何处理
export function applyCompaction(events, range, summary)   // 应用压缩并从日志重建
```

### 它检验什么

**边界条件**：恰好等于阈值时压缩吗（不压缩）、只有一条事件时能压缩吗（不能）、压缩后水位线如何更新（先应用后更新）、溢出的内容是否保留指针（保留）。

### 判据（见 `tests/t3-context.mjs`）

12 条，其中三条是"反直觉"的：**阈值等于时不触发**、**范围不足最小时不压缩**、**溢出时 inline 必须含指针**。

## 第九节 · Part D：进程与后台作业（构建题）

### 交付物

`kit/src/proc.mjs` 里的三个函数：

```js
export async function runShell(cmd, opts)         // 真跑一个进程，带超时与取消
export function transition(state, event)           // 作业状态机（五态，终态不可逆）
export function collectOutput(chunks, budget)      // 并发收集输出的合并与截断
```

### 它检验什么

**真跑进程**：`runShell` 会被测试用真实的命令调用（`node -e "..."`），而它必须：

1. 在超时后终止**整棵进程树**（测试会启动一个会派生子进程的命令）；
2. 在收到取消信号后留一个宽限期再强杀；
3. 收集 stdout/stderr 而**不因输出过多而死锁**（测试会输出超过管道缓冲区的量）。

### 判据（见 `tests/t4-proc.mjs`）

14 条，其中三条需要真实进程：超时终止、取消终止、大输出的不死锁。

**这一项的 20 分里有 12 分来自真实进程的三个判据**——因为它们是这一卷里最"讲义说了但没做就不知道"的部分。

## 第十节 · Part E：持久化与恢复（构建题）

### 交付物

`kit/src/persist.mjs` 里的两个函数：

```js
export function readAll(lines)                    // 读日志并处理尾部损坏
export async function recover(events, checkpoint) // 三步恢复（分析、重做、撤销）
```

### 它检验什么

五类损坏输入：**半行**（写入中断）、**缺字段**、**顺序号跳号**、**未知类型**、**检查点损坏**。前两类应当被截断，第三类应当抛错，第四类应当拒绝（除非带可忽略标记），第五类应当回退到备份。

**重做必须幂等**：测试会对同一份日志连做两次恢复并核对状态相同。

### 判据（见 `tests/t5-persist.mjs`）

13 条，其中四条检验损坏输入、两条检验幂等、一条检验"从检查点恢复与从头重放结果相同"（这一条最关键）。

## 第十一节 · Part F：可观测（构建题）

### 交付物

`kit/src/metrics.mjs` 里的四个函数：

```js
export function costOf(usage, price)              // 三档成本
export function latencyBreakdown(req)             // 四段延迟
export function hitRate(usages)                   // 缓存命中率
export function summarize(records)                // 汇总（含分位数）
```

### 它检验什么

**三档计费**（未命中输入、命中输入、输出）、**`cachedPromptTokens` 缺失时按零命中**、**四段延迟之和等于总耗时**、**分位数而不是均值**、以及**空集合上的除零**（`hitRate([])` 必须返回 0 而不是 NaN）。

### 判据（见 `tests/t6-metrics.mjs`）

12 条，其中两条是"安静的陷阱"：缺失字段的处理与空集合。

## 第十二节 · 判分方式与权重

```
总分 = A(15) + B(15) + C(15) + D(20) + E(20) + F(15)
```

每一项的得分按它的判据表逐条累计。**判分器运行两次**：一次用你的实现，一次用参考答案（`grade/*.reference.mjs`）——**参考答案必须满分**，否则说明测试本身有问题（而那种情况下你应当报告而不是改测试）。

**关于部分分**：每个 Part 的判据是独立的，因此"做了一个函数但边界没处理"能拿到部分分。**不要为了满分而卡在一个 Part 上**——先把六个 Part 都推到"正常路径通过"，再回头处理边界。

## 第十三节 · 常见错误

按经验，这六个 Part 的失败集中在下面十处。

**Part A/B（分析）**

1. 把"超时"一律当成可重试——而**已经产生副作用的超时不可重试**（你无法知道它是否生效）。
2. 后果描述里抄了命令（`rm -rf`）而不是说清后果（"删除目录，不可恢复"）。
3. 策略题只给结论不给依据（判分器检查 `reason` 是否非空）。

**Part C（压缩）**

4. 阈值判断写成 `>=` 而不是 `>`（**恰好等于时不压缩**）。
5. 溢出时只留指针不留内容，或者只留内容不留指针（**两者都要**）。
6. 压缩后没更新水位线，或者先更新后应用（**顺序反了**）。

**Part D（进程）**

7. 只杀直接子进程——**`sh -c "node ..."` 会留下孙子进程**。
8. 大输出时同步读 stdout（**管道缓冲区满就死锁**，必须并发消费）。
9. 状态机允许从终态回到运行态（**终态不可逆**）。

**Part E（恢复）**

10. 读到半行时抛错（**应当截断并报告**）或者读到跳号时不抛错（**应当抛错**）。
11. 重做不幂等——连做两次恢复会翻倍。

**Part F（可观测）**

12. 成本只算两档（漏了缓存写入或把命中当未命中）。
13. `cachedPromptTokens` 缺失时抛错（**应当按零命中**）。
14. 延迟四段加起来不等于总耗时。

## 附：如果你卡住了

按这个顺序排查：

1. **跑一次 `tests/run.mjs` 看明细**——多数"不通过"有明确的判据名。
2. **看 `kit/CONTRACT.md` 里那个函数的契约**——包括它的前置条件与返回值。
3. **翻讲义对应小节的判据表**——多数判据与讲义里的验收判据一一对应。
4. **构造一个最小输入自己试**——比读测试快。
5. 实在卡住时看 `grade/*.reference.mjs`——**但要在自己试过之后**，因为读懂别人的实现而自己写不出来，是那种"看起来会了其实没有"的情况。
