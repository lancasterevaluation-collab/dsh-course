# 后端方向 · 能力要求（教学大纲体）

> **这份文档是什么**：把面试题库里的题目**反推成能力要求**。题库回答"会被问什么"，这份文档回答"**应该具备什么能力**"。
> **写法约定**：每条能力用**行为动词 + 可验证的判据**写成。**没有判据的能力条目是空话**——所以每一条都给出"怎么证明你具备了它"。
> **四个层级**：L1 基础 → L2 核心 → L3 进阶 → L4 专家。**划分依据是"独立承担的范围"**，不是难度。

---

## 一、总则

### 1.1 这个岗位要解决什么问题

后端岗的核心职责可以概括为：**在不可靠的组件之上，构建可预测的系统。**

这句话界定了三个重点：

- **不可靠的组件**——网络会断、磁盘会满、进程会崩、下游会挂。**后端的全部难度来自"假设别人会失败"**；
- **可预测**——不是"平均情况好"，而是**在最坏情况下行为可知**（延迟有上限、失败有边界、恢复有路径）；
- **系统**——所以重点不是单个函数的正确性，而是**组件之间的契约与失败传播**。

### 1.2 四个层级与它们的判据

| 层级 | 独立承担的范围 | 判据（能证明你到了这一层） |
|---|---|---|
| **L1 基础** | 能在给定设计下实现正确、可测的代码 | 能写出一个接口，并**说明它在什么条件下会失败** |
| **L2 核心** | 能独立设计一个可上线的服务模块 | 能设计缓存/存储/接口，**并给出容量与失效的估算** |
| **L3 进阶** | 能诊断并优化线上问题 | 能**从现象定位到瓶颈**，改动**可灰度、可回滚** |
| **L4 专家** | 能定义架构与跨系统契约 | 能设计分布式方案，**并说明它放弃了什么（CAP 的具体取舍）** |

### 1.3 与面试题库的对应

本文档的每条能力都能在题库里找到检验形式（见 §六）。**两者是双向的**：学习按能力条目，检验按题库。

## 二、L1 基础能力

### 2.1 语言、数据结构与复杂度

**熟练掌握至少一门后端语言的运行时特性，能够从复杂度而非写法判断方案的可行性。**

- 能**分析时间与空间复杂度**，并**用它否决方案**——不是"这个算法更快"，而是"数据规模到 10⁸ 时它不可行"；
- 能**选择合适的容器**：需要 O(1) 查找用哈希、需要有序遍历用树、需要频繁首尾操作用双端队列——并**说明选择的依据是访问模式**；
- 能**理解哈希的确定性**：同一个 key 的哈希值稳定——**这一条直接推出了"热点 key 无法通过分片分散"**（见 L4）；
- 能**识别隐式复杂度**：一次看似 O(1) 的操作可能触发扩容、GC 或磁盘 IO。

**可验证的判据**：给定一个数据规模与访问模式，能选出容器并**说出它在最坏情况下的表现**。

**对应题库**：Q3.1.1（热点为什么加机器无效——哈希确定性）

---

### 2.2 网络与协议基础

**熟练掌握 HTTP 与 TCP 的基本语义，能够用协议层面的概念解释应用层现象。**

- 能**区分幂等方法与非幂等方法**（HTTP 语义），并**说明它为什么是重试的前提**；
- 能**解释一次请求的完整链路**（DNS → 连接 → TLS → 请求 → 响应），并**知道每一段可能引入的延迟**；
- 能**理解超时的语义**：超时**不意味着请求没执行**——这正是幂等键要解决的问题；
- 能**区分"连接失败"与"请求失败"**，并知道两者的重试策略不同。

**可验证的判据**：能解释"为什么支付接口必须幂等"，并给出**具体的实现机制**（去重键 + 服务端记录）。

**对应题库**：Q2.1.3（幂等的定义与实现）、Q3.1.2（两个写无法原子化）

---

### 2.3 数据库与存储基础

**熟练掌握关系型数据库的基本用法，能够说清索引、事务与隔离级别的实际后果。**

- 能**设计索引**，并**说明它为什么能加速这条查询**（而不是"加了索引就快了"）；
- 能**判断一条查询是否用得上索引**，并知道哪些写法会让索引失效；
- 能**说清事务隔离级别各自防止什么异常**（脏读、不可重复读、幻读）；
- 能**区分"数据库能保证的"与"应用层要自己保证的"**——例如唯一约束能防重复插入，但**跨库的唯一性要靠应用层**。

**可验证的判据**：给定一条慢查询，能说出**改索引、改查询、还是改数据模型**，以及各自的代价。

## 三、L2 核心能力

### 3.1 接口与 API 设计

**能够设计一份可长期维护的接口契约，并判断什么改动是破坏性的。**

- 能**写出合约的三类承诺**：行为（做什么）、时序（何时可调用）、错误（失败时怎样）；
- 能**判断一次改动是否破坏性**——**依据是"有没有依赖原有契约的代码会因此失败"**，而不是"改了什么"；
- 能**识别隐蔽的破坏性改动**：改默认值、改副作用范围、收紧时序（**这类改动编译器与测试都抓不住**）；
- 能**设计演进路径**：加而不改 → 放宽而非收紧 → 兼容层 → 版本化，**并说明为什么不用更重的那个**。

**可验证的判据**：给定一个被多处依赖的接口，能列出一次改动的**真实波及面**（谁依赖了哪个承诺），并分类为"会报错"与"会静默失效"。

**对应题库**：Q2.1.1（结构化的接口定义：`sideEffect`、`idempotent`）

---

### 3.2 缓存设计

**能够设计缓存层，并说清它与数据源之间的一致性代价。**

- 能**从缓存的本质推起**（"同一个东西会被访问多次"），并**推出三种失败是它的三种破坏方式**（穿透 / 击穿 / 雪崩）；
- 能**计算布隆过滤器的误判率**：$P_{\text{fp}}=(1-e^{-kn/m})^k$，最优 $k=\frac{m}{n}\ln 2$，**并说明每元素 10 位对应约 0.8%**；
- 能**设计防击穿**（互斥重建 / 逻辑过期），并**列出锁的三个失败路径**（持有者崩了 / 回源慢 / 锁超时）；
- 能**说明为什么"写时删缓存"优于"写时更新缓存"**——**删除是幂等的、与顺序无关**；
- 能**如实说明缓存做不到强一致**，并给出正确的表述（"控制窗口"而不是"保证一致"）。

**可验证的判据**：给定一个读多写少的场景，能设计缓存方案，并**量化不一致窗口与它的发生概率**。

**对应题库**：Q3.1.1、Q3.1.2、Q2.4.3（前缀缓存机制）

---

### 3.3 存储选型与数据建模

**能够按访问模式选择存储，而不是按流行度选择技术。**

- 能**按访问模式分类**：顺序 vs 随机、读多 vs 写多、需要在哪几个维度上查询；
- 能**说明一种存储适合什么、不适合什么**——并且**代价说得比好处多**；
- 能**设计主键与分区键**，并**说明这个选择如何影响后续的查询能力**；
- 能**识别"数据模型决定了查询能力"**这一约束——**改查询容易，改数据模型难**。

**可验证的判据**：给定三类查询（按 A 查、按 B 范围查、按 A 与 B 聚合），能设计出**同时满足它们的数据模型**，或**说明为什么不能**。

**对应题库**：Q3.1.1（缓存与数据源的分工）

---

### 3.4 错误处理与可观测

**能够设计失败路径，并让系统自己说清"发生了什么"。**

- 能**按"失败发生在哪一侧"分类错误**（请求错了 vs 环境不对），并**说明分类的目的是让调用方能选对下一步**；
- 能**设计重试**：区分可重试与不可重试，并**确保重试不破坏幂等**；
- 能**设计日志与指标**：日志用于**解释一次具体的失败**，指标用于**发现趋势**——**两者不能互相替代**；
- 能**区分症状与根因**：延迟升高是症状，**要能说出可能的三层原因**（自身 / 下游 / 资源）。

**可验证的判据**：给定一个线上告警，能在**不登录机器**的前提下说出先看哪三个指标。

**对应题库**：Q2.1.2（两种错误形态）、Q2.4.1（trace/span 的层次）、Q2.4.2（排查五步）

## 四、L3 进阶能力

### 4.1 一致性与事务

**能够判断一个场景需要什么级别的一致性，并为它给出实现方案与代价。**

- 能**区分强一致、最终一致与"有界不一致"**，并**说明各自的实现代价**；
- 能**说清分布式事务的几种方案各自放弃什么**（两阶段提交的可用性、补偿事务的复杂度）；
- 能**设计幂等**：去重键、状态机、唯一约束——并**说明每种适合什么场景**；
- 能**证明"某些一致性做不到"**——例如"两个独立写无法原子化"（**这是缓存一致性的根本困难**）。

**可验证的判据**：给定一个跨服务的流程，能说出**在哪一步可能产生不一致**，以及**如何让它最终收敛**。

**对应题库**：Q3.1.2（两个写无法原子化；不一致概率随读速率上升）

---

### 4.2 并发与锁

**能够识别并发问题，并理解"锁"与"无锁"各自的适用条件。**

- 能**识别竞态条件**，并**说明它在单线程测试里为什么测不出来**；
- 能**区分悲观锁与乐观锁**：前者假设冲突频繁、后者假设冲突罕见——**选择依据是冲突概率**；
- 能**设计分布式锁并知道它的失效模式**：锁超时、锁持有者崩溃、以及**主从切换导致锁失效**；
- 能**用幂等替代锁**：当操作本身幂等时，很多锁就不必要了。

**可验证的判据**：给定一段并发代码，能指出**至少一处竞态**，并给出两种修法（加锁 / 改幂等）及各自代价。

**对应题库**：Q3.1.1（互斥重建的锁与它的三个失败路径）

---

### 4.3 限流、熔断与降级

**能够为系统设计过载保护，并说明每一种保护的失效条件。**

- 能**区分三种限流算法**（令牌桶允许突发、漏桶平滑、滑动窗口严格），并**按场景选**；
- 能**说明固定窗口的边界突刺问题**（窗口交界处可能瞬时放行 2 倍流量）；
- 能**设计熔断**：状态机（关闭 → 打开 → 半开），并**说明半开状态的试探逻辑**；
- 能**设计降级**，并**说明降级的隐藏代价**——降级不只是"少几个功能"，**它改变了调用方看到的世界**；
- 能**说明 fail-open 与 fail-closed 的取舍**：前者保可用性、后者保正确性。

**可验证的判据**：给定"下游挂了"的场景，能说出**三层保护各自的触发条件**（限流 → 熔断 → 降级）。

**对应题库**：Q2.5.3（"部分降级"的隐藏代价）

---

### 4.4 性能分析与调优

**能够从现象定位瓶颈，并坚持"先测量再优化"。**

- 能**做延迟分解**（自身计算 / 下游调用 / 资源等待），并**说明为什么要分解而不是猜**；
- 能**区分 CPU 密集与 IO 密集**，并给出不同的优化方向；
- 能**识别"优化了占比最小的那一项"**这类常见错误；
- 能**用数据说明优化效果**，并**说明改动是否可回滚**。

**可验证的判据**：给定 P99 从 50ms 涨到 2s，能在**十分钟内**说出前三个要查的地方。

**对应题库**：Q2.4.1（延迟加性分解与"先测量再优化"）

---

## 五、L4 专家能力

### 5.1 分布式架构

**能够设计分布式方案，并明确说明它放弃了什么。**

- 能**把 CAP 的取舍落到具体决策上**（某个功能选择可用性还是强一致），而不是背定义；
- 能**说明分片键的选择如何决定后续能力**——**且能识别"热点 key 无法通过分片分散"**（因为哈希的确定性）；
- 能**理解一致性哈希的价值**：扩缩容时迁移量约为 $1/N$，而不是全部重排；
- 能**设计副本与故障转移**，并**说明故障检测的假阳性代价**（误判会导致不必要的切换）。

**可验证的判据**：给定一个"数据量大且读写都高"的场景，能给出分片方案，并**说出它的热点风险与缓解方式**。

**对应题库**：Q3.1.1（热点 key 的本质）

---

### 5.2 容量规划与成本

**能够用估算支撑决策，并说清估算的假设。**

- 能**从需求推出量级**：QPS → 带宽 → 存储 → 机器数；
- 能**做数量级估算**并**说明精度**（**估算的目的是排除不可行的方案，不是精确预测**）；
- 能**把成本写成式子**：存储成本、带宽成本、计算成本各占多少，**并找出高杠杆项**；
- 能**说明"资源受限下先优化什么"**（通常是最贵的那一项，而不是最容易的那一项）。

**可验证的判据**：给定"日活 1000 万、人均 10 次请求"，能在**两分钟内**给出 QPS 量级与所需资源量级。

**对应题库**：Q2.4.3（成本分解与命中率的杠杆）

---

### 5.3 高可用与容灾

**能够设计"部分失败时系统仍可用"的方案，并知道代价在哪。**

- 能**区分故障域**（单机 / 单机房 / 单地域），并**说明每种故障的应对层级**；
- 能**设计优雅降级**，并**明确降级后的能力边界**（用户能看到什么、不能看到什么）；
- 能**设计数据恢复**，并**说清 RPO 与 RTO 的取舍**（数据能丢多少、多久能恢复）；
- 能**识别"冗余本身会引入新故障"**（如脑裂、切换风暴）。

**可验证的判据**：给定"一个机房不可用"，能说明**系统的行为**与**恢复步骤**。

---

### 5.4 技术决策与权衡

**能够在信息不全时做出决策，并说明决策的可逆性。**

- 能**区分可逆决策与不可逆决策**，并**对前者快速决定、对后者慎重**；
- 能**把技术选择翻译成代价语言**（"这个方案要付出什么、谁承担"）；
- 能**识别"过度设计"的信号**（小规模问题上微服务、分片、多区域——**§1.6.3 的淘汰信号之一**）；
- 能**说明"不做某事"的理由**，并给出**重新评估的条件**。

**可验证的判据**：给定两个方案，能说出**选择其中一个的三条理由与两个代价**，并**指出在什么条件下会改变选择**。

## 八、这份文档的边界（本课程不覆盖什么）

**必须如实声明**：本课程的题库与文档**不覆盖**以下后端内容——它们不是不重要，而是**不在"agent harness"这个载体能覆盖的范围内**：

| 不覆盖 | 理由 |
|---|---|
| 数据库内部原理（B+ 树、MVCC 实现、WAL 细节） | harness 用的是文件与 SQLite，不涉及数据库引擎实现 |
| 分布式事务的具体协议（两阶段提交、Saga 的完整实现） | 超出单机 harness 的场景 |
| 消息队列的深度使用（顺序性、Exactly-once 的实现） | 同上 |
| 服务网格、Kubernetes、云原生部署 | **本课程的目标是"单机可运行的 harness"** |

**但有一条例外**：这些内容里的**结构**（而不是实现）常常与 harness 里的问题**同构**——例如"缓存失效模式""幂等实现""降级的隐藏代价"。**课程鼓励用"结构相同"的视角去理解它们，但不声称覆盖了它们的实现细节。**
