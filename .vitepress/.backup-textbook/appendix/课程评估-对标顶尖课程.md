# 课程评估：对标顶尖课程与 200 万档能力要求

> **这份文档是什么**：一次诚实的自我评估。参照系是三份**有实证的材料**（CS336 的作业结构、MIT 6.5840 的评分哲学、200 万档的真实 JD），评估对象是**我们目前造出来的东西**。
> **评估原则**：**先说达不到的地方**。一份只讲成绩的评估没有价值。

---

## 一、参照系（三份，都有可核实来源）

### 1.1 CS336（Stanford）：用"从零构建"定义标准

**核心前提**：学生必须**从原始数据开始构建一个完整的语言模型**——数据收集清洗、Transformer 构造、训练、部署前评估——**不许调用 API、不许用 HuggingFace、连 `torch.nn.Linear` 这类框架组件都不许用**，只能用 PyTorch 原语。

**它的五个作业**（每个对应一个 unit）：

| 作业 | 内容 | 关键约束 |
|---|---|---|
| 1 · Basics | 字节级 **BPE tokenizer** + Transformer LM（RoPE / RMSNorm / SwiGLU）+ 交叉熵 + **AdamW** + 训练循环 | **提交 perplexity 到排行榜**，90 分钟 H100 预算 |
| 2 · Systems | profiling 工具 + **FlashAttention-2 的 Triton kernel**（前向与反向）+ DDP + optimizer state sharding | 需要 NVIDIA GPU 与 Triton |
| 3 · Scaling | 用给定的 IsoFLOPs 数据**拟合 scaling law**，在固定 FLOPs 预算下查询训练 API，预测 1e19 FLOPs 时的最优规模 | **要预测，然后验证** |
| 4 · Data | Common Crawl HTML→文本、过滤（质量 / 有害 / PII）、**MinHash 去重** | 训练并**提交排行榜** |
| 5 · Alignment | **SFT + expert iteration + GRPO** 提升数学推理（MATH 数据集） | 另有可选的 DPO 安全对齐 |

**它对课程工程的要求**（这几条对我们最有参考价值）：

| 机制 | 具体做法 |
|---|---|
| **评分粒度** | 逐项给分——作业 PDF 里 `unicode1` = 1 分、`unicode2` = 3 分（**不是"这道题 10 分"**） |
| **提交物** | **既有代码，也有书面报告** |
| **提交方式** | Gradescope；**无限次重交，只算最后一次**；**鼓励部分完成** |
| **时限机制** | 共 6 个 late days，每次作业最多 3 个（1 late day = 24 小时延期） |
| **荣誉守则** | 允许学习小组；**允许用 LLM 问低级编程与高层概念问题，禁止直接用 LLM 解题**；**强烈建议关闭 AI 自动补全** |
| **门槛声明** | 明确写"**你会比其他 AI 课多写一个数量级的代码**"，且**脚手架极少** |
| **资源成本** | 完整跑一遍约 **\$100**，缩小规模可到 \$10 以下 |

### 1.2 MIT 6.5840：用"tester is the grader"定义评分

**核心哲学**：**测试框架就是评分者**——不靠人工检查代码，靠跑课程提供的测试。

**五个递进的 lab**：MapReduce → 单机 KV Server → **Raft（3A 选主 / 3B 日志复制 / 3C 持久化 / 3D 快照）** → 基于 Raft 的 KV → 分片 KV。

**它的四个机制值得逐条对照**：

| 机制 | 具体做法 | 它解决什么 |
|---|---|---|
| **递进依赖** | **后续 lab 依赖前面的正确性**；MIT 明确警告"要给自己足够时间写扎实的代码" | 让"敷衍通过"在下一关暴露 |
| **故障注入** | 提供的 `labrpc` **可以延迟、重排、丢包、断连** | **让测试覆盖异常路径** |
| **压力测试** | 官方给 `dstest.py`；常见做法是 **`dstest -s -p 20 -n 500`**（跑 500 次） | **分布式行为不确定，单次通过不算通过** |
| **一致性检查** | 用 **Porcupine** 检查线性一致性，附带可视化工具 | 用形式化的性质判定正确性 |

**它的评分哲学一句话**：

> **"run the tests multiple times before submitting"** ——**鲁棒性优于单次正确**。

**旁证**：Columbia 的同类课程（DSLabs 派生）**每个单元测试跑 50 次，每次失败做乘性惩罚**。

**它自己承认的缺陷**（这一点也值得学——**课程应当公开自己的问题**）：学生反馈"**前面的 lab 需要更强的测试**"、"**lab 之间依赖太强**"，以及 Porcupine 的可视化工具**只有少数学生有效使用**。

**注意这个分布的含义**：**"会用框架"只能覆盖到 P6–P7 的下半段**；**200 万档的要求集中在①与②**——**运行时与系统底层**。

## 三、逐项对标：我们的硬伤

### 3.1 ★ 最大的硬伤：作业是"分析型"，不是"构建型"

| | CS336 | MIT 6.5840 | **我们** |
|---|---|---|---|
| 作业产出 | **一个能跑的 LM**（交 perplexity 到排行榜） | **一个通过测试的 Raft** | **一份分析报告** |
| 代码量 | "比其他 AI 课多一个数量级" | 5 个递进 lab，每个数百行 Go | **判分器 7–13 KB，学生写 0 行核心代码** |
| 判据 | 排行榜 + 逐项给分 | 测试通过 | **客观题 + rubric 自评** |

**这是最严重的问题**：**我们的作业让学生"读懂"和"分析"，而顶尖课程让学生"造出来"。**

**它的后果很具体**：**读完我们的课程，你能讲清工具系统的设计，但你没有写过一个工具系统。** 而 200 万档的 JD 要的是"**设计落地经验**"——**"落地"这两个字，分析型作业给不了。**

**唯一的例外**是 1.3 的作业（用 `depgraph.mjs` 分析真实代码库）——**它是动手的，但仍然是"分析"而不是"构建"**。

### 3.2 评分机制：我们没有"tester is the grader"

| | MIT 6.5840 | **我们** |
|---|---|---|
| 谁判分 | **课程提供的测试框架** | **我们自己写的客观题比对** |
| 判什么 | 行为是否正确（含故障下） | 答案是否与标准答案一致 |
| 能否防"敷衍通过" | ✅ 后续 lab 会暴露 | ❌ **判分器只判知识点** |

**6.5840 的机制有一个我们完全没有的性质**：**它判的是"你的系统行为对不对"，而不是"你的回答对不对"**。

**这意味着它的评分无法被"理解"绕过**——你只有真的实现对了才能过。

### 3.3 鲁棒性验证：我们只做单次检查

| 机制 | 6.5840 | **我们** |
|---|---|---|
| 压力测试 | `dstest -p 20 -n 500`（跑 500 次） | **无** |
| 故障注入 | `labrpc` 可延迟/重排/丢包/断连 | **无** |
| 形式化检查 | Porcupine 线性一致性检查 | **无** |
| 乘性惩罚 | Columbia：跑 50 次，失败乘性扣分 | **无** |

**我们的验收判据是"跑一次，看结果"**——**而进程管理、并发、缓存这些题的失败恰恰是"偶发"的**（这一点我在 1.4 和题库里反复讲过，**但作业本身没有落实**）。

**这是一处自我矛盾**：**我在题库里写"要跑 50 次确认不泄漏"，但我们的作业机制里没有这条。**

### 3.4 竞争机制：我们没有排行榜

CS336 的作业 1 与 4 都要**提交 perplexity 到排行榜**。

**排行榜的作用不只是"比较"**，它还有三个：

- **让"部分完成"有意义**（你跑出 3.2 的 perplexity 也是成绩）；
- **暴露"看起来对但实际差"的实现**（同样的代码，别人比你快 10 倍）；
- **把优化变成可度量的**——**这正是我们在题库里反复强调的"数字要影响决策"**。

**我们没有这个机制**——所以"优化"在我们这里只是概念。

### 3.5 资源约束：我们没有预算与时限

| 机制 | CS336 | **我们** |
|---|---|---|
| 计算预算 | 90 分钟 H100（作业 1） | **无** |
| 成本限制 | 完整跑一遍约 \$100 | **无** |
| 时限机制 | 6 个 late days | **无** |
| 荣誉守则 | **明确写了"允许用 LLM 问概念，禁止用它解题"** | **无** |

**荣誉守则这一条特别值得注意**：**CS336 直面了"学生一定会用 AI"这个现实**，并给出了明确的边界。

**我们的作业没有任何这类条款**——**而这在 AI 时代是一个必须回答的问题**。

### 3.6 内容覆盖：② 系统底层几乎空白

回到五簇能力：

| 能力簇 | 我们的覆盖 | 说明 |
|---|---|---|
| ① Agent 运行时与编排 | 🟡 **部分** | 有文档与题库，**但没有"造出来"的作业** |
| ② **沙箱、隔离与系统底层** | ❌ **几乎空白** | 内核、cgroups、namespaces、Firecracker/gVisor **只在题库里作为"同构参考"提及** |
| ③ 上下文工程、记忆与 RAG | 🟡 部分 | 同上 |
| ④ 评测体系与可观测 | 🟡 部分 | 文档里有，**但最薄弱的正是这一块**（我在题库里已标注） |
| ⑤ 工程基础与后端功底 | 🟡 部分 | 系统设计章是"同构参考"，**明确声明了不覆盖** |

**② 是 200 万档的硬要求**（杭州 Agent Infra 的 200–280 万岗、OpenAI 的 \$155–405K 岗、Scale AI 的沙箱岗**全都要求这一簇**），**而我们是空白**。

**这是一个必须先回答的战略问题**（见 §五）。

### 3.7 报告要求：我们有，但形式不同

CS336 明确要求**作业交"代码 + 书面报告"**。

我们有 `writeup.md`——**形式上是对的**（1.4 的作业包里有六节报告 + rubric 自评）。**这一点我们做对了**，只是**报告分析的对象是文档而不是自己造的系统**。

## 四、我们的优势（这部分不能丢）

前面全是问题，但也有三处是**我们比参照系做得好的**。

### 4.1 证据等级体系（参照系没有）

**CS336 与 6.5840 都不标注"这条结论来自规范还是经验"。**

我们的题库引入了六级标注（【规范】/【官方文档】/【书籍】/【经验】/【不确定】/【推算】），**并且在内文里如实写出"这一条我找不到出处"**。

**它的价值在 AI 时代被放大了**：**当答案可以被生成时，唯一的区分是"知道依据的强度"**。

**这一条应当保留并强化**——**它是我们的独占优势**。

### 4.2 三合一视角（参照系都是单一维度）

CS336 是"ML + 系统"，6.5840 是"分布式系统"。**两者都不涉及产品判断**。

我们的"三合一"（产品 × 工程 × Agent）在**结构识别**上确实做到了别的课程没做的：

> **护栏指标 ↔ 守卫机制**、**替换成本 ↔ 破坏性变更的代价**、**可逆性分级 ↔ 数据格式的不可逆**——**这些是同一个结构**。

**这个视角对"200 万档"是有用的**：因为那个档位要求"**能做取舍并说清代价**"，而**取舍能力恰恰来自跨领域的结构识别**。

### 4.3 面试对接（参照系完全不做）

CS336 与 6.5840 都**不关心面试**——它们是学术课程。

我们有一份 **409 KB 的题库**、四份能力文档、以及**面试官评分维度与真实 JD 的对标**。

**这一条让它成为"课程 + 职业路径"的组合**——**而这正是用户要的"为三条路线铺路"**。

### 4.4 技术段与适配段的分离（一个有效的方法论）

同一件事分"推导"（懂）与"装配"（讲得出）两段，并给出**显式的对应关系**（面试里的每句话取自技术段的哪一节）。

**这个方法论在参照系里没有**，而它在**"知识 → 能力"的转化**上是有效的。

## 五、结论与必须先回答的问题

### 5.1 结论：我们现在造的是什么

**一句话**：

> **我们现在造的不是一门课，是"一门课的准备材料 + 一份面试题库"。**

| 维度 | 评价 |
|---|---|
| **内容深度** | 🟡 部分达标（1.4 与题库的技术段有真实深度） |
| **作业形态** | ❌ **不达标**（分析型 vs 构建型） |
| **评分机制** | ❌ 不达标（客观题 vs tester-as-grader） |
| **鲁棒性验证** | ❌ 不达标（单次检查 vs 压力测试与故障注入） |
| **系统底层覆盖** | ❌ **空白**（而它是 200 万档的硬要求） |
| **面试对接** | ✅ **超出参照系** |
| **诚实性（证据等级）** | ✅ **超出参照系** |
| **三合一视角** | ✅ 独有 |

**所以"能否代替美国顶尖课程"这个问题的答案是**：

> **目前不能。** 差距不在"讲得够不够清楚"，而在**"学生有没有被逼着造出东西"**。
>
> CS336 的核心不是它的讲义，而是**那五个必须造出来的东西**；6.5840 的核心是**那个会给你注入故障的测试框架**。**这两样，我们都没有。**

### 5.2 必须回答的第一个问题：② 号能力簇要不要做

**沙箱与系统底层（内核、cgroups、namespaces、Firecracker/gVisor）是 200 万档的硬要求，而我们完全空白。**

**但它是「另开一门课」量级的工作**——因为它需要 Linux 环境、需要系统编程、**且本环境（Windows）连运行都困难**。

**三个选项**：

| 选项 | 代价 |
|---|---|
| **A. 做** | 需要 Linux 环境 + 大量新内容；**但 200 万档的要求才完整** |
| **B. 不做，但如实声明边界** | 诚实；**但那三条路线里"AI Infra"这条会缺一条腿** |
| **C. 用"同构"做折中** | 讲清结构（如"沙箱的分层策略"）而不做系统实现；**但达不到 JD 要求的"落地经验"** |

**这个决定影响后面所有工作量的分配——所以必须先定。**

### 5.3 第二到第五个问题（按重要性）

**第二，作业要不要改成"构建型"？**

如果改，那么：
- 1.1–1.4 是"判断力地基"，**它们本来就是分析型的**（无可厚非）；
- **但第 2–5 卷的作业必须是构建型的**——**每一篇配一个"造出来并让它通过测试"的作业**；
- 并且要有**递进依赖**（后续依赖前面的正确性，如 6.5840）。

**第三，要不要做"sandbox 测试框架"？**

即：**一个能对学生的 harness 注入故障、跑压力测试、并自动判分的框架**。

**这是把"tester is the grader"落地的前提**——**而它是整个改造里技术含量最高、也最有价值的一块。**

**第四，要不要引入排行榜与计算预算？**

例如"用不超过 N 次模型调用完成这个任务，提交成功率与 token 消耗"。

**它把"优化"从概念变成可度量的**。

**第五，荣誉守则怎么写？**

CS336 的写法值得直接借鉴：**允许用 LLM 问概念与低级编程问题，禁止用它直接解题，建议关闭自动补全**。

**我们还没有任何这类条款——而 AI 时代的课程必须回答它。**

## 六、如果只做一件事

**如果只能改一处，我会改 §3.1（作业形态）。**

理由：

- CS336 与 6.5840 的核心**都不是讲义，而是"必须造出来的东西"**；
- **200 万档的 JD 要的是"设计落地经验"**——**而"落地"只能通过造出来获得**；

**而 §5.2 那个问题（② 号能力簇做不做）必须先定**——因为它决定了后面是"补一门课"还是"补一章"。
